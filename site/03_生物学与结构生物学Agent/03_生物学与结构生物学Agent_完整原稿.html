一、发展脉络：问题变了，系统边界也随之扩大

  1. 先把专业能力变为行动空间。 生物学任务的难点不是多说几步，而是资料、脚本、数据库和环境分散。Biomni 将工具、软件与数据库整理到环境中，由 Agent 检索并写代码组合；SciToolAgent 则试图用工具知识图谱帮助选择多步调用。二者重点是让多领域能力进入同一个可执行环境。
  2. 从“工具能调”进一步解决“方法如何接入”。 Paper2Agent 从论文、代码和教程构造可调用接口，BioMedAgent 在工具交互过程中积累经验；这分别面向科研方法接入成本和专业工具学习成本。接口测试和执行成功仍不能证明科学结论正确。
  3. 从数据处理扩展到研究循环。 Robin 把文献检索、候选假设、实验建议、数据分析串起来，由实验室提供物理实验；Virtual Lab 以多角色会议组织蛋白设计并把候选交给实验。科学发现的证据来自计算和实验的联动，而非多角色对话本身。
  4. 深入结构领域，控制具体物理操作。 Agent Rosetta 管理专门的设计软件；StructAgent 和结构精修监督工作围绕实验密度图、模型修改、几何与拟合指标展开；MutexaGPT 将人的酶工程直觉翻译成分子模拟指标。这里的难点从“找到工具”转向“判断操作对具体体系是否合理”。
  5. 开始单独评测几何能力与执行环境。 2026 年 ProteinGeoBench 把结构记录检索和基于坐标的数值题放在同一个评测框架中，显示具体任务组成、运行框架和可访问资源会改变结果。对 NBDB 来说，构建能核验几何计算的任务集比只问结构知识更有意义。

二、Biomni：通用能力来自“环境＋代码行动”，不只来自模型

任务与输入。【原文】用户给定问题、数据和目标，系统面对遗传、组学、微生物组等多领域任务。预印本公开版描述 E1 环境包含 150 个专业工具、105 个软件包、59 个数据库；这些是当时的环境快照，不应等同于 NBDB 已具备的能力。其正式论文发表于 Science 2026，可读作者公开预印本；代码。

怎么做。 首先从文献和专家整理动作空间；对问题检索相关工具、数据库与软件；生成计划并以代码组合动作、循环和条件；执行后根据观察调整计划，最后形成结果。一个多组学案例把 RNA 和 ATAC 数据读入、推断调控网络、过滤结果、比较细胞类型并总结。它的设计选择是让代码承担灵活组合，而非为每项任务预先写死固定工作流。

证据与边界。 作者报告了八类开发时未见的真实任务以及案例；克隆设计案例由研究者执行并测序验证。注意案例中的局部成功不能推出所有方案可安全执行，环境覆盖或代码跑通也不等于统计或生物解释正确。【NBDB 建议】模仿 E1/A1 分层，但让每次结构操作显式携带结构版本、assembly、链、残基编号、单位和选择依据；代码调用必须产出可验证文件和运行记录。

三、SciToolAgent：为什么要给工具之间建立关系

任务与流程。【原文】SciToolAgent，Nature Computational Science 2025针对生物、化学和材料多工具任务，把科学工具及其关联组织为知识图谱，基于图检索为规划和工具执行提供上下文，并设置安全检查；研究展示蛋白设计与结构预测分析等案例。图谱的价值在于缩小搜索空间、描述工具衔接，而不是替代软件本身。

评价与局限。 论文有整理过的基准和案例，但图中存在某条调用关系并不能证明服务器已安装该软件、当前输入格式兼容，或给出的参数适合一个结构。【NBDB 建议】将“能接续”拆成可检查的边：输入类型、输出类型、序列对应关系、前置条件、环境、资源、许可和验证器；每条边附可复运行的测试样例。用图检索提出候选，最后由类型检查和真实执行确认。

四、Paper2Agent：将一篇科研方法变成可调用资源

任务与流程。【原文】Paper2Agent，Nature 2026 输入论文及其代码库、教程和材料，多 Agent 分析功能、搭建 MCP 服务、生成测试并执行，出错后修复；缺少可执行代码时可退化为结构化文献资源而非宣称能运行。研究给出了 AlphaGenome、Scanpy 等案例，Scanpy 案例在额外数据上比较预处理、聚类和标记基因结果。

如何评价。 作者将 100 篇计算生物论文输入流程，74 篇完成其定义的端到端 Agent 化，生成的 599 项工具中 593 项通过自动验证；另以这 74 篇的教程衍生问题测量问答表现。无法接入的常见原因包括缺代码或数据、依赖冲突和脚本不能泛化。自动测试通过是有条件的接口证据，不代表新输入有效、算法正确或软件许可证允许任意服务化。

【NBDB 建议】 把结构论文接入拆为五关：资源检查→环境和版本锁定→参数与文件接口→作者示例复现→新结构与边界案例复核。每关给出失败理由与责任人；论文的方法、引用、测试、容器和运行日志绑定到同一工具版本，再对外标记成熟度。

五、BioMedAgent：学习工具，但经验是否可迁移要单独测

任务与流程。【原文】BioMedAgent，Nature Biomedical Engineering 2026 处理跨组学分析、建模与病理图像等任务，以多角色协作探索工具、形成可检索经验，再组合分析流程。输入是自然语言目标及数据；输出包括运行产物与分析结果。重点是让系统积累对专业软件的操作知识，而不仅在运行时搜索文档。

评价与局限。 论文给出的 BioMed-AQA 有 327 任务，报告特定设置下 77% 成功率，并在外部 BixBench 上考察泛化。这不是能与 ProteinGeoBench 或其他系统直接比较的通用成功率；需要查学习和测试任务是否隔离、错误记忆如何处理、软件更新后经验是否失效。【NBDB 建议】经验条目必须绑定适用体系、工具版本、输入签名和验收结果；只把通过独立复跑的片段提升为共享技能，并设计版本变更后的过期与回滚。

六、Robin：把假设、实验和数据分析接成有人的闭环

输入与流程。【原文】Robin，Nature 2026输入疾病问题与阶段性实验数据；Crow、Falcon 承担不同形式的文献检索，Finch 在 Jupyter 逐步编写和执行 Python/R 数据分析，结果反哺下一轮假设。其实际分析环境是带生物信息软件的容器，Finch 使用编辑并运行单元格和提交答案两个主要动作。

案例如何产生证据。 围绕干性年龄相关黄斑变性，系统提出增强视网膜色素上皮细胞吞噬的方向，研究者执行药物和细胞实验；Finch 对流式细胞数据做门控、排除死亡细胞、统计与绘图；后续提出 RNA-seq，再进行差异表达与功能富集，产生 ABCA1 等值得进一步研究的线索。部分候选的体外效果被检验；人类执行实验和部分样本前处理，细胞实验结果并非临床疗效或因果机制的完整证明。

【NBDB 建议】 把密度图或蛋白变体实验视为外部证据回流：每个候选绑定提出时证据、预注册的指标、实验条件、未入选项及反馈，避免只展示成功案例。对照固定工作流、同资源单 Agent 和无工具模型，区分文献检索、计算执行与实验反馈各自的贡献。

七、Agent Rosetta：让专门设计软件成为可迭代的环境

输入与流程。【原文】Agent Rosetta，ICML 2026 给定结构与设计目标，Agent 在面向 Rosetta 的专门环境里先选择动作，环境提供对应文档，再由模型生成参数并填充 RosettaScripts XML 模板；运行后读回结构与代理指标，循环改进设计。研究比较了固定骨架的常规氨基酸序列设计，以及向蛋白核心引入非天然残基两个任务；最终还使用 AlphaFold 3 与分子动力学作计算检验。它要解决的是复杂软件的使用、参数与反馈，而非重新发明 Rosetta 的物理模型。

证据与边界。 论文比较其指定任务中的计算指标与基线；计算代理指标不等于表达、稳定性或结合实验。复用开源 Agent 也不自动带来 Rosetta、所需许可或计算资源。【NBDB 建议】每个设计输出必须保存 XML/脚本、输入结构、残基映射、随机种子、软件版本、评分明细和候选全集；留出无法处理的残基化学情况，让系统明确拒绝。

八、StructAgent 与结构精修监督：一个指标变好并不代表模型整体变好

StructAgent。【原文】StructAgent，2026 预印本，未同行评审 用两种分工：Maria 进行文献和结构推理，Annika 在本地运行软件、追踪状态与恢复故障；重大模型修改由专家批准。输入包括密度图、坐标、序列与任务背景，操作围绕模型重新拟合、验证、配体或金属位点审计。案例包括以 5GJR 模板向 3.8 Å 的 EMD-8332 图重拟合 64 链蛋白酶体，核糖体的 530 个金属位点审计，以及酶配体拟合。蛋白酶体案例最初的 AlphaFold 单体直接组装出现结构域几何不稳定，系统改用旧结构提供拓扑、预测单体提供局部参考，并调用 ISOLDE、Servalcat/REFMAC5 和 Phenix 进行分阶段修正。三项案例说明可操作性，不等于大规模盲测或任意结构可靠。

相邻证据。 AI agent supervision of structural model building and refinement，2026 预印本 让通用编码 Agent 协调多种结构软件，报道 24 个 cryo-EM 和 X-ray 案例。其 15 个起点几何较弱的已发表 cryo-EM 模型，MolProbity 分数中位数由 2.62 改善至 1.76；其中七个模型的 CaBLAM 离群率增加；必须同时查看模型—数据拟合、局部几何、残基和化学解释。论文没有完整证明相对固定自动流程或其他 Agent 的普遍优势。

【NBDB 建议】 对每次修改保存父模型、候选模型、命令、区域和新旧验证报告；当全局指标改进但局部冲突恶化时保留两个候选并展示差异，支持专家逐位点复核与回滚，不能让模型用一个分数覆盖全部证据。

九、MutexaGPT：把模糊直觉变成可计算指标，再回到实验

输入与流程。【原文】MutexaGPT，Nature Computational Science 2026 从“扩大活性位点”等语言需求出发：QuestionAnalyzer 补问结构与突变等缺失信息；WorkPlanningBoard 将目标转换为可计算指标与突变方案；EnzyHTP 调度模拟；ResultExplainer 整理结果并解释边界。它自动化模拟与直觉转译，并不直接预测酶活性。

具体证据。 空腔案例对 600 个变体各运行 50 ns MD，按轨迹平均空腔体积排序，前十名中四个与已有实验命中相符，是回顾性对照；另一淀粉酶案例中研究者进一步测试两种变体，它们的 0°C 与 45°C 活性之比相对野生型分别提高 1.7 和 3.7 倍。该比值不等于各温度的绝对活性均提高同样倍数。50 ns 是否足够依赖体系和观察量，作者的时长分析也不能推广为所有蛋白的最低时长。

【NBDB 建议】 建立“目标→指标→方法假设→候选→模拟→统计→实验”的显式链。每一步可追溯采样、力场、轨迹、指标定义及不确定性；如果需求无法映射到已支持的科学指标，直接报告不支持，而不是编造评分。

十、Virtual Lab：多角色讨论怎样产生可实验的候选

1. 领域中的四条路线与发展逻辑

生命科学早已有大量计算程序，但运行一次程序和完成一个科学问题之间隔着输入整理、方法选择、结果比较与解释。第一条路线把分散工具变成可发现、可执行的能力：科研软件的代码库很丰富，然而安装、接口、参数和教程分散，Biomni、SciToolAgent 等开始建立统一工具环境；Paper2Agent 则进一步从论文和仓库生成经过示例测试的工具包装。它们改善的是“能否使用方法”，而不是自动证明该方法适合任何新数据。

第二条路线让系统根据中间结果改变下一步：单细胞或空间分析要处理不同数据质量、组织和实验目标，固定步骤未必合适；SpatialAgent 等通过计划、工具执行和结果解释形成反馈。结构分析中的 Agent Rosetta 将反馈落到同一设计软件内部，结构精修 Agent 和 StructAgent 则将反馈跨程序扩展到建模、精修和质控。与早期问答相比，研究对象从“回答是否合理”转向“实际产物是否达标、是否应回滚”。

第三条路线把实验选择与实验反馈接起来。BioDiscoveryAgent 在预算下选择下一批基因扰动，使用历史筛选数据回放模拟闭环；Robin 则让人类实施实验，再把数据送回 Agent 分析并更新假设。第四条路线专门研究怎样辨别系统看似成功和科学上成功：例如 BioDesignBench 把设计产物评分与候选生成、评估、筛选行为拆开。四条路线不是统一时间线上的接力赛，领域工具、交互控制、实验反馈与评价工作持续并行发展。

2. Paper2Agent：把论文的方法做成可运行接口

问题与输入。论文写出了算法和案例，但新读者要复用时往往需自己找仓库、解决依赖、学习 API，还可能生成错误代码。系统输入是论文、代码仓库、教程和数据；对于没有可运行代码的材料，还可以提供结构化文献资源，但这不等于生成了可执行方法。

运行步骤。① 找到代码库和教程；② 环境 Agent 尝试构建运行环境，提取 Agent 将核心函数包装为工具；③ 测试 Agent 运行示例，将文件是否产生、数值是否在容差内、图是否符合参考等作为测试依据，失败则修改代码或环境，持续失败的工具被排除；④ 发布 MCP 的 tools、resources、prompts，供下游 Agent 将工具与论文上下文结合。举例说，一个 AlphaGenome 包装提供变异效应预测和可视化，Agent 仍需决定组织、变异以及分析步骤。

论文实际结果。2026 年 Nature 正式版在 AlphaGenome 生成 22 个通过测试的工具；15 个教程题在 5 次独立运行中准确率为 98.7% ± 1.3%，同设置的直接仓库访问基线为 82.7% ± 3.4%。更大范围中，100 篇计算生物学论文有 74 篇完成作者定义的 Agent 化；在这 74 篇生成的 300 道教程题上，报告 91.2% ± 1.6%。成功分母是所抽取的 100 篇，问答性能只针对已成功接入的 74 篇，不能写成“100 篇都能用”或“任意结构任务 91% 正确”。缺代码、数据、依赖或脚本不可泛化仍导致失败。论文：Nature 正式版 · 作者代码

对 NBDB 的建议。可建立“论文/工具入库流水线”：登记许可证、固定镜像和依赖 → 提取操作及参数 → 用教程固定输入/期望输出回归 → 专家声明适用条件 → 用未见测试数据检查 → 发布带版本与运行环境的工具。教程通过是接入测试，还须分别验收几何意义、物种、结构组成、计算条件及异常情况，不能把 MCP 或测试通过当作科学有效性的保证。

3. Agent Rosetta：让 Agent 操纵一个复杂的科学环境

问题与输入。Rosetta 可以在物理近似能量函数下设计序列和构象，也能处理一些非天然构件，但 RosettaScripts 的 XML 配置、残基选择和参数组织很复杂。该论文给 Agent 一份目标说明（如固定目标骨架设计稳定序列）与起始结构，研究重点是怎么使通用语言模型可靠地与一个复杂、专用的程序交互。

运行步骤。① 把设计目标和已有结构作为初始状态；② 多次并行运行生成一组候选 Pose；③ 将巨大坐标对象压缩为任务相关的可观察量，如空腔、埋藏未满足氢键、逐残基排斥能，以及针对标准残基任务的预测结构 RMSD 与 pLDDT；④ Agent 从约束过的动作类型中选择下一步并填写参数，如侧链设计/重排和骨架扰动；⑤ 环境执行 RosettaScripts，成功则更新状态，失败则反馈以修复动作；⑥ 重复，输出候选并使用独立的预测或模拟进一步比较。用结构化动作模板减少自由生成复杂 XML 的错误，但合法动作不等于合理设计。

验证与边界。ICML 2026 论文测试固定骨架的标准氨基酸序列设计，以及向蛋白核心引入一个非天然氨基酸；前者对比 ProteinMPNN、BoltzGen 和人工编写协议，后者对比人工协议，并用 AlphaFold 3 与分子动力学作计算验证。论文在给定骨架集合和代理指标上报告可与这些基线相当；非天然残基实验不能据此泛化到全部化学构件或所有设计目标，预测结构和模拟也不是湿实验实测。论文还观察到针对该环境的动作模板可使模型动作成功率显著改善，但动作成功率不是蛋白功能成功率。论文：ICML 2026 · 方法和实验细节

对 NBDB 的建议。不要把整个 Rosetta 只封成一个黑箱“设计蛋白”。保留任务语义与基础操作两层：上层定义骨架、可变位置、目标、限制和预算；下层定义可组合操作、合法参数、候选集合、评价器。先在一个边界明确的固定骨架任务上验证决策，再扩展其他操作。代理指标的选择会改变 Agent 行为，应把不同指标与最终独立验证分开。

4. StructAgent：跨软件建模，并把人的判断保留在工作流中

问题与输入。冷冻电镜项目可能同时有全局图、局部图、初始模型、已知配体和文献约束；灵活拟合、配体判断和离子审查需要跨程序反复决策。StructAgent 接收研究者的建模目标与项目文件，论文将它定位为受用户指导的多 Agent 工作流资源。

运行步骤。① 领域 Agent Maria 查阅结构生物学知识、文献和项目记忆，提出策略与验收依据；② 执行 Agent Annika 将获批策略转成对本地软件的调用，追踪文件、状态和错误；③ 可编辑的 skill 文档记录程序所需输入、操作、质控和失败恢复；④ 重大模型修改由专家审批，输出日志、参数、模型和验证证据。论文列举 ChimeraX、ISOLDE、PHENIX、Coot、Servalcat/REFMAC5 和 gemmi 等，而不是由语言模型自己计算原子坐标。

证据。三个案例包括从旧模板重拟合 64 条链的蛋白酶体、审查 530 个核糖体金属离子位点并对 75 项用户批准的修改做后续精修、以及一个化学身份与朝向有歧义的配体拟合。作者明确这些是案例研究而不是正式基准；它们证明工作流可以组织并留痕，但不能单独证明与专家相比普遍更准，也没有说明无人审核即可发表。论文为 2026 年预印本。论文：StructAgent 预印本

对 NBDB 的建议。应把“建议策略”和“实际执行”拆成不同状态，给每个候选保存输入、操作、验证结果与审批记录；重要的离子/配体身份、不可逆模型改动和证据不足项需留给结构生物学家。两个角色是一个具体设计，不是多 Agent 必然优于单 Agent 的证据；研究上要控制底层模型、工具集和预算做对比。

5. 结构精修监督：为什么最优下一步需要多指标与回退

任务。2026 年预印本《AI agent supervision of structural model building and refinement》让现有代码 Agent 协调已成熟的结构程序：用户提供冷冻电镜 map、half-map、序列及可能的初始模型，或 X 射线衍射数据、free flags、序列及起始模型，并提供已知配体、离子、修饰等实验信息。Agent 准备输入、运行程序、解析验证、比较候选后选择下一步；研究者仍做最终科学判断。

一次典型决策。候选 A 通过提高 map 权重改善模型与密度的吻合，却引入更多原子碰撞；Agent 因而调整权重并比较几何指标。另一案例的侧链拟合改变了主链，作者报告改为仅转移受支持的侧链扭转并保留原骨架。某些候选的 map 指标变好，但几何不合格，因此最终保留原模型。其价值不是自动把某一个分数降到最低，而是将“检测冲突 → 生成备选 → 对照验证 → 保留/回退”变成可审查的过程。

证据和限制。共 24 个 cryo-EM 与 X 射线案例，包括 15 个已有冷冻电镜模型再精修、5 个从 map 与序列开始的建模案例和 4 个实验室案例。在前 15 个再精修案例，MolProbity 中位数从 2.62 改善至 1.76；三例 X 射线模型的 Rfree 接近但未超过已发表模型。5 个从 map 开始的案例只评估蛋白构建，未构建配体、离子及糖链；计算与人类监督约 36 小时是项目经过时间，作者没有逐例测量研究者时间或 token，不能宣称比专家快多少倍。预印本尚未同行评审。论文：结构精修监督预印本

对 NBDB 的建议。为每个候选同时保存 map 拟合、clashscore、Ramachandran/rotamer、局部变化和必要的 half-map 证据；X 射线任务保留固定 free flags 并跟踪 Rwork/Rfree 和局部残基问题。设置预先写明的接受条件，指标冲突时允许保留原模型。精修时不得将未知化学组分自动当成确定事实；水、金属与配体的判断依赖样品组成和局部证据。

6. BioDiscoveryAgent：有限实验预算下怎样利用反馈

任务与状态。对于一项遗传扰动实验，假设有约 19,000 个候选基因、每一轮只能测一小批。目标不是回答某个基因是否重要，而是在固定轮数和预算内尽量发现更多达到预定表型阈值的 hit。Agent 每轮收到研究目标、已测试基因及其观测结果，提出下一批基因并解释其选择；可选工具包括文献搜索与方案批评。

闭环如何运行。① 根据问题、背景与候选集合生成第一批；② 查询所选扰动的表型结果；③ 把结果和已尝试集合写回下一轮输入，避免重复；④ 根据已有生物知识与观察，在探索不同通路和集中测试可能有效的基因之间权衡；⑤ 累计评价发现的真实 hit / 数据集中全部真实 hit。对照包括随机方法和若干主动学习/贝叶斯优化相关基线。注意论文的主要实验是对已有扰动数据的离线回放，每次选择后从数据集中揭示对应结果，并非论文每轮新做一次 CRISPR 实验。

结果与边界。ICLR 2025 论文在六个数据集、五轮、每轮 128 个基因的设定下，报告其 Claude 3.5 Sonnet 配置比比较的基线多找到约 21% hit，非必需基因任务约 46%；这两个百分比为所定义设置下的相对改进，不是全部基因预测 21% 或 46% 的准确率。基准中候选与观察取自既有数据，实际实验还会遇到测量噪声、失败、成本差异与数据库分布变化。论文：ICLR 2025 · 算法和实验详情

对 NBDB 的建议。借鉴其受预算约束的决策方法，而不是直接迁移基因筛选数值。例如结构设计中一轮只能精算或实验少量候选时，Agent 提出多样化候选，独立评分工具返回数据，再确定下一批；与固定规则、随机选择和主动学习基线在相同模拟/计算预算下比较累计有效候选数。

7. Robin：真实实验反馈如何进入下一轮假设

问题与流程。Robin 的目标是连接文献检索、候选假设、实验数据分析和修正假设。针对干性年龄相关黄斑变性，Robin 先用 Crow 汇集疾病机制并提出实验模型，再用 Falcon 深入核查候选药物证据，通过模型裁判的成对比较排序。人类科研人员复核候选、制定实验方案并实际执行细胞实验；数据上传后 Finch 在计算环境中分析，结果送回 Robin 形成下一轮候选。

一条可追踪的例子。作者先研究 Y-27632 对视网膜色素上皮细胞吞噬的影响；系统建议进一步进行 RNA-seq，研究人员实施实验，Finch 做差异表达分析。作者使用 8 条独立 Finch 轨迹比较一致性，并开展下一轮药物候选测试；论文还报告了 ripasudil 的后续实验结果。原文写明 RNA-seq 原始 reads 的拆样和比对由人完成，Finch 执行后续差异表达分析，因此不能说 Agent 自己完成全部原始数据处理或物理实验。

证据与局限。这是研究假设与体外实验反馈相连接的真实案例，强于仅看文本答案；但具体领域、样本、模型裁判排序与人的参与均影响可推广性。八次分析的一致性可以暴露不稳定，却不会让系统性错误自动消失。论文也提示对观察到的潜在机制仍需额外实验验证。论文：Nature 2026 · 作者代码

对 NBDB 的建议。将结构分析的每个主张绑定证据：原始数据 → 计算与版本 → 候选 → 独立验证 → 科学解释 → 仍需实验的问题。允许研究者把新实验结果作为下一轮输入，并区分“观察”“计算预测”“机制假设”和“独立验证”四种结论状态。

8. SpatialAgent：计划、工具、图像与论断核查

任务。空间生物学需要同时理解细胞表达、空间坐标和组织图像，问题可能是如何设计基因面板、注释细胞、研究细胞间通讯或生成空间假设。预印本 SpatialAgent 用 Plan–Act–Conclude 架构组织工作，并结合动态工具与技能检索、多模态解释和论断核查。空间组学不等于分子三维结构，但两者都存在“数据类型复杂、工具多、结果必须贴回原始空间证据”的问题。

过程。Agent 根据用户问题与数据先形成计划；检索相关技能和可用工具；执行统计/空间分析并观察图表；根据中间结果继续分析或修订；最后结合图像与结果给出带证据的解释，并用验证模块审查生成的论断。作者报告在人和小鼠多组织数据上评估，并进行前瞻性小鼠前列腺癌研究：设计包含 100 基因的附加面板，用于 21 个样本、约 420 万细胞的分析。该面板的具体用途、数据条件和指标以原文为准，不能把个别任务上的专家比较表述为所有空间分析都达到专家水平。该工作当前引用为预印本。论文：SpatialAgent v2 · 作者代码

对 NBDB 的建议。将“空间论断核查”转成结构视角：如 Agent 声称残基位于结合界面，应链接具体链、残基编号体系、模型文件、接触定义和原子距离；如果数据不支持则报告不确定。自动截图或三维渲染只是沟通方式，真正证据仍应来自可复核的结构、密度及计算结果。

9. 从相关论文到可发表的 NBDB 研究问题

把很多工具接进平台可以创造产品价值，但“工具更多、会聊天”本身很难证明一个普适的研究贡献。下列方向是建议和待验证的假设，不代表新颖性已保证；投稿前应以最新论文、基准与代码作系统检索，确认最相近工作和差异。

可检验的问题提出的机制必须证明什么
A. 证据约束的自适应精修：在相同软件和预算下，能否更可靠地改进结构？把 map/模型/序列/化学组成和每次变更建成可追溯的候选图；分支执行，独立检查几何与数据支持，违反约束时回滚。与固定精修、专家既定协议、相同工具的通用 Agent 比较；报告最终合格率、模型劣化率及拒绝错误修改的比例。对照 StructAgent 与结构监督论文，并明确差异，如系统性前瞻评测、约束设计或透明的候选决策。
B. 类型感知的跨工具编排：显式结构语义能否减少科学上错误的工具链？操作输入输出标注结构实体、模型编号、链/残基 ID、单位、参考坐标系、half-map 配对、质控前提和适用条件；候选计划先做类型与条件检查。与仅自然语言工具描述、JSON schema 基线比较；测试格式合法但链错、残基号错、单位错等“可运行但科学错误”的问题。衡量隐藏错误检出、正确链路率及误拦截率。
C. 多候选评价与停止策略：Agent 是否过早接受第一个设计？明确生成候选集、独立多维评分、保留多样性、按预算决定继续或停止；约束不通过则返回无结论。匹配模型调用、GPU 时间及候选数量，比较首个候选、固定深度和自适应停止；看最终有效率、最佳候选质量、成本以及假阳性。已有 BioDesignBench 已研究评价深度，需要证明新机制或新任务的增量。
D. 实验反馈下的结构候选优先级设计序列或复合物 → 基于计算与已有实验结果选择下一批 → 接入湿实验结果 → 更新下一轮，研究预算分配。先历史数据回放，再前瞻盲测；对照随机、领域启发式、主动学习或贝叶斯优化，并固定批量和实验预算。最终使用结合/活性等独立实测，而非仅用预测分数证明发现。

10. 一条可落地的论文实验设计：以 cryo-EM 精修为例

研究假设。在相同候选操作、模型和计算预算下，显式跟踪多指标及原始数据证据的自适应决策，相较只看单一全局分数或固定流程，能够提高预定义的结构质量合格率并减少模型劣化。这里“合格”必须在实验前由专家写出，避免看结果后挑有利指标。

  1. 构造数据。按结构家族、分辨率范围、链数、配体组成和起始模型质量分层收集项目；记录许可、来源、map 与 half-map、序列、初始结构和已有质控。应以结构家族/同源关系及时间分割开发与测试，避免同一结构或近同源数据同时出现在调参和测试中；保留困难和失败例子，不只挑选顺利案例。
  2. 预注册比较。至少包括原始模型、固定预设精修、专家制定的有限协议、使用同样工具的基础 Agent、完整系统。方法间统一工具版本、数据、候选次数、总算力和停止条件；计算失败与超时纳入分母。若有人类基线，要记录经验、允许的时间、人工修改与审批。
  3. 逐个受控消融。去掉类型/前置条件检查、去掉独立验证、去掉候选回滚、将自适应改为固定顺序，其他配置保持一致。不要一次同时删除多个机制，否则无法定位效果来源。多个角色并非关键假设时，单 Agent 与多 Agent 也需要相同工具和预算的比较。
  4. 按任务量化。主要终点可设为满足预注册多指标约束的案例比例；同时报告 map 支持、几何离群、clashscore、局部拟合及相对起始模型变化。half-map 可用于额外的过拟合检查，但具体处理应遵循对应软件和实验方案，不能用单个数作真值。次要终点为任务成功率、失败/回滚率、时间、CPU/GPU 消耗、成本、人工审查时间和可复现率。
  5. 统计与审核。以结构案例为独立单位做配对比较及置信区间，重复运行反映随机性，不把同一结构的多次运行伪装成独立结构；对多个指标或多组比较控制解释范围。专家盲审部分结构的关键局部变更，报告分歧与未决问题，并给出每种失败类型；研究预算应做预实验与样本量论证，避免只报告最好一次。
  6. 前瞻与可重复。如果条件允许，留出未参与设计的真实项目作前瞻验证，复核实验数据与关键局部；发布脱敏输入、操作契约、容器/版本、固定随机种子、评测代码与完整轨迹。对于不能公开的结构，报告可公开的合成/公开复现集及不可公开部分的审计方式。

如何解释结果。若系统缩短操作时间但结果质量无提升，结论是效率而非质量突破；若只在部分分辨率范围有效，就报告适用范围；若无法拒绝模型劣化，也需要公开失败。可发表性依赖问题、严格对照、数据规模、独立验证与真实增量，而非系统名称或调用工具的数量。

11. 与结构计算工具板块的衔接：从清单到闭环

阅读第四板块时，建议把工具清单转化为具体任务图，而不是先问“能接多少软件”。例如一个冷冻电镜精修任务：

  1. 输入层：实验 map、匹配的 half-maps、序列、起始模型和样品中已知组分；解析模型编号、链、残基与坐标，缺少关键化学信息时先向研究者明确。
  2. 评估基线：用合适的验证程序记录初始 map 拟合与几何问题，生成机器可读取的局部问题列表，原模型不可被覆盖。
  3. 产生分支：依据问题类型调用合适的软件做有限次精修、侧链或局部重建；各分支记录版本、参数、输入哈希与作业状态。实际选用的软件以系统可部署与许可为准。
  4. 比较和决策：针对每个候选分别检查几何、模型与实验数据的一致性、特定区域变化及潜在过拟合；违反预设条件时回退。RMSD 或地图相关性提高都不单独等于科学更可靠。
  5. 交付：输出候选与起始结构、可复现操作轨迹、定量对比、局部变更及其证据，明确未解释密度与需人工检查的离子/配体。由研究者最终确认模型。

这条例子对应第四板块的格式解析、模型构建、精修、结构质量、密度匹配和可视化等工具类别；有了清晰任务契约，再选择适配软件、部署后端和评测集。第二区工程部分负责实现状态、异步执行与恢复，本章负责科学语义与验收边界。

13. 将“分析结合界面”拆成可执行且可复核的任务

下面是为 NBDB 设计的示例工作流，并非某篇论文报告的现成实现。用户问题可以是：“比较两个复合物中链 A 与链 B 的界面，解释哪些残基接触改变。”如果 Agent 只检索文献并给出一段描述，实际上没有回答这项计算问题。

  1. 把自然语言转换为任务对象。记录输入结构文件或 PDB 条目及版本、要比较的两个状态、用户指定的生物学组装体、链的映射依据、接触定义、感兴趣区域与输出要求。特别区分不对称单元与生物学组装体，不能默认输入坐标一定代表真实复合物。
  2. 核查实体和映射。读取 mmCIF/PDB，检查模型号、链标识、缺失残基、占有率、alternate location、配体、水和编号体系；比较两个状态时通过序列比对及显式映射表对齐对应残基，记录无法映射的位置。若 A 链在两个文件代表不同实体，或用户未指定组装体且多种解释合理，就暂停并向用户说明，而非自行猜测。
  3. 规定可复现的界面定义。例如将界面定义为不同链之间任意非氢原子距离不超过 4.5 Å 的残基对；4.5 Å 在此只是示例阈值，并非放之四海而皆准的科学标准。保存选用模型、原子筛选条件、alternate location 处理、距离阈值和软件版本。按需补充埋藏溶剂可及面积、氢键与盐桥等指标，但它们各自依赖具体定义和参数。
  4. 分别计算并比较。先为每个结构独立生成链间残基接触表，再按映射比较共有、消失和新增接触；序列缺失、分辨率不足、构象变化或实验条件不同都会影响结果，应标明不可比较项。结构叠合须陈述选择的原子集合与方式；内部距离不要求两个文件先对齐，不能把叠合误差当作接触变化。
  5. 输出证据包。为每项论断提供原文件、链/残基标识、原子对与距离、映射关系、接触表和可视化脚本。若一个状态为预测结构，则同时提供其局部及链间可信度相关信息；pLDDT、PAE 或复合物评分不能直接当作结合自由能、实验亲和力或功能验证。

为什么这适合研究 Agent？这个例子能产生明确的可验收对象：结构化接触表与证据链接。评测时可故意交换链名、改变残基编号、移除部分残基或提供不匹配的组装体，检查 Agent 是错误地输出貌似可信的结论，还是正确识别并表达输入不足。比较同一基础模型的“仅文档工具描述”与“结构类型和前置条件检查”两种设置，才能研究语义约束带来的增益。

14. 将论文中的结果转化为产品与研究决策

每次阅读新论文时可按五层提问：输入是否需要人工整理？决策由模型还是确定性规则完成？执行是本地计算、远程 API、数据回放还是物理实验？评价是真值、代理分数、模型裁判还是专家判断？外推跨了哪些数据、环境与目标？例如 Paper2Agent 的教程复现说明包装具备已测输入的可操作性；Agent Rosetta 的预测与模拟说明设计在所用计算代理指标上有竞争力；Robin 的实验反馈提供更强的生物学证据，但仍需要进一步确认机制。三者回答不同问题，不能把其成功率混为一项。

NBDB 初期可按一个任务族建立纵向深度：先固定一类输入和参考数据，完成可运行操作、独立验证、结果展示与失败样本库；再开放相邻任务和操作。研究上应把最有希望的机制写成反事实对照，例如“有无显式链/残基映射检查，科学错误率是否下降”，而不是单纯宣布“引入了多 Agent”。公开失败案例和数据边界也有助于研究者复现与改进。
