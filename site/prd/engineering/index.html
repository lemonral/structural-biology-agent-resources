01 / ENGINEERING

代码边界与不可破坏的不变量

一个主控与一套业务账本；API、模型决策、科学执行和文件发布各有明确的责任。

ED-01 一仓库、一个LangGraph主控、PostgreSQL业务账本与持久检查点、一个dispatcher及受限CPU子进程

先控制科学合同、权限和恢复，P0不引入Redis、Celery、Kubernetes或第二个Agent主控。

验收：运行事实不依赖浏览器、内存或追踪平台。

ED-02 原始请求、冻结科学合同、计划版本、实际尝试分离

同一合同可修计划；改变科学问题生成关联的新请求修订/Run。

验收：每个数值定位到frozen_spec_id、plan_id、attempt_id和产物hash。

ED-03 全流程同Run预算、六维整数账本

意图解析、重试、规划、报告均收费；恢复不能重置额度。

验收：input_tokens/output_tokens/model_calls/cpu_ms/tool_attempts/money_microunits均可追溯。

ED-04 文件不可变，数据库保存可见性和验收事实

文件系统与DB不能组成天然原子事务，要显式处理中间状态。

验收：完成态不指向缺失/错误字节，孤儿文件有回收条件。

ED-05 接口/类型能校验结构，编译器/授权/科学检查继续校验语义

合法JSON不代表链、映射、单位、权限或科学结论成立。

验收：模型候选在执行前通过明确的确定性检查。

HTTP决策实现要求验收
P0同源Web采用真实认证会话，CLI可用独立短期Bearer；身份和项目权限来自后端。cookie HttpOnly+Secure+SameSite；变更验证CSRF和Origin。仅trusted proxy可传认证头且必须剥离外部同名头。AC-10, AC-17
每个POST/PATCH都带Idempotency-Key，任务/Run修改另有版本CAS。数据库键绑定actor/project/method/route/key+规范payload摘要；并发进行中409+Retry-After，payload不同409。完成响应重放前重新授权；保留期初始30天并随政策版本保存。超保留期不自动重提，客户端先取已有资源/人工核查。AC-14
一个预分配ANALYZE Run覆盖意图、澄清、计划、科学计算、报告及全部重试费用。createRun事务先预留6维总预算；恢复不增额。FrozenTaskSpec计算前冻结，同合同PlanRevision追加。科学合同变化创建关联的新TaskRevision与Run，新预算独立预留，不能冲销旧UNKNOWN费用。AC-08, AC-13, AC-14
列表使用不透明游标、稳定排序和当前资源权限，不返回内部路径。默认20/最大100；游标绑定过滤条件、项目、身份与排序并签名/过期。未知/无权ID统一404；已可见资源但无变更角色403。AC-10
SSE只投递已持久化的安全事件摘要；网络允许重复，业务事实不重复。id=run_id:seq；Last-Event-ID与after_seq二选一；过期410取GET Run快照再接流。断线不取消；按event_id去重。15秒心跳与事件保留30天为初始运维建议，需先导配置。AC-14, AC-19
文件按artifact_id读取；先授权后处理Range，HTML默认附件。200/206/416单范围；强ETag、Content-Range、private no-store、nosniff、safe filename。报告主界面读取结构JSON安全渲染，不直接信任模型HTML。AC-09, AC-10, AC-18

JSON Schema只校验结构；真实科学语义与授权在编译/执行层再次检查。严格JSON拒重复key、NaN/Inf、过深/过大；配对、对象身份、DAG无环、单位、资源与权限用真实工件检查。AC-01, AC-02, AC-03, AC-04, AC-12

      数据库强制

      • 主键/UNIQUE、项目复合FK、基础enum/非负数、Run/FrozenSpec/Plan/Attempt关联、不可变/append-only事实触发器。
      • 当前计划必须编译PASSED且绑定相同FrozenSpec；Run原始请求/配置/deadline不被UPDATE改变。

      服务层继续强制

      • 真实认证、当前权限/撤销、能力enabled/健康、对象选择/单位/科学前提、依赖无环、操作合法迁移。
      • SQL JSON列不是完整JSON Schema；finite/strict类型、来源和字节路径验证须由契约层/适配器继续完成。
      • 账户锁顺序、scope匹配、reserved/confirmed缓存与明细一致、同operation资源对应及文件目录实际隔离。
      • 复合FK不阻止数据库superuser；迁移owner与运行角色分离。运行角色不得ALTER/禁用触发器或作为表owner。
      • RLS不是本草案已实现能力；若后续启用，必须验证事务连接池的每请求project/principal上下文和BYPASSRLS边界。
      • API JSON整数限制为0至2^53-1；数据库bigint并不授权更大的wire数字，超出需明确拒绝或新契约，不经浮点round。SETTLED所引用usage必须是可信CONFIRMED，不能把估计值直接当结算真值。
      • 冻结前PREFLIGHT仅允许inspect_structure及受控输入/参数；普通科学TOOL必须引用同Run编译PASSED的Plan/FrozenSpec。PREFLIGHT完成不表示科学分析已ACCEPTED。

-- Immutability guards: schema drafts protect canonical facts even if an adapter
-- accidentally issues UPDATE. They do not protect against a database superuser.
CREATE FUNCTION deny_change() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN RAISE EXCEPTION '% is append-only', TG_TABLE_NAME USING ERRCODE='23514'; END;
$$;
CREATE FUNCTION guard_request_payload() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 IF ROW(NEW.project_id,NEW.task_id,NEW.revision,NEW.request_payload,NEW.request_digest,NEW.created_by,NEW.created_at)
  IS DISTINCT FROM ROW(OLD.project_id,OLD.task_id,OLD.revision,OLD.request_payload,OLD.request_digest,OLD.created_by,OLD.created_at)
 THEN RAISE EXCEPTION 'task revision payload is immutable' USING ERRCODE='23514'; END IF;
 RETURN NEW;
END;
$$;
CREATE FUNCTION guard_run_snapshot() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
 IF ROW(NEW.project_id,NEW.task_id,NEW.task_revision,NEW.source_run_id,NEW.requested_by,
        NEW.purpose,NEW.mode,NEW.model_profile_version,NEW.config_snapshot,NEW.config_digest,
        NEW.scope_snapshot,NEW.scope_digest,NEW.policy_version,NEW.deadline_at,NEW.created_at)
  IS DISTINCT FROM ROW(OLD.project_id,OLD.task_id,OLD.task_revision,OLD.source_run_id,OLD.requested_by,
        OLD.purpose,OLD.mode,OLD.model_profile_version,OLD.config_snapshot,OLD.config_digest,
        OLD.scope_snapshot,OLD.scope_digest,OLD.policy_version,OLD.deadline_at,OLD.created_at)
 THEN RAISE EXCEPTION 'run request/config/total deadline is immutable' USING ERRCODE='23514'; END IF;
 IF OLD.frozen_spec_id IS NOT NULL AND NEW.frozen_spec_id IS DISTINCT FROM OLD.frozen_spec_id
 THEN RAISE EXCEPTION 'frozen spec cannot be replaced' USING ERRCODE='23514'; END IF;
 IF OLD.initial_plan_id IS NOT NULL AND NEW.initial_plan_id IS DISTINCT FROM OLD.initial_plan_id
 THEN RAISE EXCEPTION 'initial plan cannot be replaced' USING ERRCODE='23514'; END IF;
 IF NEW.current_plan_id IS NOT NULL AND NOT EXISTS
  (SELECT 1 FROM structbio.plans p WHERE p.project_id=NEW.project_id AND p.run_id=NEW.run_id
   AND p.plan_id=NEW.current_plan_id AND p.compile_status='PASSED' AND p.frozen_spec_id=NEW.frozen_spec_id)
 THEN RAISE EXCEPTION 'current plan must pass compilation and bind the same frozen spec' USING ERRCODE='23514'; END IF;
 RETURN NEW;
END;
$$;

      5. 编译器纯函数产生计划与诊断；需要新模型候选的调用也先记Attempt与预算。编译候选PENDING仅作为事件保存，plans表插入时结果已是PASSED或REJECTED。
      6. BEGIN；锁Run，核对同一FrozenSpec及当前启用目录/编译版本。INSERT不可变PlanRevision和Steps；PASSED时设置initial_plan_id（仅首次）及current_plan_id，追加PLAN_COMPILED事件；COMMIT。
      7. 同合同修复可追加PlanRevision和真实Attempt，继续消耗原Run剩余预算。科学合同实质改变时原子创建新TaskRevision/Run并记录source_run_id，旧Run按真实执行状态取消或核查，旧UNKNOWN预留不可转为新余额。
      提交不变量：Run固定原始请求、已冻结科学合同和总限制；动态计划只增加版本，不改历史。

      失败/回滚：冻结冲突、目录变化、取消或版本冲突则回滚全部DB记录；已发布但未登记的字节按既有孤儿GC规则清点回收，不伪造执行Attempt或科学成功。

      验收：ST-03, ST-04, AC-01, AC-19

      TX-03 单dispatcher领取与租约心跳

      锁顺序：进程持有专用数据库连接上的session advisory lock；领取单条queue/Run短事务锁。

      1. P0仅一个dispatcher。启动用固定应用命名空间的pg_try_advisory_lock获取session锁，失败的第二实例退出；连接丢失立即停止新派发并进入受控子进程核查。锁不等于OS进程隔离。
      2. BEGIN；SELECT run_id FROM run_queue WHERE queue_state='READY' AND available_at<=clock_timestamp() ORDER BY available_at,run_id FOR UPDATE SKIP LOCKED LIMIT 1；锁Run并重新检查取消、deadline、当前授权及项目并发。
      3. UPDATE run_queue SET queue_state='LEASED', lease_owner=:worker_id, lease_epoch=lease_epoch+1, lease_expires_at=:bounded_deadline, heartbeat_at=clock_timestamp() WHERE run_id=:run_id AND queue_state='READY' RETURNING lease_epoch；更新Run状态/版本并追加事件；COMMIT。
      4. 每次心跳只在owner+lease_epoch+LEASED匹配时延长至不超过Run总deadline；0行受影响即停止继续提交新动作。每Run串行一个科学Attempt，P0全局最多两个CPU子进程处理不同Run。
      5. 过期LEASED不能被普通claim直接重新启动。reconciler先fence旧epoch，记录RECONCILING/UNKNOWN，核对进程控制组、operation和已封存工件；确认旧执行已结束且语义允许后，才能重排READY或接受已完成证据。
      提交不变量：每次租约有单调epoch；陈旧结果不能覆盖新控制事实。

      失败/回滚：丢锁/心跳/DB不可用即停止新派发；不能因为lease超时就假定旧子进程已死。

      验收：ST-05, ST-06, AC-14, AC-15

      TX-04 Attempt、六维资源和文件字节原子预留

      锁顺序：Run/queue/attempt → budget_accounts按account_id排序 → storage_quota_accounts按account_id排序；所有调用统一这一顺序。

      1. 确定真实请求的operation_id与request_digest；重放同Attempt复用原operation_id，真正重试在确认前次失败/未提交后创建新Attempt，attempt_no递增。不能对UNKNOWN盲建新Attempt。
      2. BEGIN；锁Run及当前租约，核对scope、能力版本、固定参数和deadline。MODEL可形成冻结前候选；仅PREFLIGHT=registered inspect_structure可空Plan/Step执行固定对象检查，保存capability_id/tool_version。普通科学TOOL必须引用已通过编译计划及同FrozenSpec。INSERT Attempt(CREATED)。
      3. 依据服务端价格快照与provider严格max_tokens/timeout等计算保守预留，不接受模型自报cost。锁定本Run和所属项目周期所有相关metric账户，验证currency一致、confirmed+reserved+new<=limit。
      4. 六维为input_tokens、output_tokens、model_calls、cpu_ms、tool_attempts、money_microunits，全部整数非负；money为1e-6项目账本币种，报价currency和price_version必须明确，P0不静默换汇。
      5. 插入唯一operation的reservation及各账本line；更新account.reserved与版本。上传/导入/工具输出同时锁项目字节额度，工具还锁Run累计字节额；预留本次最大暂存+输出量。
      6. 将Attempt置AUTHORIZED，追加AUTHORIZATION/BUDGET_RESERVED事件；COMMIT后才交受限子进程/模型连接器执行。外部调用绝不发生在DB锁事务内。
      7. PREFLIGHT消耗实际CPU及tool_attempts等适用额度，与科学TOOL共享Run总预算；不能借PREFLIGHT启动RMSD/接触或任意其他能力。
      提交不变量：操作、权限、所有额度及Attempt一同获准或全部失败；新Run不能绕过项目周期预算。

      失败/回滚：任一维不足就回滚整组预留并返回BUDGET_EXCEEDED/资源原因；不能部分预留后先启动。

      验收：ST-07, ST-08, ST-09, AC-12, AC-13

      TX-05 可信产物登记、完成回执与事件

      锁顺序：文件发布前后均核对租约；最终短事务锁Run/queue/Attempt/相关额度，按固定顺序。

      1. 子进程仅写其私有输出目录；可信supervisor核对文件类型/路径、字节总量和退出情况。trusted artifact broker在隔离写入根处理实际文件，模型不提交宿主路径。
      2. 关闭并fsync文件，计算SHA256与bytes。INSERT STAGED Artifact及parents，所有派生关系同项目；记录预期内容地址。之后在同一文件系统内以不覆盖方式原子发布，已存在内容必须核对hash+size。
      3. BEGIN；核对operation_id/request_digest、lease_owner/epoch、期望状态和取消事实。重复完成若completion_digest相同则返回原回执；不同内容同operation冲突，进入核查，不覆盖既有工件。
      4. 可信broker确认内容仍存在且hash/size一致，Artifact转AVAILABLE；Attempt写SUCCEEDED/FAILED及不可变completion_receipt，追加事件。进程成功只代表执行，不把science直接写ACCEPTED。
      5. Usage采用TX-06结算；独立检查生成append-only Validation。所需工件和检查都完整后，controller才可将Run置COMPLETED并给科学ACCEPTED/REJECTED/INCONCLUSIVE；追加事件与outbox同事务。
      6. Artifact来源必须如实登记：原始输入用INPUT；真实模型/工具尝试产物用ATTEMPT；controller生成的正式Spec字节用CONTROL_EVENT绑定同Run业务事件，不用假MODEL/PREFLIGHT填充producer。
      提交不变量：没有AVAILABLE身份、完整内容及独立检查的结果，不能显示已验证交付。

      失败/回滚：陈旧epoch的普通finish不推进状态；实际已消耗资源仍由reconciler核实记账，不能因拒收陈旧回执隐去成本。

      验收：ST-10, ST-11, ST-12, AC-05, AC-19

      TX-06 使用量结算、UNKNOWN和晚到更正

      锁顺序：reservation lines/usage操作身份 → 对应账户按account_id排序；line_version与applied_usage_id做CAS。

      1. 每次provider/OS观察都保存不可变usage_version。ESTIMATED是估计，CONFIRMED是可信实际量，UNKNOWN.quantity必须NULL；输出计数以可信provider响应/supervisor为依据。
      2. 调用超时且可能已计费：预算line置UNKNOWN，预留额仍保留在reserved，unknown_reserved标其子集；不能当作0或直接退还。计费UNKNOWN与Run执行UNKNOWN是不同维度。
      3. 收到可信确认后在同一事务将保留预留移除，并把actual-applied_quantity增量加入confirmed；line记录该usage_id/quantity/version，重复同版本不再加账。
      4. 真实账单更正以新usage_version追加并按增量修正，不能把多个版本总和当费用。若真实费用晚到超限，仍记录事实并阻止新预留/触发告警；因此SQL不设会拒绝真实费用的sum<=limit CHECK。
      5. 只有可核实未执行/未计费或已完成结算，才能释放相应剩余额。费用无法确认的挂账按责任人+期限核查，策略性核销也保留UNKNOWN/调整依据，不伪造已知零费用。
      6. Run与项目账户是同一次usage的两种限额视角；最终费用报表从操作级可信usage最新版本读取，禁止将两层账户相加。
      提交不变量：全部尝试、失败、重试和未知费用保留；已确认事实不会因预算错误而无法落账。

      失败/回滚：结算版本冲突重新读取line，不能重复扣/加；价格币种不一致进入核查而非自动换算。

      验收：ST-08, ST-13, AC-08, AC-13

      TX-07 反馈处理与版本冲突

      锁顺序：feedback_issue FOR UPDATE；真实maintainer/owner membership FOR SHARE。

      1. 普通成员POST反馈仅创建NEEDS_REPRODUCTION和首条history，绑定可访问Run/工件/报告版本，不接收resolved/scientific_truth。
      2. 维护员PATCH带expected_version；BEGIN锁issue，核对角色及证据权限；状态变为REPRODUCED/DISPUTED/RESOLVED需reason和evidence_refs。
      3. RESOLVED必须声明resolution_type并提供可访问证据与reason。FIXED必须有regression_case_id（数据库regression_case_ref）及fix_version；NOT_A_DEFECT/DUPLICATE以证据说明非缺陷或重复，不要求也不编造修复版本。UPDATE issue WHERE version=:expected_version并保存处理类型，同时INSERT不可变history(version+1)记录相同状态/类型/证据；COMMIT。
      4. 反馈只产生待复现线索，不能改旧Validation或已冻结评分标签；确认缺陷进入新版本回归和发布流程。
      提交不变量：反馈状态和追加依据一致，旧科学证据保持不变。

      失败/回滚：并发PATCH一成功一409；跨项目工件引用拒绝，普通用户不能提升反馈为真值。

      验收：ST-14, AC-21

      幂等身份与保留

      作用域
      project_id + principal_id + HTTP method + canonical resource scope + SHA256(Idempotency-Key)；request_digest来自版本化的严格规范化请求。
      冲突
      相同key相同digest返回原已提交回执；相同key不同digest返回409。业务对象的稳定operation_id仍需保留，不能只依赖HTTP缓存。
      保留
      response_expires_at是回执缓存有效期，之后保留摘要墓碑并返回KEY_EXPIRED，客户端明确发起新请求才使用新key。最终清除窗口由最大客户端重试时域/Run保留/组织策略决定，清除后不再宣称同key永远去重。
      权限
      返回缓存回执前重新鉴权；不能借曾经有效的key读取已被撤销访问的项目数据。响应缓存同样避免凭证、宿主路径和不必要上下文。

      六维预算与计费未知

      指标
      • input_tokens
      • output_tokens
      • model_calls
      • cpu_ms
      • tool_attempts
      • money_microunits
      单位
      前五者为其名称表示的整数计量；money_microunits=1e-6所选项目账本币种。USD仅为初始示例，P0不做静默换汇。
      报价
      额度账户只保存余额币种；每次reservation.pricing_snapshot及货币usage保存currency+price_version。报价版本更新不创建游离于项目周期总额的新余额。未配置模型/价格/许可时禁止agent收费调用。
      预留不变量
      预留时必须同时满足每个适用RUN及PROJECT_PERIOD账户：confirmed_units + reserved_units + requested <= limit_units；持锁后检查并更新全部维度。
      未知计费
      unknown_reserved_units是reserved_units的子集，不是再加一份费用；UNKNOWN usage quantity=NULL。费用未知与Run执行状态未知分别记录。
      结算
      同操作/维度的多个usage_version是观察与更正历史，报表取可信最新值，预算按actual-applied_quantity差额CAS。Run和project账户不能相加当两笔收费。
      超额事实
      真实量晚到超出保守预留也必须落账，并冻结后续预留/告警；不设置会拒绝实际事实的sum<=limit表CHECK。
      窗口
      项目周期边界由服务器UTC配置冻结；一项长Run首次动作所占的周期身份固定或按明示跨期政策分摊，禁止通过延迟结算切换到新周期逃逸旧额度。
      计数核对
      定期以reservation lines最新applied_quantity/有效reserved重算account缓存；差异告警并停新预留，修正必须有审计原因，不覆盖usage历史。

      步骤事务内事务外失败时
      1. 领取与预留验证单例锁→锁Run/队列/预算与存储quota→确认无在途Attempt→创建Attempt+稳定operation_id→增加/绑定lease_epoch→提交派发事件。建立已知执行scope和只读输入。事务失败没有Attempt可运行；预留后启动失败要按实际未启动证据结算，不静默删除。
      2. 隔离启动记录launch intent及scope_id、registry/profile digest。可信runner建立隔离边界并启动固定入口。spawn已发生但DB未写PID时，按预先确定scope_id核查真实进程；无法确认则UNKNOWN，不立即重提。
      3. 观察与续租以run_state_version/lease_epoch CAS保存心跳及当前观测，必要时续租。OS/cgroup计量、读取有界管道、检查deadline和取消。租约失联只表示控制面不确定；转RECONCILING，确认旧执行停止后才可能重新排队。

      • dispatch
      • heartbeat
      • finish
      传输

      递增heartbeat_seq、observed_at与阶段；由supervisor验证执行身份并通过DB CAS续租，续租不超Run deadline。重复/乱序心跳不可倒退状态。
      结果回报
      只报告SUCCEEDED/FAILED/CANCELLED与候选文件；科学状态仅NOT_EVALUATED或适用的NOT_APPLICABLE。ACCEPTED只能由科学验证器持久化。

      • 严格JSON解码先拒绝NaN/Infinity；additionalProperties=false不替代ACL、有限数、hash和语义检查。

      • 单个message和stdout体积有界，未知protocol_version拒绝；schema更新需兼容/迁移证据。
      • capability_id与parameters采用oneOf约束；消息没有shell、command、env_secret、原始主机路径等扩权字段。
      • 示例中的UUID、时间、输出hash/bytes是虚构；部分输入hash来自既有公开AdK参考，不能当本次执行证据。
      • operation_kind=PREFLIGHT只允许inspect_structure；plan_id/frozen_spec_id/step_id全部null，仍计CPU/tool_attempts并受隔离和授权。普通TOOL三者必须非null，INSPECT purpose只能PREFLIGHT；科学子进程协议不用于MODEL调用。

      Worker包与函数接口

      接口输入输出不变量
      Registry.resolve(capability_id, tool_version, project_scope) -> RegisteredAdapter服务端注册目录与当前授权；不是模型提供可执行文件。不可变代码/环境digest、严格schema、资源profile、科学接受协议。未登记/禁用/未通过部署回归的能力不产生执行入口。
      InputResolver.prepare(attempt, artifact_refs) -> ReadOnlyInputSet同项目已授权artifact_id、摘要、预期类型与引用闭包。后端生成input_0001等别名，映射到已核对的只读输入，不向模型暴露宿主路径。逐对象ACL、字节hash/size/fstat核对；所有间接输入也须在允许闭包。
      Dispatcher.claim_and_reserve(worker_instance) -> ClaimedAttempt | None单例租约、READY队列、Run剩余总预算与存储quota。Attempt、operation_id、Attempt.lease_epoch快照、预留引用与effective limits。短DB事务锁/版本CAS后提交；不在事务锁内调用模型、fork或等待文件。

      • float64；moving X与reference Y按同一映射排序。拟合区F至少3对非共线点，重复/非有限数拒绝；rank阈值按数值精度、点数与尺度的版本化策略决定，不能误拒所有平面(rank2)点。

      • 变换只由F求得；E单独评价 sqrt(mean(sum((X_E@R+t-Y_E)^2)))。F/E索引、原子数量、参考/移动方向与单位全部入产物。
      • 不自动剔除离群点或调整阈值。SVD不收敛/非有限输出/不变量失败由数值错误报告，不能让模型反复跑同一计算刷成功。

      RB-W01 Worker/dispatcher重启
      1. 停止新增领取并取得singleton状态。
      2. 读取DB LEASED/UNKNOWN与真实execution_scope列表；不只根据过期时间判失败。
      3. 对照owner/boot_id/epoch/进程创建身份与已发布工件；仍运行则接管监控或按策略终止。
      4. 确认旧执行停止和usage/文件事实后，CAS终结或重新READY；不重置预算。
      恢复退出条件：无未归属进程，所有在途Attempt有终态或明确UNKNOWN责任，才恢复领取。
      RB-W02 空间/配额耗尽
      1. 停止新分析准入及超额写入。
      2. 按RunStorageQuota与可信实际字节核查暂存、候选、已发布/孤儿文件；不按年龄直接删在途文件。
      3. 保留受影响Run证据；只按GC策略清理确认无引用/无在途的对象。
      4. 恢复配额与写入探针，相关Run按原状态核对。
      恢复退出条件：字节账本与实际存储一致，未丢已承诺工件，余量满足冻结准入条件。
      RB-W03 坏科学结果/报告引用错误
      1. 禁用受影响能力/模板的新Run。
      2. 定位输入、选区、映射、版本和首个失效不变量；保全旧产物与验证记录。
      3. 用独立参考复现，修复后加入dev/reg，不把测试答案馈回当前holdout。
      4. 受影响旧结果追加重评记录并标记范围，不覆盖历史报告。
      恢复退出条件：数值、正常任务、错误输入与报告引用回归通过，责任人审阅后分阶段恢复。
      RB-W04 升级/回滚
      1. 发布包固定代码、镜像/依赖、schema、能力、提示/模型和检查器版本。
      2. 先迁移兼容的增量schema，跑合同/科学/故障/隔离回归，参考模式与真实模型先导分开。
      3. 小范围放新Run；在途Run保持其旧合同/环境可重现，不强换工具版本。
      4. 回滚先停新准入；确认旧程序兼容当前DB/对象，再回应用版本；数据库回退仅按演练后的灾难恢复流程。
      恢复退出条件：没有被误覆盖的在途状态，旧/新报告都能追溯，必要恢复演练完成。
