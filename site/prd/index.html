01 / PRD

为什么做，以及怎样判断做成了

减少把问题翻译成工具命令和复算材料的重复劳动，同时保留研究者对科学对象与结论的判断。

要解决的问题

  • 通用聊天能建议工具，但不能单独确认链、映射、科学前提与真实产物。
  • 领域程序能计算，但对象、参数、环境、依赖和复算记录仍常靠手工连接。
  • 产品增量是将科学语义、受控执行、独立检查和证据报告连接成同一任务闭环。

一次交付算什么

研究任务及其规格、运行与证据；聊天承担输入、澄清与解释，任务工作台承载正式对象。

任务在权限和预算内产生通过领域检查的工件及证据相符的报告；退出码、模型措辞和页面渲染均不单独决定成功。

02 / PRD

首版边界与长期能力地图

先让一个有限工具集合真正可靠，再沿统一能力包合同扩展各种结构计算任务。

以版本化能力注册、类型化输入输出、依赖计划和各任务的接受协议获得扩展性。首版只对已登记、已部署且通过参考验证的能力提供执行承诺。

任务能力族P0：首版必须交付P1：闭环后扩展P2：新协议 / 新模态
检索、解析与对象身份允许来源PDB ID或获授权上传；PDB/mmCIF；模型/链/残基/原子/altloc清单与hash。受控数据源、批量导入、装配体构建与更多预处理。跨数据库、多模态对象与组织治理。
对应与结构叠合受支持蛋白Cα选择、显式一对一映射、全链/指定区拟合与独立评价区、RMSD和逐位移。复杂自动对应、结构域、检索和多结构比较。更多复合物、非标准聚合物与多模态对齐。
接触与界面描述明确蛋白/配体对象的重原子距离接触、原子对和残基汇总。SASA/埋藏面积与更多界面几何指标。更复杂相互作用模型与多条件统计。
模型质量与实验支持输入完整性、对象和数值检查，不能称完整结构质量评价。明确范围的几何质量、局部置信度与结构特征。密度/实验模型联合验证。
轨迹与构象集合识别不支持，解释所需能力。先设计拓扑/轨迹、PBC、拟合和采样接受协议。版本化轨迹分析、相关性、重复与不确定性。
预测与对接结果分析不承诺预测、对接或设计。按明确格式设计结果导入和溯源。适用范围、许可和独立验证明确后接入具体能力。
组合与执行后端有限注册能力的类型化依赖计划、受控CPU Worker、持久状态和产物。小批量、长任务、受控HPC适配器；真实恢复/取消演练。更广GPU、组织配额与复杂跨环境流程。
报告、复核与改进证据报告、对象/指标视图、图表、下载、反馈与冻结回归。模板、专家复核、配置对照和受控优化。；可选只读3D浏览。跨项目知识复用与更大规模优化。

首版的支持模式

明确对象与已登记几何操作，可在一任务中组合解析、选择、对应、叠合、接触和报告。开放问题先拆成支持操作，无法落入范围时停在解释/澄清，不虚构工具结果。

开发者注册新能力时，同时提供输入输出类型、前置条件、执行边界、科学验收和回归用例。通用性以新对象及新组合实测，不以工具数量衡量。

首版明确不做

  • 任意shell、任意Python和模型自行安装软件。
  • 任意网站抓取、开放外发、覆盖原文件或修改项目权限。
  • 真实Slurm/GPU提交、分布式多Agent、生物设计与湿实验执行。
  • 所有结构问题都能处理的无边界承诺。
  • 自动证明亲和力、因果功能、自由能或动力学机制。
  • 把固定计划教学包包装为已验证的模型驱动Agent。
P0指进入限定团队试点前的必需范围，按里程碑逐步完成。高影响审批、新科学能力和自动优化分为“P0合同 / P1真实能力”，不把预留接口算作已实现功能。

J-03 失败闭环：重试、科学拒绝和恢复

比较任务遇到工具瞬时故障，用户关闭页面后回来查看或取消。

开始条件

  • Task/Plan/Run已持久保存。
  • CPU Worker是真正实现和被测后端。
1
系统 保存错误和剩余预算，仅对可重试类型有限重试。同Run的多个Attempt，失败进入成本与评测账本。
2
检查器 发现错对象/单位，尽管工具exit0仍拒绝科学接受。运行结果与科学拒绝理由分列。
3
用户 重开任务页或点击取消。同一Run可查；取消先显示请求中，真实进程退出才变已取消。

终态忠实反映事实，保留成功/失败/重试/取消证据，不交未经接受的成功报告。

事实与调度PostgreSQL：业务表、event/outbox 表、DB 队列、租约与锁；checkpointer 使用隔离表/命名空间

P0 不加 Redis/Celery/Kafka。队列吞吐或后端需求有实测瓶颈后再替换 dispatcher，业务合同不依赖队列实现。

执行隔离独立 CPU Worker + 固定镜像/依赖的非特权运行容器或等效受限进程环境

不让 API/模型进程直接解析任意输入或获得宿主文件与网络权限；工具由服务器注册。

只读输入、专用输出、无宿主凭证/控制 socket、受限网络与 CPU/内存/进程/磁盘/时间；须在目标服务器验证有效配置，不能以容器名称作为安全保证。

产物项目隔离的不可变文件存储 + PostgreSQL 元数据与 SHA-256

本地 SSD 文件即可支撑首版，API 按 artifact_id 授权读写；对象存储以后通过同一接口接入。

模型不提供宿主路径。写入临时文件、核对大小/hash 后以新身份提交；报告和原始产物不原地覆盖。

观测结构化审计/执行事件 + 请求/span 关联 + 本地指标

排查失败与记录全部成本，不让观测服务成为业务必需依赖。

持久业务事件与可选 trace 采样分开；不记录密钥、完整敏感坐标或模型私有推理。

假设建议默认需要确认
A-01 先建单课题组试点；开发版单人localhost，团队试点需要真实服务端认证与项目权限。开发版不对外开放；团队内网试点接既有SSO或认证适配器。用户名单、项目归属、现有身份系统。
A-02 P0以普通CPU坐标分析为主，公开或用户获授权的PDB/mmCIF输入。先用AdK参考开工；补充不同结构特点的对象验证后再扩充支持声明。真实数据种类、规模、保密要求和优先任务族。
A-03 模型供应商、型号、费用和上下文上限未确认。一个Planner接口、一个首期模型配置；凭证仅在服务端。可用服务、数据政策、网络和预算。
A-04 团队投入与工期未知。先交端到端垂直切片；按产物与验收证据退出里程碑，不虚构日期。开发与领域评审投入、环境、试点时间。
A-05 容量、资源阈值和SLO待先导测量。P0必须有保守可配置硬限额；上线前实测并冻结，不以无限制作为默认。文件大小、原子数、deadline、并发、模型和计算费用上限。
