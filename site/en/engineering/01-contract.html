What problem this chapter solves

A mature system must state what it accepted, which object it measured and what evidence will count as completion. Conversation gathers intent; a versioned contract makes it executable and reviewable.

Define the deliverable before the dialogue

“Compare these structures” could mean fold, assembly, local conformation or model quality. Decompose the request into objects, measurements, required inputs and outputs. A useful first operation is a specified-atom comparison under an explicit mapping. The Task persists the formal request after the chat disconnects. Separate user-provided facts, facts confirmed from files and information still unknown. Record defaults and their scientific effect; do not use a convenient chain default to erase ambiguity.

Put scientific semantics in both input and output contracts

A file path is not an input identity. Record content hash, format, model, chain namespace, residue/atom selection, assembly handling, units and missing-data policy. In mmCIF, auth and label identifiers can differ; a syntactically valid chain name may select the wrong entity. First inspect the actual hierarchy. Outputs should include correspondence tables, transformation parameters, per-position differences, coverage, exclusions and a validation record. A low RMSD is not a universal success criterion: it depends on the fitted and evaluated object.

Let the planner propose and the compiler verify

The model selects candidate capabilities and dependencies. A deterministic compiler checks registered tool versions, typed references, compatible selections, required validation, DAG structure, scope and resource limits. Reject a plan before side effects when its prerequisites fail. Accept equivalent valid paths rather than forcing one narrative reference sequence. Keep candidate actions, accepted plans, actual tool results and report explanations as distinct records.

Turn uncertainty into a control branch

Missing decisive identity goes to clarification; unsupported scope goes to a reasoned boundary response; transient tool failure goes to a safe bounded retry; insufficient science goes to rejection or inconclusive evidence. A same-contract execution repair can append a plan version. A changed scientific question after freezing creates a linked new request revision and Run. The original contract and failed evidence remain auditable.

Failure scenario and response

Scenario: A multichain file returns a plausible numeric result after a default chain was selected.

Response: Reject trusted scientific delivery if the actual selection does not match the contract. Show the object inventory, obtain the decisive selection and preserve the failed attempt. A plausible number does not establish that the intended object was measured.

This is a design exercise, not an incident report from a deployed service. Confirm actual behavior from task, process/job, artifact and policy records rather than from the final text alone.

Delivery checklist

  • A task has explicit objects, supported scope and refusal conditions.
  • Every default has provenance and a stated effect.
  • Input/output schemas include units, identity and selection semantics.
  • Planner proposals cannot bypass deterministic preconditions.
  • The report can be traced to a frozen contract and actual artifacts.
