A practical learning path for scientific Agents

Move from the first real function tool to typed tasks, durable execution and independently checked structural analysis.

Author: Yi Zhou (周熠)

Start from one inspectable question

Build a structure-inspection assistant that answers: “Which models and chains are present, and what parsing anomalies were found?” Add explicit structural-comparison tasks only after this first boundary is trustworthy. Choose one introductory course, one Agent framework and one supported model configuration; learning every framework first is unnecessary.

The learning materials are a source snapshot, not a claim that every example has been installed or run. Model credentials, scientific environments and compute services need separate setup. The existing offline exercises intentionally use a fixed plan or synthetic inputs and no real model. They help test execution and checking before adding model decisions.

Six steps, each with a verifiable artifact

StepBuildVerify
1. Understand the loopA diagram distinguishing model decisions, actual tools and environment state.Explain why a fixed workflow is useful and which decisions genuinely depend on new observations.
2. Add one real toolA standalone structure-inventory function, then a tool wrapper.One valid file returns genuine chain/model counts; invalid input gives an explicit error; actual parameters/results are inspectable.
3. Define contractsTyped request, success and error schemas with file/model/chain identities.Unknown fields, nonexistent chains, missing units and non-finite numbers do not silently become valid defaults.
4. Save state and recoverTask, Step, Attempt, optional Job and Artifact records with failure classes.After restart, inspect existing work before resubmitting. Closing the UI does not cancel computation.
5. Add independent acceptanceA small task set and reference distance/geometry checks.Rigid transforms preserve internal distances; verify atom selections, units and tolerances. Separate execution, artifact validity, science and cost.
6. Read scientific code by componentA method-integration note with dependency/version, I/O, example, tests and source.Run a distinct input and explain why a tutorial reproduction does not establish open-ended scientific generality.

After direct function calls pass, compare the same tool through MCP and an Agent wrapper. The contract and error semantics should remain the same. A framework should not silently replace the scientific definition.

A runnable offline geometry exercise

Before configuring a model, use the deterministic exercise to inspect a complete tool contract, real function execution, artifacts and independent checks. It uses synthetic coordinates and fixed plans, not a PDB/mmCIF parser or natural-language inference. The six teaching checks cover a reference triangle, rigid-transform invariance, selection order, invalid selection, units/non-finite values, and the separation of execution from scientific acceptance.

Framework roles overlap; these are learning directions, not a one-to-one ranking or proof of superiority. Pin the actual repository revision and select examples suited to your provider, operating system and deployment policy.

Twelve learning resources and concrete exercises

L01 Hello-Agents (Datawhale)

Beginner course; the main material is Chinese, with an English README.

PrerequisiteExerciseBoundary
Python and basic LLM concepts.Wrap a local mmCIF inventory/residue-count function, return structured invalid-input errors and save parameters/logs.A general Agent tutorial; scientific validation and HPC/production permissions remain application work.

L02 AI Agents for Beginners (Microsoft)

English course with translations.

PrerequisiteExerciseBoundary
Python and the selected examples’ service prerequisites.Expose local structure inspection and comparison as two tools; record actual calls and accept results against a reference.Select examples matching your runtime/provider; this course is not a structural-computing platform.

L03 Hugging Face Agents Course

English course with translated versions.

PrerequisiteExerciseBoundary
Python, LLM basics and the course account requirements.Build a tool Agent with a stop condition and validate local geometry against reference answers.Course assessment does not replace independent scientific acceptance.

L04 OpenAI Agents SDK (Python)

Function tools, run loop, sessions and tracing.

PrerequisiteExerciseBoundary
Python functions, type annotations and basic async code.Replace examples/basic/tools.py with a structure-information function returning chain lists, counts and explicit parsing errors.Actual model calls need configured service access; pin the SDK version used for reproduction.

L05 Pydantic

Typed input/output constraints and JSON schemas.

PrerequisiteExerciseBoundary
Python classes, dictionaries and typing.Define file/model/chain selection input and structured success/error output; reject unknown fields and invalid numbers.Shape validation does not establish correct object selection, units or scientific truth.

L06 LangGraph

Explicit state, nodes, branches and checkpoints.

PrerequisiteExerciseBoundary
Functions, state dictionaries and tool-call concepts.Connect deterministic input inspection, validation and failure branches before inserting a model planner.Graph state cannot replace a job ledger or deduplicate arbitrary external effects automatically.

L07 MCP Python SDK

A common tool/resource/client/server interface.

PrerequisiteExerciseBoundary
Function I/O and client-server basics.Expose structure inspection with typed parameters, results and errors; keep the same domain contract across direct and MCP calls.Add MCP when multiple clients need the interface. Protocol connectivity is not execution isolation or scientific acceptance.

L08 Langfuse examples

Tracing, evaluation and feedback integration examples.

PrerequisiteExerciseBoundary
A runnable tool or Agent and basic request/log concepts.Record input hashes, versions, output IDs, latency and acceptance for successful and failed scientific calls.Choose examples matching language and SDK versions; traces diagnose, validators establish scientific acceptance.

L09 Temporal Python samples

Durable workflows, activities, retry, cancellation and async completion.

PrerequisiteExerciseBoundary
Python async and external-operation semantics.Split inspection into activities, simulate a retry/Worker restart and detect duplicate outputs or external jobs.Use when long jobs justify it. External reconciliation and idempotency are still required.

L10 ToolUniverse

Scientific tool discovery, parameter descriptions, invocation and composition.

PrerequisiteExerciseBoundary
Python, JSON Schema and basic MCP concepts.Describe a structure-validation operation and test missing path, wrong format and valid input with structured results.A base installation does not supply all local scientific dependencies; some remote tools need separate credentials.

L11 Biomni

Scientific environment and task-Agent separation with execution records.

PrerequisiteExerciseBoundary
Python, isolated environments and dependency management.Register local structure validation returning hash, chain inventory, parser diagnostics and provenance; test fixed inputs first.Installing the environment is not reproducing a research result; model/services and dependencies require separate setup.

L12 Paper2Agent

Wrapping research code as reusable tools with environments, tests and documentation.

PrerequisiteExerciseBoundary
Python, Git, testing and reproducible source material.Package an existing structure-metadata tutorial with I/O, dependencies, examples, expected artifacts and reference tests.Generated interfaces retain upstream data/code/environment limitations; passing a tutorial is not validation on new structures.

From the prototype to a usable task service

The first useful milestone is a natural-language request that triggers an appropriate real tool, respects a checked contract, yields traceable artifacts and reports a failure honestly. Then add persistent state, restricted execution, cumulative budget, independent acceptance, feedback and release regression. Broader tool coverage follows explicit capability admission, rather than replacing those controls.
