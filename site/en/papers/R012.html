DSPy

DSPy: Compiling Declarative Language Model Calls into State-of-the-Art Pipelines

First public: 2023-10-05 · Conference publication · ICLR 2024 · Main conference

DSPy describes language-model programs using declarative signatures and composable modules, then optimizes prompts and demonstrations against data and metrics. It optimizes programs rather than replacing an application's execution platform.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Handwritten long prompts make multi-stage systems hard to reuse and optimize. The paper tests whether program structure and data-driven compilation offer a better unit of development.

How the mechanism works

  1. Signatures state input/output fields and intent; modules compose model operations and information flow.
  2. Bootstrap useful demonstrations from teacher or current-program traces accepted by a task metric, reducing the need for complete human-labeled intermediate traces.
  3. Compare few-shot, bootstrap, search and ensemble compilation on development data, then evaluate the selected configuration on isolated test data.

Study setting and reported evidence

Mathematics and retrieval programs, including GSM8K and different base models, show improvements from compilation with interactions between program structure and optimizer choice.

Limits and interpretation

A biased or scientifically weak metric makes optimization fit the wrong target more effectively. Search can adapt to development tasks and incurs costs separate from inference.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

First isolate modules such as object extraction and tool selection, then optimize them on independently labeled examples. A convenient energy score or report-format metric must not silently replace the scientific objective.

Reproduction and implementation checks

Freeze development/test splits and validator definitions. Record candidate search cost separately from deployment cost, compare optimizer variants, and test the final program on unseen structures and task combinations.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
