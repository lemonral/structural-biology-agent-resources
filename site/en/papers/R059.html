SciToolAgent Evo

SciToolAgent-Evo: An Ontology-Aware Self-Evolving Agent for Open-World Scientific Tool Acquisition

First public: 2026-07-30 · Preprint · arXiv · 2026

SciToolAgent-Evo combines evolving memory, a tool ontology and gated exploration to acquire unknown tools. 'Unknown' is defined within a specified tool-space split, not arbitrary internet software deployment.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

A controller must decide whether existing skills suffice, whether a capability gap requires search, and whether exploration is worth its cost.

How the mechanism works

  1. Compare baseline and exploratory trajectories to extract reusable skill chains and context-specific lessons as non-parametric knowledge.
  2. Decompose gaps into tool requests, retrieve and rerank candidates using functions, inputs/outputs and ontology relationships.
  3. Use a LinUCB gate with feasibility, gap and ontology features to choose exploitation or exploration, then update relationships and experience.

Study setting and reported evidence

OpenSciToolBench has 900 questions, complemented by SciToolEval. Experiments with two backbones and repeated runs report tool-chain alignment and answer accuracy, including accumulation, transfer and gating ablations.

Limits and interpretation

The candidate graph and known/unknown split define the meaning of openness. Reference-chain alignment may miss equivalent routes and does not independently validate software environments or scientific assumptions.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Track capability gaps, candidate discovery, onboarding tests and knowledge updates separately. A promising tool still needs object-type, environment and reference-task validation before autonomous use.

Reproduction and implementation checks

Preserve the split, ontology, retrieved memories and exploration decisions. Report chain accuracy and answer accuracy separately and test valid alternatives rather than treating one reference chain as scientific truth.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Extension of the problem

R023 · SciToolAgent

SciToolAgent uses a scientific-tool knowledge graph to retrieve related tools and plan multi-step chains, followed by execution and synthesis. Graph relationships organize capability semantics rather than guarantee deployment or scientific correctness.

Compare mechanisms

R058 · OpenAgent

OpenAgent diagnoses tool-use generalization under changed queries, actions, observations and domains. Controlled environments separate failure sources rather than claiming direct compatibility with arbitrary scientific software.
