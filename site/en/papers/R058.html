R058 · Learning, memory and system optimization

OpenAgent

Can Agents Generalize to the Open World? Unveiling the Fragility of Static Training in Tool Use

First public: 2026-07-01 · Conference publication · ICML 2026 · Main conference

OpenAgent diagnoses tool-use generalization under changed queries, actions, observations and domains. Controlled environments separate failure sources rather than claiming direct compatibility with arbitrary scientific software.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

High performance in a static tool environment may reflect memorized interface conventions instead of robust adaptation to current rules.

How the mechanism works

  1. Perturb user phrasing, tool identifiers or semantics, returned formats and domains separately to distinguish renaming from genuine semantic or dependency changes.
  2. Introduce errors, empty returns, redirections and missing conditions to test adaptation and recognition of unsolvable requests.
  3. Compare SFT and GRPO on separated training/test variants, reporting errors, efficiency, task correctness and refusal.

Study setting and reported evidence

The archived setting uses 6,050 training and 880 evaluation examples with Qwen2.5-7B, keeping test change patterns out of training. Robustness depends on the type of environmental change.

Source coverage: Original guide checked against the full text. This English edition translates the archived review and does not claim a new independent reproduction.

Limits and interpretation

Controlled point-of-interest and calculation tasks simplify attribution but omit scientific files, numerical uncertainty and deployment complexity. Designed unseen variants do not exhaust an open world.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Add renamed tools, changed parameter keys, numbering systems, anomalous logs and impossible tasks to structural-agent regression tests. These diagnose failure but do not prove sandbox training solves every real-tool problem.

Reproduction and implementation checks

Freeze perturbation definitions and separate surface, semantic and domain changes. Compare training approaches at comparable budgets and evaluate appropriate refusal independently of ordinary success.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Diagnosis and response

R059 · SciToolAgent Evo

SciToolAgent-Evo combines evolving memory, a tool ontology and gated exploration to acquire unknown tools. 'Unknown' is defined within a specified tool-space split, not arbitrary internet software deployment.

Complementary benchmarks

R078 · ToolSandbox

ToolSandbox evaluates multi-turn tool use using explicit world state, simulated users, milestones and forbidden events. Its evaluation DAG allows valid ordering alternatives rather than forcing one execution workflow.
