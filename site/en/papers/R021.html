AFlow

AFlow: Automating Agentic Workflow Generation

First public: 2024-10-14 · Conference publication · ICLR 2025 · Main conference

AFlow searches reusable code-defined agent workflows with execution feedback. A search node is a complete workflow selected during development, rather than a per-question action state explored anew at deployment.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Manually designed connections among generation, review, testing and ensembles leave useful workflow structures unexplored.

How the mechanism works

  1. Represent nodes and control logic as code; combine predefined operations such as Generate, Review/Revise, Ensemble and Test while fixing other settings to constrain search.
  2. Choose parent workflows using a mixture of uniform and score-weighted selection, retaining opportunities to restart from the template.
  3. Run candidate workflows repeatedly on development examples, archive changes and score variability, stop at a budget or plateau, and freeze the selected workflow before testing.

Study setting and reported evidence

Six QA, coding and mathematics benchmarks use separate development/test data. Some workflows transfer across execution models, but not uniformly. Reported test-execution cost does not include the entire development search cost.

Limits and interpretation

Selection of development examples and repeated evaluations can bias the search. Short QA or programming feedback does not model the cost of long scientific simulations.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Start workflow search on cheap repeatable structural analyses with fixed objects, permissions and validators. Require performance on new inputs before extending to expensive computations.

Reproduction and implementation checks

Preserve parent–child edits, repeated scores, search stopping rules and all development costs. Separate model used to optimize a workflow from model used to execute it, and evaluate frozen workflows on untouched tests.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
