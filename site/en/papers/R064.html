AgentEvolver: System-Wide Self-Evolution Through Task Execution

First public: 2026-10-08 · Preprint · arXiv · 2026-10-08

AgentEvolver versions and evaluates runtime software capabilities while keeping the base model fixed. It distinguishes a capability change, adoption, actual later use and final task success as separate evidence events.

Research problem

Systems described as self-improving may confuse writing a memory, launching a subtask or changing reusable implementation, obscuring what actually improved.

How the mechanism works

  1. Separate component definitions, process instances and stored contents, archiving immutable payloads for adopted versions.
  2. Record ownership, parent calls, versions and state in a shared runtime with resource conflicts, budgets, subtask lifecycles and recoverable contexts.
  3. Compare candidates with baselines and regressions, then record retention, activation, rollback and later calls independently of final delivery acceptance.

Study setting and reported evidence

The paper reports SWE-bench Pro Public comparisons and six historical application cases. Some outcomes are partial or unsuccessful; an adopted component does not guarantee the encompassing task finished.

Limits and interpretation

Valid provenance cannot rescue a weak evaluator or unfair baseline. Later use in the same ongoing task differs from frozen-library transfer to genuinely independent tasks.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Version structural adapters, workflows and validators independently. Check both reference tasks and whether later consumers actually use the accepted version, while judging scientific delivery separately.

Reproduction and implementation checks

Preserve exact version payloads, comparison calls, adoption decisions, activation and consumption records. Add independent transfer and full cost accounting rather than equating adoption with improvement.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Compare adaptation targets

R004 · Reflexion

Reflexion compresses task feedback into verbal reflections that persist across attempts. Improvement occurs through episodic context and additional attempts, without updating the base model's weights.

Compare system construction

R036 · MetaAgent

MetaAgent generates a finite-state machine containing roles, condition validators and listeners, then merges redundant states. Explicit transitions support local revision and backtracking during multi-agent execution.
