MCP Bench

MCP-Bench: Benchmarking Tool-Using LLM Agents with Complex Real-World Tasks via MCP Servers

First public: 2025-08-28 · Conference publication · ICLR 2026 · Main conference Poster

MCP-Bench constructs coupled multi-step tasks from complementary tools on real MCP services. It separates interface and runtime checks from model judgments of task-level planning and completion.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Connecting a protocol does not resolve which tools to choose or how outputs from one service become valid inputs to another.

How the mechanism works

  1. Identify within-service and cross-service input/output dependencies to create linear, parallel or mixed task structures.
  2. Filter for usefulness and solvability, then rewrite detailed tasks as high-level user requests while retaining necessary precise values.
  3. Compute name/schema/runtime measures from traces and separately judge completion, tool choice and planning using task context and dependency references.

Study setting and reported evidence

The archived v1 connects 28 services and 250 tools and evaluates 20 models. Strong interface compliance can coexist with weaker high-level results; cross-service dependencies are especially difficult for some models.

Source coverage: Original guide checked against the full text. This English edition translates the archived review and does not claim a new independent reproduction.

Limits and interpretation

Task synthesis and judging share dependency references and may favor the original route. Online services, data and judge versions affect reproducibility.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Measure discovery, argument compliance, execution and scientific output independently. MCP communication cannot replace object, numbering, unit and method-precondition checks.

Reproduction and implementation checks

Snapshot services and judge settings, repeat judgments and inspect valid alternative routes. Preserve actual observations and distinguish service outages from planner errors and evaluator disagreement.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Complementary tests

OpenAgent diagnoses tool-use generalization under changed queries, actions, observations and domains. Controlled environments separate failure sources rather than claiming direct compatibility with arbitrary scientific software.
