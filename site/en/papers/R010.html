MetaGPT

MetaGPT: Meta Programming for A Multi-Agent Collaborative Framework

First public: 2023-08-01 · Conference publication · ICLR 2024 · Main conference

MetaGPT encodes software-team operating procedures as role responsibilities, structured artifacts and handoff rules. The central idea is disciplined coordination rather than intelligence gained merely by increasing the number of roles.

Research problem

Free-form multi-agent conversations can produce inconsistent requirements, designs and code because downstream roles lack explicit upstream contracts.

How the mechanism works

  1. Assign product, architecture and engineering responsibilities with defined triggers and deliverables.
  2. Exchange structured requirements, designs and interfaces through message mechanisms, so recipients can check what they actually consume.
  3. Use execution and checking feedback to revise generated software; documents alone are insufficient completion evidence.

Study setting and reported evidence

SoftwareDev and other software-engineering tasks compare ChatDev, feedback ablations and role combinations. The paper reports improved executability and reduced revision cost while token use increases.

Limits and interpretation

An SOP embeds assumptions about the domain. Scientific goals may change with evidence, making a fixed company-like role chain inappropriate. Extra roles and iterations require matched-budget comparisons.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Adopt checkable handoffs for task objects, candidate models and validation decisions. Split roles only when responsibilities can be isolated, and allow evidence-driven rollback, reformulation or stopping.

Reproduction and implementation checks

Fix model, tasks, role configuration and feedback budget. Measure executability, time, tokens and human revision separately, including an otherwise identical system without feedback.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

R027 · MAST

MAST derives a taxonomy of multi-agent failures from execution traces and supplies annotations and an automatic labeling workflow. It is a diagnostic resource rather than an agent that automatically repairs every failure.
