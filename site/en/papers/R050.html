BioAgent Bench

BioAgent Bench: An AI Agent Evaluation Suite for Bioinformatics

First public: 2026-01-29 · Conference publication · ICML 2026 · Main conference

BioAgent Bench evaluates bioinformatics workflows through explicit inputs, required steps and output files, adding corruption, distractor and prompt-bloating tests. Workflow completion is necessary but insufficient for scientific reliability.

Research problem

Normal-case task completion can conceal brittle input handling, unstable results or inappropriate continuation after an anomaly is detected.

How the mechanism works

  1. Specify task–artifact contracts and distinguish sample inputs from shared references; only some tasks have directly binary-verifiable results.
  2. A rubric-guided model judge inspects expected and produced tables, file paths and output directories, emphasizing workflow completion rather than exact numerical identity.
  3. Repeat runs and introduce damaged files, decoys and redundant instructions; assess anomaly detection, stopping behavior and output consistency separately.

Study setting and reported evidence

Model–harness comparisons include near-complete normal workflows in some settings. Controlled perturbations show that detecting corruption does not always stop questionable analysis, and prompt bloat can eliminate progress. Some resource-heavy tasks and perturbations have few repeats.

Limits and interpretation

Artifact-based model judging can reward apparently complete but partly wrong work. Stability is not truth, and limited trials do not establish a universal reliability rate.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Test damaged coordinates, wrong references and ambiguous mappings. Require separate workflow, data and structural-quality validators, including evidence-based stopping rather than a generated claim of completion.

Reproduction and implementation checks

Reproduce the exact harness and task rubric, distinguish binary checks from judgment, and report repeated-run distributions, perturbation coverage and resource-heavy exceptions.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
