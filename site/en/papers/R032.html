ScienceBoard

ScienceBoard: Evaluating Multimodal Autonomous Agents in Realistic Scientific Workflows

First public: 2025-05-26 · Conference publication · ICLR 2026 · Main conference Poster

ScienceBoard places agents in virtual machines running real scientific applications and checks internal software state. It combines visual interaction, commands and scientific workflows, while distinguishing task-state completion from scientific discovery.

Research problem

Screenshots or natural-language answers alone are ambiguous evidence of whether an agent changed the intended object or completed a software operation.

How the mechanism works

  1. Provide mouse/keyboard actions, system commands, application scripts and some APIs within one environment.
  2. Initialize tasks with fixed files and configurations, adding application-specific state-query adapters where needed.
  3. Score selected objects, properties and computation state with task-specific exact matches, ranges and numerical tolerances.

Study setting and reported evidence

The benchmark contains 169 tasks across six scientific domains, with model and GUI-strategy comparisons and screenshot/accessibility-tree observation variants. Completion remains difficult and varies substantially by application and observation mode.

Limits and interpretation

State adapters require application-specific engineering. Correctly setting a view or software property does not prove the scientific method or interpretation is valid; extra reasoning only partly addresses interaction bottlenecks.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Prefer recordable application scripting where possible. For necessary GUI operations, query state and confirm target objects, while validating operation completion, numerical measurement and interpretation separately.

Reproduction and implementation checks

Pin VM images, application modifications, initialization files and observation channels. Compare agents with the same available interfaces and report domain-stratified results rather than only a pooled score.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Complementary evaluation

R049 · DSGym

DSGym unifies data-science tasks, execution environments and scoring, while auditing whether questions actually require data access. It includes filtered tasks, domain workflows and execution-validated synthesis examples.

AstaBench separates scientific-agent tasks, a standard tool environment, baseline systems and cost reporting. The purpose is rigorous comparison under controlled information access and inference resources.
