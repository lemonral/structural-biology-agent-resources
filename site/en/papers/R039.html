R039 · Scientific systems and structural biology

Paper2Agent

Reimagining research papers as interactive and reliable AI agents

First public: 2025-09-08 · Journal publication · Nature · 2026-09-16

Paper2Agent turns paper-linked code, data and tutorials into callable MCP services. Environment setup, operation extraction and test-driven repair are explicit stages, with reliability evidence coming mainly from case reproduction and new queries.

Research problem

A published method is not immediately a stable tool: dependencies, entry points, resources and reference behavior must first be identified.

How the mechanism works

  1. Locate repositories and resources, configure the environment and extract meaningful method operations from tutorials and code.
  2. Execute reference examples, compare outputs or figures, repair failures and lock accepted tools and environments.
  3. Separate executable tools, static paper/code/data resources and multi-step prompts beneath a chat interaction layer.

Study setting and reported evidence

The archived v2 presents AlphaGenome, Scanpy and TISSUE, comparing generated interfaces with reference-code results and demonstrating new-input queries. This is not a uniform randomized benchmark over arbitrary papers.

Source coverage: Original guide checked against the full text. This English edition translates the archived review and does not claim a new independent reproduction.

Limits and interpretation

Code and tests produced by related agents can share blind spots. Missing data, licenses, weights or complete tutorials cannot be supplied merely by protocol wrapping.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Treat generated structural operations as candidate tools until object semantics, units, method assumptions and independent reference tasks pass. Validate tutorial reproduction and new-input generalization separately.

Reproduction and implementation checks

Keep reference code, environment versions, expected artifacts and repair histories. Add boundary inputs and independent tests before making a generated service available to autonomous planning.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

R041 · ToolUniverse

ToolUniverse unifies scientific-tool descriptions, types and calling conventions, then connects discovery, execution, composition and maintenance. It is a tool ecosystem rather than a guarantee that every backend is scientifically valid everywhere.

Environment and integration

R033 · Biomni

Biomni combines a unified biomedical computing environment with a code-based agent that retrieves relevant resources and executes adaptive analyses. Resource breadth is a design feature, not proof of autonomy on every structural problem.
