AgentBench

AgentBench: Evaluating LLMs as Agents

First public: Not recorded in source index · Conference publication · ICLR 2024

AgentBench evaluates sequential decisions and environmental feedback across eight interactive environments. It exposes the gap between answering static questions and completing extended action trajectories.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

A strong language benchmark score does not show whether a model can maintain state, follow instructions and reach a terminal goal through interaction.

How the mechanism works

  1. Model interaction with partially observed states, actions, transitions, observations and rewards, evaluating full trajectories.
  2. Keep environment-specific tasks and termination criteria, then aggregate only with explicit scales and weights.
  3. Separate environment servers and model clients, adapting chat or completion interfaces with fixed prompts and decoding.

Study setting and reported evidence

The paper compares listed API and open models under its historical versions and interfaces. Environment scores show substantial long-horizon and instruction-following failures; this is not a current-model ranking.

Source coverage: Original guide checked against the full text. This English edition translates the archived review and does not claim a new independent reproduction.

Limits and interpretation

An aggregate score compresses different code, game and web failure mechanisms. Fixed decoding controls some variation but does not establish robustness across prompts, disturbances or repeats.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Evaluate structural workflows from file reading through tools, execution and interpretation rather than only the final report. Add geometry and experimental-data criteria beyond the generic interaction scaffold.

Reproduction and implementation checks

Pin model versions, action parsers, adapters, prompts and environment initialization. Report per-environment outcomes, weighting and repeated-run stability alongside any total.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Evaluation dimensions

R077 · Tau Bench

Tau-bench evaluates tools, user dialogue and domain policies in a mutable environment, checking final database state. Its pass^k measures success on every repeated run, unlike pass@k's at-least-one success.

State dependencies

R078 · ToolSandbox

ToolSandbox evaluates multi-turn tool use using explicit world state, simulated users, milestones and forbidden events. Its evaluation DAG allows valid ordering alternatives rather than forcing one execution workflow.
