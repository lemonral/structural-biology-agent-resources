ToolSandbox

ToolSandbox: A Stateful, Conversational, Interactive Evaluation Benchmark for LLM Tool Use Capabilities

First public: Not recorded in source index · See publication record · See publication record

ToolSandbox evaluates multi-turn tool use using explicit world state, simulated users, milestones and forbidden events. Its evaluation DAG allows valid ordering alternatives rather than forcing one execution workflow.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Stateful tasks require satisfying prerequisites, asking for missing information and avoiding prohibited actions, beyond formatting a legal call.

How the mechanism works

  1. Execution Context holds world state; tools read or change it and return errors when prerequisites are absent.
  2. Constrain the simulated user's knowledge and behavior with boundaries and examples, then audit simulation errors independently.
  3. Match trajectories to milestones under DAG ordering; forbidden events zero the similarity score, while interaction count is measured separately.

Study setting and reported evidence

Models are compared by state dependency, normalization, insufficient-information and tool-augmentation categories. Average milestone similarity can hide severe information-gathering weaknesses; human audits find residual simulator errors even after prompt improvements.

Limits and interpretation

Milestone design is costly and can over-specify a reference route. The paper does not cover future interruptions of background jobs or establish mandatory authentication/confirmation guarantees.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Specify prerequisites, key artifacts and forbidden events for structural evaluation while allowing scientifically equivalent paths. HPC recovery, background state and approvals still need dedicated implementation.

Reproduction and implementation checks

Report milestone similarity rather than relabeling it complete-task success. Preserve DAG definitions, forbidden conditions, user-simulation audits and call counts, and distinguish simulator failures from agent mistakes.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
