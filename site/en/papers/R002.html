R002 · Reasoning, action and orchestration

ReAct

ReAct: Synergizing Reasoning and Acting in Language Models

First public: 2022-10-06 · Conference publication · ICLR 2023 · Main conference

ReAct interleaves language-based decisions with external actions and observations. New observations can change the next step, but this loop alone does not supply permissions, durable recovery or scientific acceptance rules.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Pure language reasoning can continue from false facts; action-only policies can lose long-term intent. Interactive tasks require decisions that remain responsive to external information.

How the mechanism works

  1. Maintain task-relevant subgoals, progress and information gaps in the decision context; these descriptions do not themselves change the environment.
  2. Send actions through a defined executor and append actual tool or environment returns to the trajectory.
  3. Repeat until a terminal action or budget limit. The paper also studies combinations with CoT and self-consistency rather than claiming one format is universally best.

Study setting and reported evidence

HotpotQA and FEVER use Wikipedia access; ALFWorld and WebShop provide restricted action spaces. Comparisons include standard prompting, CoT and action-only policies. ReAct beats CoT on FEVER in the original setting but is slightly below it on HotpotQA.

Limits and interpretation

A real retrieval result can still concern the wrong object. Serial histories increase cost, and repeated actions can form loops. The original experiments do not validate hours-long scientific job recovery.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Keep feedback nodes where identity, tool failure or candidate quality changes the route. Bind scientific judgments to actual artifacts and validation records; fixed format conversion need not invoke the model after every step.

Reproduction and implementation checks

Freeze action syntax, examples and maximum steps. Save proposed actions separately from executed parameters and observations. Compare strategies under matched budgets and classify retrieval, reasoning and execution failures.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Compare mechanisms

R007 · ReWOO

ReWOO separates planning, tool execution and synthesis. Evidence variables express dependencies before actual tool returns fill them, reducing repeated prompt construction rather than eliminating observation use.

Complementary perspective

R015 · LLMCompiler

LLMCompiler plans function calls as a dependency graph and executes ready tasks in parallel. The benefit targets unnecessary serialization and repeated planning, while preserving actual data dependencies.
