R030 · Learning, memory and system optimization

ToolRL

ToolRL: Reward is All Tool Learning Needs

First public: 2025-04-16 · Conference publication · NeurIPS 2025 · Main Track

ToolRL studies the type, granularity and scale of tool-learning rewards, separating output format from call correctness. Fine-grained supervision uses reference calls and does not imply one uniquely correct scientific workflow.

Research problem

A single completion reward gives little information about whether a tool name, parameter name or parameter value caused failure.

How the mechanism works

  1. Represent reasoning, tool requests and observations with explicit boundaries; parse and execute actual calls.
  2. Match predicted and reference tool names, parameter names and values, with stated normalization and reward scales.
  3. Train with PPO or GRPO and test reward ablations and renamed tools or arguments to investigate generalization.

Study setting and reported evidence

Mixed tool datasets train models evaluated on BFCL, API-Bank and related tasks, including naming perturbations. Reported improvements depend on the provided reference calls and tested environments.

Limits and interpretation

Field matching to one reference path may penalize valid alternatives. Correct syntax or labels do not establish structural identity, units, method applicability or acceptable side effects.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Log format, object selection, argument legality and scientific acceptance separately. Permit equivalent tools and valid analysis routes; do not judge structural analysis solely by an exact call-string match.

Reproduction and implementation checks

Publish reward formulas, scales, matching rules and reference-path assumptions. Compare outcome-only and granular rewards under matching training budgets, then independently evaluate valid alternative workflows.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Compare mechanisms

R003 · Toolformer

Toolformer constructs API-augmented training text using a few demonstrations, actual API execution and a language-model loss filter. Tool-use behavior is learned through fine-tuning rather than supplied only in an inference-time tool prompt.

R029 · ReTool

ReTool combines natural-language reasoning and live code execution during training, using a code-enhanced cold start and outcome reinforcement learning. The objective is to learn when and how to use feedback, beyond granting interpreter access.
