R040 · Learning, memory and system optimization

CodeGym

Generalizable End-to-End Tool-Use RL with Synthetic CodeGym

First public: 2025-09-22 · Conference publication · ICLR 2026 · Main conference

CodeGym converts coding problems into interactive environments with hidden state and callable functions, then trains multi-turn tool use with verifiable rewards. Its contribution is environment synthesis and transfer, not a deployed scientific agent.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Training general interaction requires many solvable environments with reliable feedback, beyond static question–answer examples.

How the mechanism works

  1. Extract state, atomic operations, observations and terminal rewards from code problems, using test inputs for reset and reference solutions for expected outputs.
  2. Validate generated environments across inputs and accept them only when a tool-using candidate solves all tests.
  3. Serve CPU environments to GPU rollouts; trial calls in snapshot subprocesses and commit successful state changes while returning errors on failure.

Study setting and reported evidence

Evaluation includes held-out CodeGym tasks, tau-bench, tau-squared Bench, ALFWorld and reasoning benchmarks. Several settings improve transfer; some larger-model results use a single seed, limiting stability evidence.

Limits and interpretation

A simulator snapshot cannot undo an already submitted GPU job or remote write. A code-problem terminal answer also does not validate an open scientific interpretation.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Start training on side-effect-free file and geometry tasks, independently validate environments and then test transfer to real tools. External jobs need submission, cancellation and recovery ledgers.

Reproduction and implementation checks

Record generated-environment rejection criteria, reference solutions, resets and repeated-call limits. Separate environment defects from policy failures and report seeds and held-out distributions.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.

Compare data generation

R045 · GOAT

GOAT first constructs and executes dependent API chains, then generates natural-language goals describing those chains. Synthetic supervision begins from actual calls rather than from unconstrained question generation.

Generalization evaluation

R058 · OpenAgent

OpenAgent diagnoses tool-use generalization under changed queries, actions, observations and domains. Controlled environments separate failure sources rather than claiming direct compatibility with arbitrary scientific software.
