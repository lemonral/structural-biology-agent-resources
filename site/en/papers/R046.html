AstaBench

AstaBench: Rigorous Benchmarking of AI Agents with a Scientific Research Suite

First public: 2025-10-24 · Conference publication · ICLR 2026 · Main conference Oral

AstaBench separates scientific-agent tasks, a standard tool environment, baseline systems and cost reporting. The purpose is rigorous comparison under controlled information access and inference resources.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Scientific-agent comparisons mix different tools, evidence access, model costs and task coverage, making a single leaderboard score difficult to interpret.

How the mechanism works

  1. Separate literature, code, analysis and end-to-end tasks, using program checks where possible and explicit rubrics for long outputs.
  2. Constrain literature by dates or paper identifiers and run code in stateful notebooks, with a defined tool subset per task.
  3. Normalize model-use costs to a common price snapshot and report openness, custom-tool access and accuracy–cost tradeoffs.

Study setting and reported evidence

The archived v2 covers 22 architecture types. Some specialist systems worsen with model upgrades. Partial research-step completion can be high while complete-project success remains very low, so the two metrics must remain separate.

Source coverage: Original guide checked against the full text. This English edition translates the archived review and does not claim a new independent reproduction.

Limits and interpretation

GPU exclusions and notebook timeouts limit coverage of long structural simulations. Normalized inference cost omits some engineering, queuing and human-review costs; rubric judgments need independent spot checks.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Compare structural agents with the same reference files, database snapshots, tools and budgets. Report modeling, execution, interpretation and full-workflow completion alongside averages.

Reproduction and implementation checks

Track modified benchmark variants rather than equating them with original leaderboards. Retain evidence cutoffs, price tables, missing coverage and project-level all-steps acceptance criteria.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
