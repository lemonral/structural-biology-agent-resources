R015 · Reasoning, action and orchestration

LLMCompiler

An LLM Compiler for Parallel Function Calling

First public: 2023-12-07 · Conference publication · ICML 2024 · Main conference

LLMCompiler plans function calls as a dependency graph and executes ready tasks in parallel. The benefit targets unnecessary serialization and repeated planning, while preserving actual data dependencies.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

Sequential tool loops make independent calls wait for one another and may repeat planning or stop prematurely.

How the mechanism works

  1. A function-calling planner emits concrete operations and references to predecessor results.
  2. A task-fetching unit identifies nodes whose dependencies are satisfied instead of asking the model to approve each independent call.
  3. Executors return results to downstream tasks; synthesis can answer or trigger replanning when necessary.

Study setting and reported evidence

HotpotQA-related settings, recommendations and ParallelQA compare tuned ReAct and parallel-calling baselines. The paper measures accuracy, end-to-end latency, tokens and cost, with benefits varying by calling pattern.

Limits and interpretation

Hidden dependencies, invalid references and stateful APIs can invalidate parallel execution. Function scheduling does not itself supply cluster queuing, multi-day recovery or licensing management.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Parallelize independent structural checks while retaining coordinate normalization and mapping as genuine prerequisites. Attach types, resource bounds and acceptance contracts to the graph so concurrency cannot change scientific comparison conditions.

Reproduction and implementation checks

Match model, tools, quotas and tasks. Measure planning and execution time separately and inspect repeated calls, early stopping, graph errors and downstream result binding.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
