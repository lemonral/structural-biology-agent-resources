Tau Bench

τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains

First public: Not recorded in source index · See publication record · See publication record

Tau-bench evaluates tools, user dialogue and domain policies in a mutable environment, checking final database state. Its pass^k measures success on every repeated run, unlike pass@k's at-least-one success.

Research problemMechanismEvidenceLimitsImplementationReproductionReading connectionsSources

Research problem

An assistant may occasionally finish a request while inconsistently collecting information, choosing arguments or respecting policies across repeats.

How the mechanism works

  1. Use partially observed API access and a simulated user with private goals and incomplete information.
  2. Compare the final database with a labeled target state and check required response information, permitting varied valid read/dialogue routes.
  3. Estimate repeated reliability per task and report pass^k separately from ordinary success and best-of-many measures.

Study setting and reported evidence

Retail and airline experiments compare models and interaction formats; reliability falls substantially as the required number of successful repeats grows. Limited failure audits reveal argument errors, policy mistakes and missed compound requests.

Limits and interpretation

Correct terminal state may still follow an unauthorized action or omitted confirmation. Simulated users can introduce errors, and task construction/calibration affects the distribution.

Implications for a structural-biology agent

Editorial design inference, distinct from the paper's measured result.

Test gradually supplied information and researcher corrections while repeatedly checking object identity. For key modifications, verify approval and execution order as well as the final structural file.

Reproduction and implementation checks

Preserve domain aggregation weights, user model, policy enforcement and all repeats. Audit process compliance separately from reward=1 and do not confuse pass^k with pass@k.

Reading connections

Use the paired mechanisms to locate what changes between systems: information access, control, memory, training, execution or acceptance.
