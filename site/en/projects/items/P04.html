DeerFlow

Study end-to-end delivery through files, memory, skills and sandbox execution.

Complete agent system with skills, subagents and execution environments

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

The reviewed DeerFlow 2.0 rewrites the earlier Deep Research system as a general harness. Its workbench, files, skills, subagents and environments make it useful for studying complete task delivery.

Best fit
Learning how a task workbench, delegation, file environments and artifact delivery fit together.
Boundary
A general execution system does not define structural objects, scientific software environments or quality acceptance.
Relation to other systems
The reviewed system uses LangGraph and LangChain; compare its preconfigured capabilities with Deep Agents.

2. Mechanism at a glance

  1. Receive a task and context
  2. Plan and delegate subtasks
  3. Use skills, tools and environments
  4. Organize files and deliver results

Components and responsibilities

ComponentResponsibility
Lead agent assemblyThe assembly entry point selects models, tools, middleware and run options. Demonstrations do not establish which features every configuration enables.
Subtasks, skills and contextSubagents handle subproblems, skills provide reusable operating knowledge, and files/memory hold material. Specify deliverables and budgets at handoff.
Environments and application servicesEnvironments, gateway and frontend make execution interactive. Task state, session streams and actual execution results have distinct lifecycles.

3. Follow a real run

  1. Submit goals, files and context from the workbench.
  2. The lead agent selects tools, skills or subtasks.
  3. Return environment observations and files while events update the UI.
  4. Organize deliverables and apply domain verification to scientific conclusions.

State and recovery

Separate sessions, runs, subtasks, workspaces and artifacts. An ended display stream may not be the final backend state. Reconcile persistent records and the environment when resuming.

Deployment and dependencies

Combine frontend, backend, model configuration and environments according to the chosen release. Match documents, plugins and options to the 2.0 rather than 1.x codebase.

4. Tradeoffs and scientific use

Integrated capabilities reduce product assembly work but add default behavior. Keep scientific actions and quality rules in independently controlled tools.

Structural-biology adaptation

Adapt workbench interaction, file workspaces and artifact presentation while exposing scientific actions as controlled tools.

Practice task

Expose only structure inspection and report organization. Trace main tasks, subtasks and files, then inject a subtask failure and inspect its presentation.

5. Reading path

README version notes and core capabilities, then backend, tool and run-state entry points.

Start with lead_agent assembly, then gateway and environment interfaces. Version boundaries and real run terminal states matter more than demo feature lists.

Version and evidence boundary

DeerFlow 2.0 is a rewritten harness. The older Deep Research implementation lives on a separate branch; do not mix them.
