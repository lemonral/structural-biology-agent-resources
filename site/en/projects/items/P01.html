Dify

Connect visual orchestration, models, knowledge, tools and application APIs.

Visual LLM application and workflow platform

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Dify is an application platform connecting visual workflows, agents, knowledge, models and APIs. Trace canvas definitions into actual backend execution instead of focusing only on dragging nodes.

Best fit
Learning how a complete LLM application connects UI, workflows, knowledge and services.
Boundary
Visual orchestration does not supply scientific input semantics, resource scheduling or acceptance criteria.
Relation to other systems
Compare visual orchestration with Flowise and control granularity with code frameworks such as LangChain.

2. Mechanism at a glance

  1. Configure models and knowledge
  2. Build a workflow or agent
  3. Connect external tools
  4. Publish an interface and API

Components and responsibilities

ComponentResponsibility
Application and flow definitionsThe UI edits applications, nodes and connections; the backend turns configuration into runs. Identify the executable operation and parameters behind each canvas node.
Workflow and tool executionModels, retrieval and external tools return different outputs. Surface tool failure, node failure and generated-answer failure separately.
Knowledge, models and servicesModel management, retrieval, plugins and tools supply external capabilities. Their boundaries differ from task state, logs and artifact storage.

3. Follow a real run

  1. Configure inputs, models and tools in an application or workflow.
  2. Accept a user request through the application API.
  3. Advance backend nodes, record execution events and collect external observations.
  4. Return results through the UI/API while the scientific backend checks objects, files and quality.

State and recovery

Version applications, run state, knowledge indexes and user files independently. Results from edited flows and older configurations are different experimental conditions.

Deployment and dependencies

Deployment typically includes Web, API, executor and storage services, according to its deployment files. Configure model services, plugins, scientific APIs and artifact storage separately.

4. Tradeoffs and scientific use

Low-code tools quickly provide a usable entry point. Complex scientific state is easier to verify behind stable backend APIs than inside node text fields.

Structural-biology adaptation

Provide file input, task interaction and result presentation for an existing structural-analysis API, with computation implemented separately.

Practice task

Build an application that only calls a structure-inspection API. Upload a file, display real task status and artifact links, and make failures explicit.
