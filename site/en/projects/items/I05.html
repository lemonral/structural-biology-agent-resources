A2A Protocol

Delegate tasks to remote agents through explicit capabilities, states and artifacts.

Interoperable task exchange between agent applications

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

A2A standardizes tasks and results between agent applications, especially black-box remote services. It differs from tool-oriented MCP and does not prescribe internal decision mechanisms.

Best fit
Treating remote agents as black-box services with structured task and result exchange.
Boundary
The protocol does not define internal reasoning or establish trusted scientific behavior. A deterministic function often needs only a tool interface.
Relation to other systems
A2A targets agent-task interoperability, while MCP targets tool-service interaction; the responsibilities differ.

2. Mechanism at a glance

  1. Discover capabilities
  2. Submit and track tasks
  3. Exchange messages and artifacts

Components and responsibilities

ComponentResponsibility
Capability discoveryDescriptions advertise supported tasks and interfaces. Match them to deployed versions and actual availability.
Tasks and statesManage submission, progress, input requests and completion. Associate reported status with real execution rather than natural-language claims alone.
Messages and artifactsMessages carry interaction and artifacts carry deliverables. Callers still verify files, provenance, object identity and acceptance criteria.

3. Follow a real run

  1. Discover capabilities and confirm task scope.
  2. Submit inputs and explicit output requirements.
  3. Handle status updates or requests for more input.
  4. Collect and independently accept artifacts without assuming the remote implementation.

State and recovery

Correlate local tasks, remote Task IDs, messages and artifacts. Protocol compatibility does not imply equivalent costs, states or scientific semantics.

Deployment and dependencies

Provide matching protocol versions, client/server implementations and network endpoints. Separate protocol material from the full application backend.

4. Tradeoffs and scientific use

Reduces coupling in remote delegation but adds capability and status trust questions. Direct tool calls are often simpler for one deterministic function.

Structural-biology adaptation

Specify a remote structure-inspection task with file identity, acceptance rules, waiting states and artifacts.

Practice task

Write a remote inspection contract covering files, criteria, waiting and deliverables, and explain why plain chat messages would omit important execution semantics.

5. Reading path

Protocol lifecycle and data structures, then SDK examples and comparison with MCP.

Compare A2A task handoff and MCP tool calls through their lifecycles and data structures before studying SDK examples.

Version and evidence boundary

Read specification, SDK and application backend separately. A protocol repository is not a complete agent framework.
