Microsoft Agent Framework

Connect model agents and stateful workflows through consistent development interfaces.

Cross-language agents and collaborative graph workflows

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Microsoft Agent Framework combines agents and collaborative graph workflows in a cross-language development system. Understand current interfaces alongside migration from AutoGen and Semantic Kernel.

Best fit
Applications requiring Python/.NET, explicit collaboration patterns, durable state or Microsoft-service integration.
Boundary
Checkpoints do not automatically make external computations exactly-once. Cluster job state and scientific quality still need verification.
Relation to other systems
Official migration material links AutoGen and Semantic Kernel to the newer framework. Read historical papers, projects and current APIs separately.

2. Mechanism at a glance

  1. Configure models and tools
  2. Construct agents and workflows
  3. Checkpoint and hand off
  4. Trace and recover execution

Components and responsibilities

ComponentResponsibility
Agents and model clientsClients connect models and tools with language- and backend-specific configuration. Azure examples do not imply Azure-only execution.
Function tools and middlewareTools provide application actions and middleware handles requests, responses and errors. Separate interface behavior from scientific validation.
Workflows and executorsSequential, concurrent, handoff and team relationships require explicit executor I/O and state, beyond role prompts.
Checkpoints and observabilityCheckpoints, streamed events and traces support run management. The application still integrates external job submission, reconciliation and artifact acceptance.

3. Follow a real run

  1. Create model clients, agents and permitted tools.
  2. Run an agent directly or place it in a workflow executor.
  3. Advance execution, handoffs or human input through events and state.
  4. Collect artifacts, reconcile external facts and report supported conclusions.

State and recovery

Separate framework state, client sessions, traces and external business objects. Recovery uses saved material and does not prove whether a remote job ran or completed correctly.

Deployment and dependencies

Choose language bindings and configure model and hosting backends independently. Do not mix experimental modules, stable packages and older project APIs.

4. Tradeoffs and scientific use

Cross-language integration and explicit collaboration patterns are strengths. The wider service/runtime stack introduces more client, configuration and lifecycle concepts.

Structural-biology adaptation

Represent analysis, job-status and verification nodes while storing task, artifact and review state.

Practice task

Complete a task with a local tool, then compare sequential and concurrent workflows. Record actual tool start/end events and validation, and check for repeated external actions after resumption.

Read _agents and _tools, then workflow executors and checkpoints. Compare old concepts through migration guides rather than mechanically renaming packages.

Version and evidence boundary
