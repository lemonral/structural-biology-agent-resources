Google ADK

Put agents, tools and stateful workflows into a testable runtime.

Code-first agent, workflow and task-delegation framework

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Google ADK provides code-first agents, workflows, delegation and development runtime components. Its Google integrations do not imply a single supported model or deployment setting.

Best fit
Modular agent systems, branching state or Google-service integration while retaining model choice.
Boundary
The runtime does not supply structural-computation environments, HPC capacity or independent domain acceptance.
Relation to other systems
A code-first alternative to other agent frameworks. Its stated model and deployment flexibility is broader than Gemini alone.

2. Mechanism at a glance

  1. Define agents and tools
  2. Organize tasks and workflows
  3. Maintain run state
  4. Execute and collect results

Components and responsibilities

ComponentResponsibility
Agents and toolsInstructions, model configuration and permitted tools define an agent. Test model decision capability separately from real tool execution.
Runner and sessionsThe runner connects agents, sessions and events. Conversation identity does not replace external task or job identity.
Workflow runtimeSequential steps, routing, loops, parallelism and recovery express control. Inspect actual state and retry configuration instead of relying on a workflow label.
Task delegationDelegated tasks need defined inputs, acceptance, cancellation and completion semantics rather than only a broad natural-language goal.

3. Follow a real run

  1. Create agents, sessions and task context.
  2. Advance events and model calls through the runner, selecting tools or delegated tasks.
  3. Use workflow state to coordinate subsequent nodes and collect results.
  4. Check scientific results and provenance after collecting events and artifacts.

State and recovery

Link session messages, run events, workflow state and external jobs without conflating them. Long tasks need stable references; session records need not contain all scientific evidence.

Deployment and dependencies

Local development, containers and managed environments are distinct forms. Pin ADK and model adapters; do not mix 2.0 runtime examples with older tutorial APIs.

4. Tradeoffs and scientific use

Useful for modular agents and workflows, especially with Google services. Developers must understand framework run objects and local/cloud configuration differences.

Structural-biology adaptation

Organize file inspection, computation calls and deliverables with explicit run state and structural selections.

Practice task

Implement inspection, computation and reporting nodes. Test missing input and a tool failure, checking that the event chain preserves both errors.

5. Reading path

The basic README agent, followed by Workflow Runtime, Task API and official recipes.

Start at llm_agent and Runner, then sessions and workflows. Identify when events are emitted, who owns state and how completion is declared.

Version and evidence boundary

The source README describes ADK 2.0. Verify the version of older workflow examples before combining APIs.
