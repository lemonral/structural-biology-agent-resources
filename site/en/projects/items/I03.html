Langfuse Python SDK

Trace model, tool and application runs and connect them to datasets and scores.

Observability and evaluation SDK

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Langfuse makes model, tool and application behavior observable and links runs to datasets and evaluation. Scientific validity still requires independent domain criteria.

Best fit
Locating failures and comparing runs while preserving separate scientific acceptance criteria.
Boundary
Tracing does not correct root causes. Evaluation focused on prose or format can still reward scientifically incorrect outputs.
Relation to other systems
Observability is not a scheduler or sole source of truth. Keep critical execution and artifact facts in independent records.

2. Mechanism at a glance

  1. Create traces and observations
  2. Collect and export events
  3. Associate datasets and scores

Components and responsibilities

ComponentResponsibility
Traces and observationsGroup related model, tool and other steps. Stable task IDs and artifact references link traces back to actual analyses.
Clients and exportSDKs collect and send configured events. Loss, delay or sampling can make traces incomplete, so preserve critical execution evidence independently.
Datasets and scoresAssociate inputs, outputs and evaluation. Separate model ratings, human judgments and numerical references rather than hiding them in one success score.

3. Follow a real run

  1. Assign a stable task identity and trace.
  2. Record model calls, tool parameters, results and exceptions.
  3. Attach artifacts and validation results to observations.
  4. Compare versions by error category, cost and actual acceptance.

State and recovery

A trace is an observation record, not the scheduler or unique fact store. File digests, exit status and scientific checks should remain available in independent execution records.

Deployment and dependencies

Configure SDK, observability backend and export behavior separately. Self-hosting, sampling and integrations depend on deployment.

4. Tradeoffs and scientific use

Helps diagnose and compare behavior without fixing failures automatically. Scientific errors can receive high scores under poorly designed evaluators.

Structural-biology adaptation

Trace successful and failed structure tasks and score independent numerical checks separately from model-based review.

Practice task

Trace one success and one failure and locate the responsible step. Score independent numerical verification separately from model review.
