Deep Agents

Reuse common agent capabilities while focusing on domain tools.

Agent harness with files, context management and subagents

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Deep Agents packages common support capabilities in a higher-level harness. Planning, file context and subagents are composable capabilities, not mandatory sequential stages of every task.

Best fit
Complex-task prototypes requiring file operations, delegated subtasks and long-context management.
Boundary
It is not a scientific tool collection. File, shell and subagent access do not establish calculation correctness.
Relation to other systems
Built above LangChain create_agent and the LangGraph runtime, with file and subagent capabilities preconfigured.

2. Mechanism at a glance

  1. Plan and track tasks
  2. Use files for context
  3. Delegate to subagents
  4. Execute tools and return observations

Components and responsibilities

ComponentResponsibility
Agent constructorCombines the base agent with middleware, models, tools, backends and subagents. Inspect the constructor to determine what an instance actually enables.
Files and contextFilesystem middleware exposes material, notes and intermediate content. Backends determine storage; readable files are not automatically accepted scientific artifacts.
Subagent delegationMiddleware organizes subtasks and returns. Specify input, budget and deliverables, and do not treat role dialogue as independent verification.
Backend protocolBackends govern file and execution capabilities. A uniform interface does not imply equivalent isolation, persistence or execution semantics.

3. Follow a real run

  1. Read the goal and available capabilities, then choose direct handling or a task plan.
  2. Read files for additional material or delegate isolated subproblems.
  3. Run scientific tools through a controlled backend and return observations with file references.
  4. Integrate deliverables, then check file identity, quality and interpretation in the application.

State and recovery

Context files, long-term storage, subagent workspaces and scientific outputs have different lifecycles. Separate model-authored notes from tool-produced evidence.

Deployment and dependencies

SDK, CLI and hosted service are different deployment forms. Fix backend, model and workspace rules before adding sandbox execution; hosted-service behavior cannot be assumed for a local file backend.

4. Tradeoffs and scientific use

Preconfigured capabilities reduce setup work but add default context-management behavior. Diagnose planning, file selection, subagent handoff and computation errors separately.

Structural-biology adaptation

Delegate manual reading, plan preparation and reporting, while routing structural computations through controlled tools and independent verification.

Practice task

Restrict a subagent to software-manual research and the main agent to verified tools. Require every report claim to link to a real artifact rather than a subagent completion statement.

5. Reading path

SDK Quickstart, then Backends, Subagents and Context engineering.

Follow the constructor, filesystem/subagent middleware and backend protocol. Check capability installation, storage destinations and actual subtask return types.

Version and evidence boundary

Distinguish the SDK from hosted offerings. Enabled behavior depends on configuration; structural-biology use is a proposed adaptation.
