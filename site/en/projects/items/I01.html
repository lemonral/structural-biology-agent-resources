MCP Python SDK

Standardize discovery, invocation and resource access between agent applications and tool services.

Tool protocol and client/server SDK

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

MCP standardizes interaction with tool services. It solves protocol discovery, calls and resource access; application and domain systems still decide actions, schedule calculations and verify results.

Best fit
Exposing tool services to multiple agent clients through a common protocol.
Boundary
MCP does not define model decisions, cluster scheduling or scientific acceptance. Small in-process tool sets may be simpler as direct functions.
Relation to other systems
Protocol sessions, tool calls and external jobs have separate identities. Asynchronous science needs submit, query and collection operations.

2. Mechanism at a glance

  1. Declare server capabilities
  2. Connect clients and transports
  3. Return structured observations

Components and responsibilities

ComponentResponsibility
Servers and capabilitiesExpose tools, resources or prompts with I/O descriptions. Capability declarations must match actual software environments and supported inputs.
Clients and transportConnect, discover and invoke services. Distinguish protocol/connection errors from business-tool errors and scientific findings.
Structured returnsReturn content and status to callers. Parseable output does not establish valid objects or numbers; retain verification evidence at both boundaries.

3. Follow a real run

  1. Connect a client to an identified server and discover capabilities.
  2. Select a tool by task, type and conditions, then send parameters.
  3. Execute the real operation and return observations or errors.
  4. Bind the response to task/artifact identities and run scientific checks.

State and recovery

Sessions, calls and jobs are separate states. For asynchronous tools, design explicit submission, status and artifact collection rather than inferring completion from conversation text.

Deployment and dependencies

Check stdio/HTTP transport settings against the SDK and protocol version. The source review warns against combining older FastMCP examples with newer interfaces.

4. Tradeoffs and scientific use

A common protocol lowers cross-client integration cost but does not supply scientific schemas or resource management. Avoid extra deployment when direct functions suffice.

Structural-biology adaptation

Invoke the same inspection function directly and via MCP, comparing parameters, error types and results.

Practice task

Compare direct and MCP invocation of one inspection function, preserving arguments and expected exceptions, and confirm equivalent results.

5. Reading path

Official server/client examples, then tool schemas, transports and error handling.

Read server/client examples, schemas, transports and failures. Write the protocol contract separately from the scientific contract.

Version and evidence boundary

Protocol/SDK snapshots are infrastructure material rather than a complete agent framework.
