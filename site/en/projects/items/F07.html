PydanticAI

Connect tools, injected context and typed outputs within an agent loop.

Typed Python AI SDK with dependency and output contracts

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

PydanticAI connects models, tools, dependencies and outputs through a typed loop. Its value is placing contracts in inspectable code, beyond formatting the final answer.

Best fit
Python agents that need explicit interface types, structured outputs and controlled application dependencies.
Boundary
Type validity does not establish correct biological objects, physical assumptions or numerical results.
Relation to other systems
PydanticAI is an agent SDK. Pydantic provides related data constraints; they solve different problems.

2. Mechanism at a glance

  1. Define dependencies and output types
  2. Register function tools
  3. Run model/tool interactions
  4. Validate and return results

Components and responsibilities

ComponentResponsibility
Agent and run graphDefine the model, tools and output contract. Distinguish final results from tool observations while following model and tool nodes.
Dependency contextPass databases, services and business objects to tools without putting every resource in the prompt. Manage resource lifetimes separately from conversation state.
Tools and output typesTypes and validators constrain parameters and final outputs. Parsing failures can trigger handling, but these checks do not establish scientific semantics.
Graph, Evals and related componentsControl, evaluation, persistence and harness functions occupy separate layers. Selecting one does not supply a complete production system.

3. Follow a real run

  1. Define task inputs, dependency context and acceptable output types.
  2. Validate parameters before running a model-selected function.
  3. Return structured observations or recognizable errors to the loop.
  4. Type-check the final output, then perform artifact and scientific acceptance checks.

State and recovery

Separate type definitions, run messages, injected dependencies and scientific data. Serializing an object does not restore external connections. Preserve file and version references alongside model summaries.

Deployment and dependencies

Use the Python SDK in an application process and add model services, databases or durable backends as required. Pin Pydantic versions, model capabilities and optional components.

4. Tradeoffs and scientific use

Clear contracts aid tests and refactoring, but overly broad types can hide semantic mistakes. Compare explicit graph control for complex branches and avoid unnecessary components for simple agents.

Structural-biology adaptation

Type structure-inspection inputs, dependency context and results, and connect independent domain validation functions.

Practice task

Represent invalid input, computation failure and failed quality acceptance with distinct result types. Confirm that callers cannot mistake any of them for successful analysis.

5. Reading path

A minimal README agent, then Agent, Tools, Dependencies and Output.

Trace the run graph to tool definitions and output handling. Separate errors detected by parsers from those requiring domain functions and independent criteria.

Version and evidence boundary

The source project also includes harness capabilities. Check Evals, Graph and other components separately.
