LlamaIndex

Turn research material into retrievable context and expose queries as tools.

Data-oriented RAG, agent and workflow toolkit

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

LlamaIndex covers data ingestion, indexing, retrieval and agent-facing queries. Treating retrieval as a tool connects a literature system to a computational agent without conflating the two.

Best fit
Retrieval over papers, tool manuals and research notes, or agents that depend on data context.
Boundary
Document retrieval cannot replace coordinate calculations, and indexing does not establish scientific correctness.
Relation to other systems
Independent of the LangChain stack. Retrieval can be exposed to another agent as a tool.

2. Mechanism at a glance

  1. Ingest and process data
  2. Build indexes and retrieval
  3. Expose queries as tools
  4. Compose agents and workflows

Components and responsibilities

ComponentResponsibility
Documents and nodesOrganize data into retrievable units with provenance, location and metadata. Chunking determines what context reaches the model.
Indexes and retrieversIndexes organize retrieval; retrievers select candidates. Similarity, reranking and filters affect coverage and do not by themselves establish sufficient evidence.
Queries and toolsA query pipeline may return raw evidence, an aggregated summary or a generated answer. Preserve this distinction when exposing it as an agent tool.
Agents and workflowsAgents select data or computation tools, while workflows organize events and steps. Scientific coordinate semantics and acceptance criteria remain application-defined.

3. Follow a real run

  1. Parse papers or manuals, retain provenance and versions, and build an index.
  2. A user query or agent triggers retrieval.
  3. Retrieved passages and citations enter generation or planning.
  4. Run numerical tools and cite literature evidence separately from computational artifacts.

State and recovery

Separate originals, chunks, vector indexes, retrieval results and conversational memory. Rebuild or update indexes when manuals change, and avoid silently combining old parameter descriptions with new tool versions.

Deployment and dependencies

Local ingestion and storage are possible with the open-source framework; cloud parsing products require separate service configuration. Record parser, embedding model, index snapshot, filters and agent configuration.

4. Tradeoffs and scientific use

Useful when data context is complex. The main costs are curation, retrieval quality and citation verification. Decouple retrieval from an execution runtime for hours-long calculations.

Structural-biology adaptation

Retrieve versioned manual passages and structure annotations for the planner; use domain tools for numerical work.

Practice task

Index a structural-analysis manual. Check whether two parameter queries retrieve the correct versioned passages, then invoke retrieval and calculation as distinct tools.
