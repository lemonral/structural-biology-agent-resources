Haystack

Control retrieval, routing and generation through explicitly connected components.

Component-based RAG, agent and data-processing framework

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

Haystack expresses LLM applications as components and connected pipelines. Explicit retrieval, routing, generation and agent steps let developers measure and replace individual stages.

Best fit
Python applications needing composable retrieval, document processing and tool-using agents.
Boundary
Coordinate calculations, domain objects and scientific acceptance need separate implementations.
Relation to other systems
Compare data ingestion with LlamaIndex and component/pipeline expression with LangChain.

2. Mechanism at a glance

  1. Define inputs and components
  2. Connect retrieval and generation
  3. Add agents and tools
  4. Trace pipeline execution

Components and responsibilities

ComponentResponsibility
Components and portsDefined inputs and outputs connect components. Port compatibility establishes data transfer, while meaning, provenance and quality remain application obligations.
Pipeline connectionsPipelines control data flow among retrieval, reranking, routing and generation stages, enabling stage-specific evaluation.
Agents and toolsAn agent interacts within a tool set and run conditions. Lifecycle hooks expose execution events but do not provide scientific ground truth.
Stores and integrationsDocument stores and model connectors supply external capabilities. Record their dependencies, indexes and states separately from the core pipeline.

3. Follow a real run

  1. Connect loading and retrieval into a minimal testable pipeline.
  2. Inspect actual inputs and outputs at every component.
  3. Use an agent for dynamic tool choice while retaining deterministic processing as components.
  4. Record the generated result and its evidence, then apply task-specific checks.

State and recovery

Pipeline configuration, document stores, model context and tool artifacts are distinct layers. Save the full pipeline and external index snapshot to reproduce version-dependent behavior.

Deployment and dependencies

Python prototypes can run locally. Production adds model and document services. Pin integration and core packages separately; an example does not establish backend interchangeability.

4. Tradeoffs and scientific use

Modularity supports substitution and measurement but increases data-connection and type-management work. Scientific computation additionally needs domain tools and job adapters.

Structural-biology adaptation

Build provenance-aware manual retrieval and connect the retrieved information to a computation plan.

Practice task

Build retrieval, parameter explanation and computation stages. Evaluate correct retrieval, version-compatible parameters and independently verified numerical results separately.
