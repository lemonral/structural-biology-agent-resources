OpenAI Agents SDK

Build a traceable model/tool loop using Agent, tools and Runner.

Code-first agent runtime loop and tool SDK

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

OpenAI Agents SDK organizes in-application execution around agents, Runner, tools, sessions and traces. Its lifecycle and environment responsibilities differ from a hosted agent API.

Best fit
Starting with one agent, function tools and structured run records, adding delegation when needed.
Boundary
Scientific verification, actual cluster job state and domain software environments remain application responsibilities.
Relation to other systems
Can be used without LangChain. Function tools, MCP and other agents can expose capabilities.

2. Mechanism at a glance

  1. Define agents and tools
  2. Run the interaction loop
  3. Delegate or return results
  4. Record sessions and traces

Components and responsibilities

ComponentResponsibility
Agent definitionStore instructions, model settings, tools and control requirements. Define one clear responsibility before adding agents-as-tools or handoff targets.
Runner loopCoordinate model requests, tools, delegation and termination. Read actual run results and exceptions rather than only the last text message.
Tools and delegationFunctions, MCP and other tool interfaces perform actions. Handoffs and agents-as-tools have different call/return structures and responsibility boundaries.
Sessions and tracingSessions retain interaction history and traces locate model, tool and delegation events. Neither is a complete scientific artifact registry.

3. Follow a real run

  1. Provide an agent with the task, permitted tools and context.
  2. Runner calls the model and executes tools or handles delegation.
  3. Return real observations until a terminal result or run failure.
  4. Read run state, artifacts and final output, then apply independent checks.

State and recovery

Associate sessions, runs, tool calls and files. Long-job state requires job IDs, input digests and result versions outside conversation history.

Deployment and dependencies

Embed the SDK in a Python service and configure model access, session storage and tool environments. Keep responsibilities distinct from hosted APIs and other execution forms.

4. Tradeoffs and scientific use

A small core aids prototyping and debugging. Recovery, resource control and domain rules still need implementation; control models and tools when attributing comparative gains.

Structural-biology adaptation

Connect structure-inspection and geometric functions, linking tool calls to results and artifacts.

Practice task

Return a structured inspection result from one function tool. Examine success, tool exception and failed scientific acceptance before deciding whether delegation helps.

5. Reading path

Quickstart and basic/tools.py, followed by Running agents, Sessions and Tracing.

Read agent.py, run.py and tool.py. Locate argument parsing, observation reinsertion, terminal state and final output separately.

Version and evidence boundary
