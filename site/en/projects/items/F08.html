smolagents

Let the model compose tools in executable code, then reason from observations.

Lightweight agent library using code as actions

Source snapshot: 2026-10-30 · Chinese original

1. Position in the system

smolagents emphasizes code as an action representation. A program fragment can combine several tools more compactly than individual JSON calls, making the executor a critical system component.

Best fit
Learning code-action agents, tool composition and a relatively small execution loop.
Boundary
Generated code is not scientific verification. Execution environment, dependencies and permitted scope require explicit configuration.
Relation to other systems
Multiple model and tool sources make it useful for comparison with function-calling SDKs.

2. Mechanism at a glance

  1. Configure models and tools
  2. Generate code actions
  3. Run them in an executor
  4. Read observations and continue

Components and responsibilities

ComponentResponsibility
Model and agent loopThe agent maintains the task and observations. Compare CodeAgent actions with function-call actions to understand debugging and execution differences.
Tool collectionLocal, Hub or protocol-adapted tools offer bounded external capabilities. Inspect actual dependencies, I/O and versions regardless of the source.
Code executorThe executor controls where code runs and what it can access. Correct generated syntax does not establish correct environments or file selections.
Step and result recordsLogs reconstruct actions, errors and observations. Map code to real inputs, artifact versions and validation records for scientific tasks.

3. Follow a real run

  1. Provide a task and an explicitly selected tool collection.
  2. Generate code or another supported action and run it through the executor.
  3. Return observations, errors and variable results.
  4. Decide whether to continue, then independently verify final artifacts and calculations.

State and recovery

Interpreter variables, files, conversation traces and external services have different persistence. An in-memory variable cannot be the sole recovery record for a long job.

Deployment and dependencies

Use a local or remote model with the chosen local or isolated executor. Pin model, tool packages, imports and environment; executors need not expose equivalent capabilities.

4. Tradeoffs and scientific use

Code actions express loops and composition compactly but require simultaneous debugging of decision logic and execution environment. Compare with strict function tools under matched tasks and budgets.

Structural-biology adaptation

Compose structure-inspection functions under explicit input and tool boundaries, preserving code, parameters and results.

Practice task

Compose two read-only inspection tools, inject a missing file, and inspect how the error informs the next action. Verify final numbers with an independent reference.

5. Reading path

README Quick demo, then the CodeAgent loop and tool interfaces in agents.py.

Read the action loop in agents.py and executor interfaces. Distinguish generated code, code actually executed and actual tool return values.

Version and evidence boundary

Code actions and software-development coding agents are different concepts. Execution mode depends on configuration.
