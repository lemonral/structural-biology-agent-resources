READING METHOD & TERMINOLOGY

怎样读懂一篇论文，
怎样判断一个项目

先找问题、对象和证据，再理解机制与实现。论文的实验结论、项目的功能说明，以及本导读的迁移建议分别阅读。

01 / ACADEMIC READING

论文研读：让每个结论都有对应证据

阅读顺序应回答的问题容易出现的误读
问题与缺口研究对象是什么，已有方法在哪个具体条件下不足？把宏大背景当成论文已经解决的全部任务。
方法与设计输入怎样经过组件与判断，变成输出；每个设计解决哪个缺口？只记住名字和框架图，没有理解信息与控制的流向。
实验、对照与指标数据、基线、预算和评分是什么；结果支持到哪里？把不同任务、模型、工具与预算下的分数直接比较。
消融与失败去掉哪个组件会改变什么；哪些任务失败或不稳定？只引用最佳一列，把失败与条件从结论中删掉。
复现与外推代码、数据、版本、环境和独立测试是否可得？把教程成功、作者自报或一次案例当作通用能力。
02 / ENGINEERING READING

工业项目阅读：从组件到运行与维护

视图重点内容
组件视图Agent、工具、运行时、存储、服务和界面分别归谁负责。
运行视图从请求到模型、工具、外部状态、产物，再到用户看到的终态。
数据与状态视图对话、任务、尝试、外部Job、文件与验证结果怎样关联。
部署视图哪些能力在本地、远程服务、Worker或计算集群；需要哪些依赖。
源码视图从真实入口看接口与状态，而不是凭目录名字猜内部算法。
验证视图正常、无效输入、失败、恢复和质量不合格怎样分别判断。
03 / GLOSSARY

常用术语放在实际任务中理解

术语简明解释
Agent基于目标和观察选择下一行动的系统。实际能力还取决于模型、工具、环境、状态与停止规则。
Workflow / 工作流将步骤及其控制关系明确组织起来；可含固定函数和Agent节点，不要求每一步都由模型决定。
Harness / 运行配套体系围绕Agent循环提供工具、工作区、上下文、执行与恢复等配套；具体范围随项目而异。
RAG / 检索增强生成从资料中检索上下文再生成回答。检索相关与证据正确、结论成立是不同判断。
Schema / 数据合同描述字段、类型及结构约束。解析成功不证明文件身份或科学选择正确。
Checkpoint / 检查点为继续执行保存状态材料。不会自动保证外部作业只执行一次，也不会替代科学验证。
MCP 与 A2AMCP主要连接应用与工具/资源服务；A2A主要规范Agent应用之间的任务与产物交互。
消融 / Ablation在明确控制条件下去掉或更改某组件，检查其影响。并非所有项目或论文都做了这样的对照。
独立测试冻结系统后在未用于开发选择的数据与任务上评价；需要防止近重复对象、模板或同源材料泄漏。
复现、复制与泛化复跑作者配置、新实现得到相近结论、以及新对象/新任务上的有效性分别要求不同证据。
03B / ENGINEERING TERMS

读工程手册时，用这组词对照具体对象

术语在本系统里怎么理解
Worker / 计算执行进程从已接受的任务中领取工作，在指定环境里运行真实工具，并回传日志、作业身份和产物。它和网页请求、模型推理是不同生命周期。
Outbox / 事务外发记录把业务状态与待发送的操作意图写入同一个数据库事务，再由投递者发送。解决本地“已记账却没发出”一类问题；外部副作用仍需核对。
Reconciliation / 状态核对比较账本里的记录与外部作业或文件的真实状态，处理延迟、失联与冲突。无法确定时保留未知，不把查询不到等同未发生。
幂等 / Idempotency对同一逻辑操作重复请求时，结果与副作用符合约定的重复处理规则。稳定键只是身份材料；是否能去重取决于实际执行边界和后端保证。
At-least-once / 至少一次投递同一消息或动作可能被再次交付。消费者必须能识别重复和已完成状态，并对外部副作用采取适当保护。
Artifact / 计算产物被登记和追踪的结果文件或数据对象，包含摘要、来源、生成配置与相关验证，而不是文件名或模型回答中的一段描述。
SLI 与 SLOSLI是测量服务行为的指标，SLO是对某段时间与范围约定的目标。排队、执行、科学验收与成本分别定义，不能混成一个成功率。
Runbook / 故障处理手册写清触发信号、核查顺序、可执行恢复、停止条件与负责人；应通过演练校验，不能只列“重启服务”。
科学工作流与资源调度科学工作流表达稳定的步骤与数据依赖；资源调度负责将计算安排到资源。Agent决策、持久业务状态和独立科学判定仍有各自责任。

04 / READ METRICS CAREFULLY

一个成功率之前，先检查分母与预算

说明性例子，不对应任何一篇论文的结果

同一任务运行多次，“至少成功一次”“每次都成功”和“所有运行的平均通过率”可能给出完全不同的印象。best-of、多次尝试与单次部署需要分别报告。

阅读pass@k、pass^k、reward、CSR或任务完成率时，回到该论文的具体定义：评分对象是答案、轨迹、文件还是终态？预算是否包括失败？是否把多次最佳结果与别人的单次结果比较？

结构计算至少分开执行完成、产物有效和科学验收；报告各层的分母、失败和成本。
