BioMedAgent

Empowering AI data scientists using a multi-agent LLM framework with self-evolving capabilities for autonomous, tool-aware biomedical data analyses

BioMedAgent研究多Agent如何通过交互探索学习工具，再从记忆中检索经验完成生物医学数据分析。它把工具使用经验的积累作为跨任务分析能力的一部分，而不仅依赖预写工作流。

01 / PROBLEM & GAP

论文究竟在解决什么问题

研究问题

生物医学数据分析需要把自然语言问题转换成统计、组学或机器学习流程，并在不同工具和环境之间执行。工具文档往往不足以覆盖实际调用中的失败条件；一次任务中学到的操作如果无法保留，后续任务仍会重复探索并承担相同错误。

相对已有工作的缺口

固定流程降低了规划自由度，纯代码生成又容易忽略领域工具的真实接口。本文加入Interactive Exploration和Memory Retrieval，让工具探索产生可复用经验；是否真正跨任务迁移，取决于学习、记忆和测试之间的隔离。

任务要素本论文的具体设定
输入自然语言分析问题、相应数据，以及已配置的工具代码、描述和环境。
输出可执行分析过程、结果文件与面向用户的分析输出；具体任务的正确性由评价答案与判据决定。
环境、假设与人工角色多Agent协作规划、编码和执行；专家提供任务、工具与评价资料。公开示例需另配服务与部分工具环境，不是网页问答演示即代表完整论文设置。
02 / METHOD & DESIGN

核心方法：组件怎样解决前面的缺口

01

工具的交互探索

Interactive Exploration让系统通过与工具交互学习使用经验，而非只读取一次文档就假定能正确调用。经验应关联工具及其适用情境；现有可读资料未充分揭示全部探索预算和失败处理细节。

为什么这样设计：针对文档与实际执行之间的落差，让工具知识包含实际使用中获得的信息。
02

经验记忆与检索复用

Memory Retrieval在新分析问题中检索既有经验，支持后续规划和工具调用。其收益需要同仅有当前任务上下文的设置区分，并核查记忆包含的是通用工具知识还是接近测试答案的信息。

为什么这样设计：减少反复学习同一工具的成本，但也使经验来源和测试隔离成为方法的一部分。
03

协作分析与工具配置

多Agent共同承担规划、编码与执行，调用外部分析工具完成任务。官方仓库提供agent入口、工具描述和示例；扩展工具需要代码、文档与环境配置，不能仅凭一个名称声明即认为已可靠接入。

为什么这样设计：将复杂分析拆成可协作的工作，但可靠执行仍依赖明确的工具契约和实际环境。

04 / CRITICAL APPRAISAL

证据支持到哪里，哪些结论仍需验证

记忆可能改变测试条件

若探索或记忆写入阶段接触近似测试问题，成功率就同时反映经验暴露；需要明确划分才能判断新任务泛化。

外部工具与服务更新使经验过期

曾经成功的调用不保证新版本仍有效；学习型工具记忆必须关联软件版本、数据类型和失败条件。

有限公开资料不能拆分组件贡献

当前能核实机制名称、代码入口与任务范围，但不足以报告IE、MR和多Agent各自的独立消融收益。

对结构计算Agent的启发
本导读的设计推论

本导读推论：结构Agent可以保存经验证的工具使用经验，但记忆条目应包含输入类型、软件版本和结果核查方式。复用时先验证契约是否仍成立，不能把曾经运行成功当作新结构问题的科学结论。

  1. 固定论文工具清单与仓库提交，区分演示和完整实验配置
