DESIGN 01 / 16

架构、框架、模型与科学工具的分工

本章把现有 PRD 0.2 的合同收敛成可实施的架构说明。它是设计讲解配套，配合既有 PPT 阅读；当前 3188 网站仍是资料站，真实模型驱动的 Agent 服务尚未部署。

软件架构回答模块怎样协作、事实存在哪里、失败后谁负责，以及权限和资源怎样约束。框架提供可复用的控制与集成机制。模型根据允许看到的信息提出候选理解或动作，科学工具读取真实输入并计算。把这几层分开，才能定位“链选错”“工具没运行”“报告越过证据”等不同错误。

    保留原始 TaskRevision，在首次模型调用前持久化同一 Run 的输入、配置、后端权限范围与总预算。

  2. 固定预检与澄清

    PREFLIGHT 只检查文件和对象清单；模型解析与补充回答都记入这个 Run，不另开免费的 planning_run。

  3. 冻结科学合同

    必要条件明确后绑定 FrozenTaskSpec，固定对象、选择、映射规则、测量意图和接受政策。

  4. 编译与实际执行

    模型提出 typed 计划，可信程序检查依赖、权限、资源和版本，再派给 Worker；实际工件在执行边界核实。

  5. 验证并交付

    同一 Run 内受限修订保持科学合同；验证记录与不可变报告引用真实产物，项目内正常新增报告和同权限下载自动交付。

先问哪一层出错

例如模型正确提出 CORE 对齐，但 Worker 读取旧文件，应查执行与身份；如果模型提出各区独立拟合却解释成相对 CORE 位移，应查任务语义与方法。仅更换模型无法替代这些责任检查。

这一节怎么讲 · 配套口语稿

这里先区分几个容易混在一起的词。架构规定各部分如何协作、事实放在哪里以及失败由谁处理。框架帮助组织控制流程，模型提出理解和候选动作，科学工具才读取实际坐标并计算。这样划分以后，我们才能知道问题来自理解、执行还是结果解释，也能在以后更换框架时保留科学合同。

沿着流程看，一开始就创建分析 Run 并建立总预算，随后在同一个 Run 中预检、澄清、冻结规格，再规划、执行和验证。固定步骤由代码负责，需要新观察时才让模型决策。这一章是对已有 PPT 的补充设计，描述下一步要实现的服务；目前资料站和固定流程示例并不等于完整 Agent 已经部署。

九个模块的输入、输出与责任边界

模块是代码和职责边界，首版可以保存在一个代码仓库；API、控制进程与计算 Worker 可分别重启，不需要一开始拆成九个微服务。

按“谁拥有事实、谁允许副作用、谁判科学结果”拆分，比按模型角色拆分更容易定位错误。模块之间传版本化数据与工件引用；执行记录、授权和预算通过业务账本协同，不能只通过聊天消息传递。ModelAdapter 同时服务冻结前意图解析与冻结后规划，所有调用归属同一个 Run。

这一节怎么讲 · 配套口语稿

这九个模块是职责划分，不要求先部署九个独立服务。最重要的边界是，模型提出什么、程序实际做了什么、科学上能否接受，分别由谁负责。输入检查提供真实对象，规格构建明确问题，规划提出候选，编译和授权决定能否执行，Worker 才产生真正的计算记录。

产物与验证保留不可变历史，报告引用这些事实，用户反馈再进入复现和审查。这样一个错误就能追到责任位置：错链查对象与合同，没生成文件查执行，夸大结论查报告。模块之间使用有版本的工件引用和业务记录，不靠几个角色互相说已完成。这是补充架构设计，仍需后续实现和验收。

DESIGN 04 / 16

State、业务账本与 checkpoint 各存什么

State 是下一步决策所需的工作视图；业务账本保存执行与成本事实；checkpoint 保存图运行位置。它们可用同一个 PostgreSQL 实例，但使用不同表与职责。

存储/视图保存什么怎样使用反例
业务账本TaskRevision、Run、FrozenSpec、PlanRevision、Attempt、Artifact 元数据、Validation、成员关系与预算预留权威状态迁移、事务锁、幂等和访问检查；每次副作用前读取当前事实checkpoint 中的旧权限不能覆盖已撤销的 membership
图内 Staterun_id、已读取账本版本、当前阶段、候选/冻结规格引用、观察摘要、待澄清项与计划引用为节点提供最小上下文；只缓存可重读的事实，不复制大坐标把模型说的“文件存在”写成可信产物
持久 checkpoint某 thread 的图状态、节点执行进度与恢复所需中间信息在中断或故障后定位图；生产配置真实持久 checkpointerInMemorySaver 不跨进程持久；节点重放不保证副作用只执行一次
不可变产物存储输入字节、对象清单、映射、指标、验证与报告内容及其 hash账本按 artifact_id 定位并鉴权；保留原始与规范输出只在聊天摘要存最终 RMSD，丢掉映射和变换
跨线程 Store / 可选 trace经审查的偏好/经验；可采样诊断 span按项目权限复用信息；trace 帮助调试且可删除采样用长期记忆当本次文件真值，或用 trace 采样代替完整业务事件
  1. 恢复时先重读账本

    核对 Run 身份、state_version、当前成员权限、预算预留/实际用量与截止时间。图内保存的剩余额度只作工作视图。

一个 ANALYZE Run 从创建起覆盖预检、模型解析、澄清、规划、计算和报告。先确定科学合同，再派发普通科学操作；恢复与修订使用原 Run 剩余额度。

异步、租约与恢复：账本保存事实

PostgreSQL 保存业务状态、操作身份、事件和预算；LangGraph checkpoint 保存图的恢复位置。文件存储、模型提供方与数据库之间没有自动的共同事务。

机制负责什么恢复时必须核对
Idempotency-Key识别相同用户写请求同身份/项目/方法/资源、同 payload 返回原身份；同 key 异 payload 为 409；重放仍查当前权限
operation_id识别一次真实尝试同 Attempt 重投复用 ID 和 request_digest；有依据的新重试才创建新 Attempt/operation_id
事务 + outbox状态、队列、预留与待通知事实一致一起提交；通知允许重复，消费者按事件身份去重
租约 + lease_epoch限制当前领取者与迟到提交领取时递增 epoch；旧 epoch 不能更新权威状态或发布产物
checkpoint恢复控制图与可见上下文节点可重放；先查账本已有操作，不能据图位置再次执行副作用
  1. 提交与领取

    短事务保存 Run、队列、业务事件及预算；消费者用行锁/SKIP LOCKED 领取并续租，计算不占长数据库事务。

  2. 失联先协调

    租约超时进入 RECONCILING，核对受控进程句柄、启动时间、输出槽和完成回执。仅凭 PID 或心跳丢失不能认定未执行；事实不足保留 UNKNOWN。

  3. 跨存储发布

    Attempt 专用临时槽关闭写入并核 hash/size，形成可核对的不可变字节，再登记 AVAILABLE。下载只认权威元数据与当前权限；缺文件标 MISSING，孤儿字节隔离或协调登记。

三个不能省略的故障窗口

文件已落盘但元数据未提交，会留下孤儿文件；数据库标可用而文件丢失，需要阻断下载并修复；模型请求已发送但响应丢失，费用仍可能发生。对未决调用保留 UNKNOWN 预留，不按零成本释放；恢复不刷新 Run 总预算。

这一节怎么讲 · 配套口语稿

异步的关键是把已经发生的事实留在账本里。API收到请求后先持久化，Controller和Worker即使重启，也能按同一个Run查到操作。用户重复点击用幂等键识别，某次真实尝试用operation_id识别，二者解决的重复不同。租约带递增epoch，避免迟到Worker覆盖新状态。

检查点只说明图从哪里恢复，不证明工具是否已经运行。恢复前还要查数据库、真实进程和产物。文件与数据库也没有共同事务，可能出现文件已写但尚未登记的窗口，因此必须有临时槽、完成回执和协调流程。无法确定执行或计费时保留未知，既不盲目重提，也不把预算重新归零。
