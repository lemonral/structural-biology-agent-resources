深度专题：Agent 方法为什么这样发展，以及如何用于结构生物学

阅读主线：推理文本 → 用工具取得真实观察 → 把调用组织成计划 → 从失败和成功中保存经验 → 协作交接 → 根据评价自动优化 → 用交互训练与开放环境检验。下文的 NBDB 示例是面向平台的设计推论，不是原论文做过的生物学实验；年份分别说明首次公开或正式发表，截止 2026-10-27。

一、从语言推理到环境反馈：Agent 闭环的起点

2022 年的核心问题不是“如何让多个智能体开会”，而是模型会生成语言，却不能直接确认外部事实或完成精确计算。Chain-of-Thought（CoT，NeurIPS 2022）在少样本示例中加入中间推理，使模型学习输出分步过程；作者在算术、常识和符号推理上实验。这个工作说明把问题拆成中间步骤有价值，但仅凭生成的过程无法保证证据真实，也没有操作环境、异常处理和执行记录。

ReAct（2022 首发，ICLR 2023）把“思考→行动→观察”交替组织：模型根据目标选择调用，工具返回真实观察，再根据观察决定下一步。它在 HotpotQA、FEVER 中使用 Wikipedia 接口，在 ALFWorld、WebShop 中进行交互任务；论文报告后两个环境相对所比较的模仿或强化学习基线分别提高 34 和 10 个百分点，这一结果只适用于论文环境和基线。ReAct 解决了 CoT 无法获取最新外部状态的问题；代价是模型每步重新决策，长链条会增加调用、时延与累计出错机会。

示意：用户要求比较两个结构
模型决定查找结构 → 工具返回候选及链信息 → 模型选择待验证的链
→ 调用比对 → 返回对齐范围、残基映射、RMSD → 汇总并引用结果

关键区别是，工具真正返回的观察才是证据；模型事先写下“RMSD 应该很小”只是预期。并且“结构比对调用成功”并不等于“比对了正确的链和对应残基”。这个区别就是科学 Agent 要引入任务约束和独立验证的原因。

Toolformer（2023 首发，NeurIPS 2023）研究了另一个问题：如何让模型本身学会何时调用工具。它用少量 API 示例生成候选调用，执行调用，再按工具返回是否改善后续文本预测来筛选训练数据，最后微调模型。论文实验覆盖计算器、搜索、问答、翻译和日历等工具。与 ReAct 的推理时提示不同，它把调用习惯写进模型参数；但训练中能预测文本更好，不等于工具调用已满足科学前提，更不能代替权限、资源控制与执行验证。

平台启示：首先建立一个可测的单 Agent 闭环：任务解析、有限工具选择、结构化调用、读取观察、校验、报告。先用明确工具与小任务验证，再考虑复杂多 Agent 或训练。

二、从一步步试探到计划、依赖与搜索（2023—2024）

ReAct 把反馈带进流程，但把每一个独立步骤都变成“模型想一次→工具跑一次→模型再想一次”，会重复传输上下文。研发者开始分别处理漏步骤、重复推理、并行机会和错误路径，这些问题不能由同一种规划统一解决。

Plan-and-Solve（ACL 2023）先要求模型把问题分解，再逐步求解，目标是减少没有计划时的漏步；论文在多个推理数据集上比较 zero-shot 提示。它更像组织思维的计划提示，原文不是长作业调度器。对于输入、工具、依赖明确的分析，平台仍应把计划落成可检查的数据结构。

ReWOO（2023，预印本）通过 Planner、Worker、Solver 解耦：先产生完整计划，在计划中用证据变量引用前一步结果；Worker 执行工具并填充变量，Solver 最后合成答案。论文表 2 的 HotpotQA 设置中，与 ReAct 相比，每题平均 token 约 9,795 降至 1,986（约 4.9 倍效率），准确率由 40.8% 升至 42.4%（增加 1.6 个百分点，约 4% 相对提升）；这是该基准和实验配置下的结果。它不是每得到一次观察都让模型重规划；当工具结果可能改变后续路径，例如结构缺少用户要求的链时，一次性计划需要设置显式检查点和局部重规划。

规划示例：
E1 = 获取结构 A；E2 = 获取结构 B             # 可并行
E3 = 确定链和残基映射(E1, E2)                  # 依赖 E1、E2
E4 = 对映射区域进行比对(E1, E2, E3)            # 依赖 E3
若 E3 无可靠映射 → 停止、请求澄清或局部改计划，不能虚构 E4

LLMCompiler（ICML 2024）把调用计划变成依赖图：Planner 生成调用与依赖，Task Fetching Unit 在依赖满足时分发，Executor 并行运行，最后整合。论文在其基准中相对 ReAct 报告最高约 3.7 倍时延加速、成本最低约为对照的 1/6.7；并非所有任务都能得到这一倍率。科学计算里并行是否合算还取决于 GPU 数量、排队、输入数据搬运、共享文件冲突和上下游约束。它改善的是调度结构，并不自动证明参数或结果正确。

LATS（ICML 2024）面对另一问题：一个计划走错后该如何寻找替代路径？它结合蒙特卡洛树搜索、语言模型评价、环境反馈和反思，展开并选择候选轨迹；在程序、交互问答、网页和数学任务中实验。论文在 HumanEval 使用 GPT-4、最多 8 次搜索迭代，每次扩展采样 5 个候选，并用模型生成的 4 条测试与执行反馈选出一个解，再在正式测试集评估；其报告的最终解 pass@1 为 92.7%。这并非一次模型调用直接答对 92.7%，搜索消耗和内部测试质量必须纳入比较。科研场景中，对轻量输入处理或可快速校验的参数选择可尝试搜索；昂贵模拟、不可逆实验或缺少可靠评分器的操作不能无预算地扩展搜索树。

何时使用：工具返回决定下一步 → ReAct 风格反馈；依赖大体已知且存在独立分支 → 显式 DAG；结果存在有限替代方案且评价便宜 → 有预算搜索。它们可以共存：DAG 节点内使用小范围反馈，检查点失败才重新规划。

三、从反思到技能与记忆：如何不重复犯错

Reflexion（NeurIPS 2023）将尝试、反馈和语言反思组成跨尝试循环：执行者产生轨迹，评价器给出反馈，反思器写下下次可用的经验，下一轮读取。论文明确没有更新模型权重；在程序、决策和推理任务实验。对于 HumanEval Python，作者使用模型生成的测试（最多 6 条）及失败后的反思和修订，报告最终提交解的 pass@1 为 91.0%；这不是单次生成的成功率，也不应与未使用多轮测试的模型直接视为同预算比较。科研平台可记录“此文件缺失配体参数，不能运行某项计算”的条件和处理方法，但如果评价器只检查进程退出码，错误经验也会被强化。

Voyager（2023 首发，TMLR 2024）在 Minecraft 中组合自动课程、可执行代码技能库和反馈驱动的程序修正。技能不只是自然语言结论，而是可调用、可组合的程序；作者测试了物品发现、探索距离、科技树进度与新世界迁移。其启发是把验证过的多步操作沉淀成参数化技能，而非把所有对话记忆一股脑存入向量库。技能必须有输入条件、依赖版本、测试及撤销机制；游戏内迁移不直接证明科学数据上也能迁移。

MemGPT（2023，预印本）借鉴内存分层，管理有限上下文中的工作内容与外部存储，按需读写并通过中断管理控制流；论文测试长文档分析和跨会话聊天。它解决“信息放不进上下文”，不保证被取回的信息正确。对 NBDB 更合适的分层是：数据库存可溯源事实，任务数据库存执行状态，经验库存候选方法，当前上下文只放与此任务相关的摘要和引用；完整结构、密度图、轨迹保存在对象存储，而不是塞进提示。

Agentic Plan Caching（NeurIPS 2025）从完成轨迹中提取结构化计划模板，匹配相似新任务，再用轻量模型适配具体上下文。论文在五类任务上报告相对准确率最优基线平均成本下降 50.31%，应用层表现为该基线的 96.61%；其延迟微基准使用 FinanceBench 的 100 条随机查询，报告端到端耗时下降 27.28%。这些是特定配置下的结果，不能推断所有工作负载都性能不变或均有同样提速。缓存的是计划结构，不是把旧蛋白的计算结果冒充新蛋白结果；模板必须重新绑定结构、版本、输入假设与资源。

ACE（ICLR 2026）针对反复压缩摘要造成细节遗失，把经验作为可增量更新的 playbook，由生成、反思和整理模块共同维护。论文在 Agent 和金融推理设置中评估离线与在线上下文适配；所报结果不能自动推及生命科学。MemRL（2026，预印本）则先按语义检索，再结合环境反馈学习记忆的效用；这是对记忆选择做强化学习，论文强调基础模型权重不更新，不能等同于用 RL 训练模型本身。

要评估记忆是否有用：对同一测试集比较无记忆、简单相似检索、带验证的技能库；统计正确率、错误经验污染、检索噪声、token、跨版本失效。记录“经验适用条件和来源”比单纯记录“上次成功”更重要。

四、从单 Agent 到协作：角色如何真正产生价值

AutoGen（2023 首发，COLM 2024）把可编程的 Agent 对话作为组织模式，将模型、工具与人类反馈放入交互过程。它提供协作抽象，不意味着增加角色数量就会增加准确率；当前软件仓库已归档，论文思想与今天的软件选型要分开看。AutoGen 官方仓库建议新项目参考后继框架。

MetaGPT（ICLR 2024）指出把多个语言模型简单串起来会传播逻辑不一致，因此把软件团队的标准操作流程与角色交付物引入协作：上游形成需求或设计，中间产物供下游使用与检查。论文评价的是协作软件开发任务，不是结构生物学。MetaAgent（ICML 2025）进一步研究用有限状态机控制多 Agent 的动作与状态转移。两篇共同指向：真正的设计单位是谁有权做什么、何时交接、交接什么、失败如何返回。

NBDB 协作示意：
任务规划 → [序列证据模块 ∥ 结构证据模块] → 结果汇总
                                           ↓
                           独立验证器检查引用、残基映射、适用范围
                                           ↓
                           报告：已证实结果 / 不确定性 / 未完成步骤

这里“专家”可以先是确定性的工具封装，只有确需自由推理或上下文隔离时才变成独立 Agent。多个 Agent 即使互相赞同，也可能共享同一个错误来源；独立验证应尽可能由不同证据、程序检查或人工复核支撑。若同预算下单 Agent 与固定工作流已达到要求，多 Agent 的通信和维护成本未必有回报。

五、从手工提示到自动化设计：优化的对象必须明确

DSPy（ICLR 2024）把语言模型调用写成具有输入、输出和组合关系的模块，再利用数据与评价指标优化提示、示例或其他参数。论文在数学、多跳检索、复杂问答与 Agent 循环中给出案例。它主要解决模块内部如何表达和配置，不负责替你发明可靠的科学评价指标。若开发集只奖励“报告看起来完整”，优化器会把它推向流畅而非正确。

ADAS／Meta Agent Search（ICLR 2025）把 Agent 表示为代码，由元 Agent 基于已发现程序生成、测试并归档新设计；论文在编码、科学及数学等任务研究跨任务和模型迁移。AFlow（ICLR 2025）更聚焦于工作流图，将节点和边组成的代码视为搜索对象，用树搜索、代码修改和执行反馈探索方案。论文六个数据集上的平均提升和成本结果由其评测设定产生，不能等同于生产平台收益。

方法主要被优化对象需要先有容易忽略的成本
DSPy模块提示、示例等配置输入输出契约、可评分样本编译/搜索成本、开发集过拟合
ADASAgent 程序及组合沙箱执行、程序评分和候选档案搜索代码安全、评测预算
AFlow节点与边构成的工作流可执行任务和工作流评分图搜索成本、数据泄漏
Plan Caching / ACE复用计划 / 更新上下文经验可验证轨迹和失效规则错误经验污染及版本维护

科学软件版本、工具可用性、样本分布会改变。自动生成的工作流应先在隔离环境测试，记录每次候选和成本；冻结选中方案后，在从未参与搜索的测试集评价，不能把搜索时最佳开发分数当最终结论。

六、2025—2026：从提示与搜索走向交互训练和开放世界

前面方法多通过上下文、搜索或程序结构调整系统，基础模型可以保持不变。新一阶段的问题是：能否利用真实执行轨迹，让模型学会何时调用工具、如何从错误中恢复？

ReTool（ICLR 2026）先用合成的代码增强推理数据冷启动，再在多轮代码执行的 rollout 中以任务结果训练模型；文本推理与代码执行可以交替。论文在数学竞赛任务中观察到改进与代码自修正，这证明在可明确验证答案的环境中具备潜力，不能直接推出模型掌握结构建模。ToolRL（NeurIPS 2025）系统研究工具选择和调用中的奖励类型、粒度与时序，提醒我们：只奖励最终答案可能提供过于稀疏的信号，但过度奖励“调用次数”也会产生无意义调用。

CodeGym（ICLR 2026）把编程题中的原子函数或逻辑抽成工具，将静态题转成多轮交互环境，以可验证程序结果支持训练。作者在分布外工具使用基准观察到改善。对 NBDB 的启发是先建设可重置、可验证、工具和输入可变的训练环境；但模拟出来的科学任务若遗漏真实数据质量、排队、输入依赖和失败模式，模型可能只学会模拟器。

ToolOrchestra（ICML 2026）训练较小的协调模型选择其他模型和工具，奖励同时涉及结果、效率与用户偏好。论文在其 HLE、τ²-Bench 等设置报告效果和成本优势；这是模型/工具组合与具体基线条件下的结果。对 NBDB，可探索按任务复杂度分配模型与计算资源，但以科学有效性作为约束，不应让费用奖励鼓励跳过验证。

Agent Lightning v1.0（2026，预印本）研究由实际 Agent harness 负责工具、上下文和交互循环，而训练器观察模型请求与响应的训练架构；作者指出重新分词、样本合并、优势计算等会影响训练。论文给出了编码 Agent 的复现实验；这说明训练与部署的运行环境必须对齐，并不是说任意现有平台接上 RL 后就能自动改进。

OpenAgent（ICML 2026）把开放环境变化分解为查询、动作、观察、领域等分布变化，在受控沙箱中测试训练后的工具 Agent，并研究扰动增强微调。它给平台一个重要的评价视角：同一套工具版本上得高分不足以证明可迁移，还要测试未见工具、改名参数、工具报错、数据格式变化及不可完成任务。

七、把方法拼成一个可以运行的 NBDB 任务

任务示例：用户上传两份蛋白结构，请求比较指定链的结构差异，说明覆盖范围和结果可信边界。示例中涉及的操作与判断是建议设计，不代表平台已实现。

  1. 任务契约：解析两个结构、链标识、是否需要生物学组装体、比对范围与输出要求；无法唯一确定时询问用户或明确假设。
  2. 工具发现：按输入格式、操作类型、版本与可用性检索工具；候选必须可执行、有契约，并记录选择理由。ToolLLM（ICLR 2024）收集 16,464 个 REST API、构造指令与轨迹并训练检索器，展示工具多时先检索候选的意义；其实验 API 规模不等于已覆盖科学计算。
  3. 规划和调度：独立检查两个输入可并行；链确认与残基映射依赖输入；真正比对依赖映射。把数据和版本作为节点输入，持久化每一步状态与产物。
  4. 观察和恢复：若链不存在或比对覆盖太低，返回结构化错误，禁止生成伪造数字；允许有限重规划或让用户选链。提交耗时作业后保存任务标识，重启后查询状态，避免盲目重复提交。
  5. 独立验证：检查比对对象、残基对应关系、对齐残基数和覆盖率，标明所用程序及 RMSD 的定义与单位；对于预测结构，模型给出的置信指标与实验验证是不同证据，不能互换。
  6. 最终报告与经验：每个数值链接到对应输入、程序版本、参数和结果文件；可信度不足时说明原因。仅经测试的通用流程可候选进入技能库，不能复用旧样本的结论。

这一例子把 ReAct 式条件分支、LLMCompiler 式依赖调度、Voyager 式可复用技能和独立科学验证组合起来；它是一个具体设计，而不是声称任何一篇论文已经构建了这套平台。

八、如何从系统建设形成可发表的研究

论文需要回答明确的新问题，而不是把多个通用组件堆在一起。下面三个题目是研究假设，需要实验验证，不能预设一定成立或保证录用。

研究假设与贡献关键对照和数据主要结果及失败分析
面向科学输入约束的工具选择与计划：在工具注册表中加入输入兼容性、残基映射和前置条件，减少看似成功的无效分析。同一模型和工具下比较自由调用、仅文本工具描述、结构化约束计划；按结构家族、实验方式、工具版本划分训练/开发/测试；包含无解和缺失输入。科学任务有效完成率、工具选择和输入正确率、无法完成识别、费用与耗时；分析是约束本身、工具检索还是验证器造成改善。
作业状态不确定时的可靠恢复：针对长作业响应丢失和重复提交，验证状态对账策略能否提高可恢复性。相同工作流比较无恢复、仅模型重试、持久化意图与状态对账；注入提交后断连、排队超时、节点崩溃和存储延迟。重复提交率、丢失任务率、最终状态一致性、恢复耗时、资源浪费；报告失败注入模型和假设。
有条件的技能经验复用：将成功轨迹保存为版本化、可验证的计划模板，在新结构和工具变化下测试。比较无记忆、相似检索、版本和前置条件约束的技能；按蛋白家族和工具版本独立划分；重复执行统计方差。任务有效率、错误复用率、费用、OOD 性能及人工维护成本；删除版本约束或验证环节做消融。

统一实验协议：预先定义任务成功的分母：所有发起任务，包括超时、异常和拒绝；同时报告正确拒绝与不正确拒绝。保留数据及工具版本、算力、token、训练与搜索成本；多次独立运行并报告不确定性。把流程通过率、科学正确性、人工时间、失败代价分开报告；专家盲评只用于需要专业判断的结果，并明确一致性和样本量。将不同架构置于相同输入、工具、模型与预算下比较，以便定位贡献来源。

推荐推进顺序：① 构建可复现工具执行和科学验证；② 建立单 Agent 与固定流程基线、真实任务集；③ 围绕最明显失败提出一个机制并做消融；④ 测试新家族、新工具及不完整输入；⑤ 再决定是否训练和投稿。既有论文提供的是研究方法与实验设计，不提供 NBDB 场景的结论。

九、补充逐篇解读：记忆、训练与开放系统

本节对前文着墨较少的代表作逐篇展开，包含研究问题、方法、评测、局限和对 NBDB 的启发。启发是面向平台的研究设计，不是论文原有生物学结果。

Generative Agents（ACM UIST 2023，正式会议）

问题：如何让长期交互的模拟角色记住过去并产生连贯行为？做法：输入是观察事件与角色背景；系统把经历写入记忆流，按近期性、重要性和相关性取回，再生成高层反思与分层计划，最后输出动作和对话；反思与计划也进入记忆。评价：在 25 个模拟角色的小镇中观察两天交互，并通过访谈式问题和去掉记忆、反思、计划的消融评价行为可信度。局限：可信行为不是客观事实，论文记录了记忆漏取及编造；沙箱中的社交可信度不等于科学分析准确。NBDB 启发：经验检索可参考相关性和时间，但科学事实需保留原始来源、版本与验证状态。论文原文与会议信息

A-Mem（NeurIPS 2025，正式会议）

问题：长期记忆仅按向量相似度孤立存取，难将相关经历组织起来。做法：新交互输入模型，形成包含内容、上下文、关键词、标签和向量的笔记；检索历史笔记后判断是否连边，并可更新旧笔记属性；查询时检索关联笔记辅助回答。评价：在 LoCoMo 长对话问答和 DialSim 数据上，对多模型及记忆基线比较 F1、BLEU 等，并分析多跳、时间、对抗问题。局限：连接和更新由模型决定，可能把错误或无关信息传播；文本重合度无法验证科学推断。NBDB 启发：给经验建立来源、适用条件和版本间的可追溯联系，同时保留原始记录并允许撤销。NeurIPS 论文

Search-R1（COLM 2025，正式会议）

问题：模型在何时搜索、如何根据结果继续查询上未经交互训练，固定检索一次难处理多跳问题。做法：以问题为输入，模型生成搜索标记与查询，检索器返回文档后继续推理或再搜索，最终输出答案；训练用最终答案奖励与 PPO/GRPO 等方法，并屏蔽检索文本的策略损失，只优化模型生成 token。评价：论文在 7 个问答数据集上对照不同 RAG 策略及训练设置；不同版本的摘要数字有差异，复现应固定正式版、模型与检索器。局限：最终答案正确不能保证每条证据充分或引用可靠，静态问答不能替代科研计算。NBDB 启发：先积累带引用的多轮检索轨迹，分别评估查询选择、证据覆盖和答案。COLM 正式论文

GOAT（Findings of ACL 2026，正式发表）

问题：高级目标涉及依赖的多步 API 调用，而人工标注轨迹昂贵，先编问题再补调用可能产生不真实或过于简单的样本。做法：读取 API 文档，构造候选输入输出依赖图，经语义筛选、模型判断和实际 API 执行验证边；采样连通调用序列、执行并记录参数与响应，再反推高层目标和答案，形成微调数据。评价：比较多个目标导向工具调用基准，并构造含人工核验的 GOATBench。局限：数据质量仍依赖 API 的可用性、构造的数据和生成的目标是否真实；并非科学结果标注。NBDB 启发：可用受控工具依赖图合成可回放训练轨迹，另留真实科研问题和人工科学验收作独立测试。ACL Anthology

AgentEvolver: System-Wide Self-Evolution Through Task Execution（2026，预印本）

问题：Agent 完成一次任务后，怎样将过程中改进的组件用于以后的工作，并且追踪它究竟是否有效？做法：保持基础模型固定，把工具、技能、Agent、工作流、连接器、环境、记忆和插件纳入统一的版本生命周期；候选变更经基线比较、评估与保留，再供后续任务使用，Runtime 保持计划和可恢复上下文。评价：作者自报 SWE-bench Pro Public 有/无演化对比及 6 个历史应用案例，包含未完成和失败例。局限：论文说明逐题原始结果、实际运行配置和完整成本未可供核验，不能做配对显著性或独立迁移结论。NBDB 启发：为技能建立候选、验证、版本、使用记录与回滚流程；冻结技能库后再测试新任务。arXiv 预印本

ToolLLM（ICLR 2024，正式会议）

问题：工具库大时，模型既要找对 API，也要完成多步调用，人工覆盖大量接口困难。做法：收集 16,464 个真实 REST API 的描述，自动生成单/多工具指令，利用深度优先搜索产生调用路径，再用数据微调模型；另训练 API 检索器缩小候选范围。输出是 API 调用轨迹及回答。评价：ToolBench、ToolEval 和分布外 APIBench 检验工具使用，依赖自动评估及所选工具环境。局限：真实 API 不代表任何返回均可信，也不能推知覆盖生物软件或复杂文件。NBDB 启发：将科学操作的格式、版本、资源和输入条件纳入可检索工具描述，再用实际执行及领域验证测试。ICLR 论文

MetaAgent（ICML 2025，正式会议）

问题：人工设计多个 Agent 的角色、通信和错误回退成本高。做法：输入任务类型描述，自动设计角色和有限状态机；每个状态定义执行角色、指令、转移条件的验证者和结果接收者，并尝试合并冗余状态。运行时根据状态和检查结果转移或回退，输出协作结果。评价：论文对文字和实际任务比较自动设计和人工设计系统。局限：状态机生成本身仍会出错；文中比较无法替代长作业、并发及科学输出的验证。NBDB 启发：先固定有限任务状态与产物契约，再在沙箱中研究自动生成流程；不可让模型自行绕过科学验证。ICML 论文

ReTool（ICLR 2026，正式会议）

问题：模型不擅长判断何时把数值或符号计算交给代码，又不能只依赖静态范例学习工具策略。做法：输入数学问题，模型先用含代码的合成推理样本冷启动，再通过多轮 rollout 交替生成推理和调用代码解释器，以任务结果奖励训练模型。输出包括推理、代码、执行结果和答案。评价：在 AIME 等数学问题上对照文本 RL、工具方法，观察代码修复等行为。局限：答案可验证的数学问题和开放科学计算的奖励结构不同；成功代码也可能使用不合适的科学假设。NBDB 启发：先选择可回放且有独立参考结果的小任务，比较工具使用质量，防止以执行成功充当科研正确。ICLR 论文

ToolRL（NeurIPS 2025，正式会议）

问题：工具任务存在函数选择、多个参数和调用顺序，最终答案奖励常太粗，如何设计 RL 奖励？做法：系统比较奖励的类型、尺度、粒度及时间分布，并据此设计工具选择与应用奖励来训练模型；输入为工具任务，输出为调用和结果。评价：在多个工具使用基准比较基础模型和监督微调模型，并分析训练稳定性。局限：中间奖励若按错误规则打分，可能激励格式正确但科学不成立的轨迹；数值效果受任务和奖励设置影响。NBDB 启发：把可执行、参数约束、科学验证和成本分别记录，建立专家抽查的奖励审计集，检验奖励投机。NeurIPS 论文

CodeGym（ICLR 2026，正式会议）

问题：固定的工具训练轨迹或窄环境容易让模型对新工具和流程失效，多样可验证的交互环境又难构造。做法：将代码问题中的原子函数或逻辑抽成可调用工具，把静态编程题转为可配置、多轮、可执行和可验证的交互任务，借此进行工具使用 RL。评价：跨模型与不同推理配置，在未见工具使用基准上测泛化。局限：代码环境只覆盖真实系统部分结构，难自动模拟科学参数、测量噪声、长作业或数据质量。NBDB 启发：从版本固定的真实科学工具与小型标准结构构造可重置训练环境，再另设真实外部分布测试集。ICLR 论文

ToolOrchestra（ICML 2026，正式会议）

问题：复杂任务不一定每一步都需要最昂贵模型，如何同时优化解题质量、工具选择和成本？做法：训练较小的协调模型，按请求选择调用其他模型或工具，奖励结合任务结果、效率和用户工具偏好；输出是协调轨迹与最终答案。评价：在 HLE、τ²-Bench、FRAMES 等具体配置中比较成本与准确率，并测试未见工具。局限：论文数字依赖模型、工具、计价和任务设置，不能推断便宜路由在科研上必然可靠。NBDB 启发：记录每步模型和 CPU/GPU、队列等总成本，把质量下限和验证要求作为约束，再与固定路由公平对照。ICML 论文

Agent Lightning v1.0（2026，预印本）

问题：真实 Agent 的交互由运行时管理，训练器若另起一套环境，可能与实际部署不一致；多次模型调用的训练信号也难归属。做法：运行 harness 负责上下文、工具和控制循环，训练侧通过请求与响应衔接 rollout 和优化，研究重分词、样本合并、优势估计等问题。评价：在指令遵循、搜索、编码任务上实验，并提供编码 Agent RL 流程。局限：训练管线可连接现有 Agent 不代表任意任务已有有效奖励；论文仍是预印本。NBDB 启发：若未来训练策略，应记录工具版本、输入和逐次模型调用，保留重现轨迹与任务级独立验证。arXiv 预印本

OpenAgent（ICML 2026，正式会议）

问题：固定工具和测试集上的高分，能否支撑工具接口、用户任务与环境持续变化的真实部署？做法：把开放环境中的变化划分为查询、动作、观察和领域等维度，在受控沙箱中构造分层扰动，比较监督微调和 RL Agent 的退化；进一步研究扰动增强微调。评价：比较不同扰动类型与程度下的工具使用表现，并测试干预效果。局限：受控扰动只能模拟开放世界的一部分，改善不保证对所有真实科研环境成立。NBDB 启发：独立设置新工具、参数更名、格式变化、返回错误及任务无解等测试，不只统计旧版本的成功率。ICML 论文

用户提出一个跨多种工具的科学问题时，系统需要依次解决五件事：知道下一步想查什么；能调用外部资源；读取真实结果并决定下一步；控制长期任务的成本和状态；根据可验证反馈持续改进。这些能力不是一篇论文一次解决的，也不是从旧方法到新方法的线性替代。下面把论文按它们解决的瓶颈排列，再用统一的 NBDB 任务串起来。

贯穿示例：给定蛋白质序列和一个候选结构，用户要判断“结合位点附近的突变是否值得进一步实验”。系统需要先确认结构来源、序列与残基编号；提取突变位置与邻域；计算局部几何与可接近性；比较可获得的参考结构；在结果不足时明确停止并说明需要哪些实验数据。该例是报告自拟的工程研究任务，不是下列论文的实验任务，也不等于可以仅凭结构证明突变效应。
  1. 2022：推理步骤外显。CoT 提示通过示例诱导分步推理，主要解决复杂问题中一步给答案容易出错；它仍无法保证中间事实真实，也不自行操作外部世界。
  2. 2022–2023：与环境闭环。ReAct 将推理、行动和观察交替执行；Toolformer 研究怎样通过生成与筛选训练样本，让模型学会插入工具调用。二者分别主要是运行时控制范式和训练方法，不能当成同一类“框架”。
  3. 2023–2024：规划、反馈、搜索。ReWOO 将计划从工具观察中拆出以减少重复上下文；LLMCompiler 表达依赖并行；Reflexion 用反馈写出下次尝试的经验；LATS 进一步在多个可回放分支之间搜索。
  4. 2023 起：长期上下文和协作。MemGPT 将有限上下文与外部记忆分层；AutoGen 将多角色的消息和控制写成程序；MetaGPT 把标准工序及结构化中间产物引入协作。它们回答不同问题，可以与上面的方法组合。
  5. 2024–2026：把程序和行为当作优化对象。DSPy 从模块、指标和样本自动优化提示等参数；ADAS/AFlow 搜索 Agent 或工作流；Search-R1、ReTool 等把真实工具交互放进训练回合；ACE 等则改进可演化的上下文。注意论文首次公开时间、正式发表时间和代码版本不同。

阅读原则：每篇先看它操作了什么对象（提示、状态、流程、记忆还是模型权重），然后看外部环境与反馈是什么，再看基线是否拥有相同工具、预算和测试数据。优先重现关键实验的变量与评价，避免把一个数字转述成所有任务上的结论。

二、从生成答案到生成下一步：CoT、ReAct 和 Toolformer

核心转折是把语言模型从一次性回答者，变为能与外部环境交互的控制器。

2.1 CoT：中间步骤帮助组织问题，但不是外部证据

Chain-of-Thought Prompting 在示例中同时展示问题、中间推理与答案，让模型沿类似格式生成中间步骤。与只演示输入—答案相比，它将复杂问题拆成一串语言步骤；论文主要考察算术、常识和符号推理，也强调效果与模型规模相关。对应论文卡片与本地原文

局限与工程推论：模型生成“第 42 位残基靠近配体”并不等于它真实读取了结构。步骤文本可以帮助表示计划，却不能替代工具返回、原始记录或独立验证；即使推理看似连贯，错误前提仍可能一路传递。

2.2 ReAct：每一步都可根据真实观察调整

ReAct 原文 将轨迹写成 Thought → Action → Observation 的循环：模型根据当前上下文提出动作，环境执行搜索或交互，工具返回的观察加入上下文，再决定下一步。对 HotpotQA、Fever，论文提供 Wikipedia 搜索、查找和结束动作；对 ALFWorld、WebShop，动作对应任务环境中的交互。本地论文

目标: 检查链 A 突变 42 的局部环境
Action: inspect_structure(structure_id, chain="A")
Observation: 返回链 A 的序列与残基编号；42 缺失
Decision: 停止计算该坐标；查询构建体或请求用户确认映射
Final: 缺失的残基不是已计算的“暴露”或“埋藏”

论文证据及边界：其 PaLM-540B 提示实验中，HotpotQA 的 exact match：CoT 29.4、ReAct 27.4；Fever 准确率：CoT 56.3、ReAct 60.9。组合方法在文中两项指标进一步变化，说明外部工具及交替模式并不自动保证每项问答都强于纯 CoT；任务、检索质量和使用次数都重要。论文的人工错误分析也区分了搜索结果问题与推理错误。这些数值不是结构生物学的性能证明。

NBDB 借鉴：模型决定“下一步要读哪一份结果”，执行层决定“操作是否合法并真正运行”，验证器根据实际文件判定成功；当观察为空、作业失败或编号不一致时，要有明确分支，不能由模型补造观察。

2.3 Toolformer：训练模型决定何时调用，而非仅在提示里规定

Toolformer 原文 提出从大量文本构造工具调用训练数据：先用少量人工示例提示模型在候选位置生成 API 调用；实际执行调用；比较有、无调用结果时原文后续 token 的预测损失，保留能显著改善预测的调用；最后用筛出的带工具标记文本微调模型。论文演示问答、计算器、检索、翻译和日历等 API。本地论文

实验如何读：论文使用经过过滤的 LAMA SQuAD 子集进行补全事实、零样本测试，Toolformer 开启问答工具为 33.8，关闭工具的同模型为 22.1；在 WebQuestions、Natural Questions、TriviaQA 的实验里，作者有意关闭问答工具以避免工具本身直接解答，主要使用 Wikipedia 搜索，结果仍低于所比较的 GPT-3 基线。作者还指出系统不能像交互式 Agent 一样反复改写搜索查询、浏览多条结果，生成训练样本也可能低效。因而检验工具训练应同时记录工具是否可直接解题、没有工具的模型表现及是否能从坏观察中恢复。

关键区别：ReAct 主要规定推理时的交互轨迹；Toolformer 通过离线数据生成和微调改变模型的调用倾向。其过滤信号是“对续写有帮助”，不直接等价于科研结论正确、安全或预算合理。迁移到 NBDB 时，应给训练样本增加真实工具版本、输入前提和独立科学验证；不可把工具返回中的结论自动当金标准。

三、为什么要计划、并行和重规划：ReWOO 与 LLMCompiler

把一次模型调用串行地等待每个工具，容易浪费上下文与时间；但提前规划也会损失适应性。

3.1 ReWOO：计划先写，证据随后填充

ReWOO 将系统拆成 Planner、Worker、Solver。Planner 一次产生带证据变量的计划，如“检索目标结构 → E1”“读取 E1 的链信息 → E2”；Worker 执行工具调用并用前一步结果填充变量；Solver 将计划与收集的证据综合成答案。这样减少每一步重复送入模型的示例和长观察。论文在 HotpotQA 等任务比较 token 使用与质量，其收益属于当时的提示、工具及模型条件；长短工具响应、模型计费和缓存改变后应重新测量。本地论文

它适合前后依赖大致已知、路径中途很少改变的任务。若 E1 显示用户指定链不存在，继续按原计划把 E1 当有效结构参数会放大错误，因此实践中必须给关键节点增加输入校验和有界重规划：等待的不是一段文本，而是一份带状态、类型与来源的证据对象。

3.2 LLMCompiler：从“步骤清单”走向依赖图

LLMCompiler 的 Planner 产生带依赖的任务，Task Fetching Unit 判断哪些依赖已就绪，Executor 并发执行工具；当现有结果不能完成任务时还可触发重新规划。它能边接收计划边调度就绪节点。论文在其比较任务中报告相对 ReAct 最多约 3.7 倍延迟加速、成本最低约为对照方法的 1/6.7（论文称最高约 6.7 倍成本节省）；这些是作者给出的不同测试条件下的“最高”值，不代表任何科学计算都有该倍率。本地论文

结构合法性检查 ────────────┐
序列与编号映射 ────────────┼→ 汇总 → 选择需要的后续计算
参考结构检索 ──────────────┘
映射成功 → 提取局部邻域 → 可接近性计算 → 汇总
任一关键前提失败 → 解释失败并重规划 / 请求信息

同一对象的只读检查可并行，依赖映射结果的计算必须等待；对有写入或昂贵资源的步骤要根据真实依赖、幂等性和资源限额判断是否并发。并行缩短的是关键路径而非所有任务耗时：等待 GPU 队列、传输大文件和科学工具本身的耗时均需测量。比较 ReAct、ReWOO、DAG 时固定模型、工具、输入、可用预算与成功定义，报告任务成功率、p50/p95 时间、实际美元/GPU 时间和失败后的恢复次数。

四、从一次尝试到反馈改进：Reflexion 和 LATS

多一次尝试有时有用；何时改、如何评价、是否允许回退决定了它是否可靠。

4.1 Reflexion：语言反思是一种跨尝试记忆

Reflexion 分为 Actor、Evaluator 和 Self-reflection：Actor 尝试执行任务；评价器输出成功、失败或测试反馈；反思模块把反馈转成可供下一次尝试参考的文字，放入情节记忆。它在论文设置中并不要求用梯度更新模型参数。“自我反思”不意味着其判断必然正确，效果取决于反馈能否指出真正错误。本地论文

读实验的关键：作者在 HumanEval Python 报告 GPT-4 基线约 80.1%、Reflexion 91.0%；同表 MBPP Python 为基线 80.1%、Reflexion 77.1%。文中分析一部分原因是生成测试产生的假阳性：对“生成的内部测试全部通过”的代码，仍未通过最终评测的比例：MBPP Python 约 16.3%，HumanEval Python 约 1.4%。因此不能只摘 91% 宣称“反思总能提升”；生成测试、重试与评估条件构成了结果的一部分。

NBDB 版本：计算失败后记录“哪个前提失败、证据文件、命令返回码、版本、下一次可尝试的条件”，例如“链 A 在这个构建体中缺失；先检查生物组装或选择正确构建体”。区别可重复的输入问题、临时基础设施故障和科学上尚无定论，避免给所有失败贴上“调整参数再试”。经验必须可追溯到确切运行和工具版本。

4.2 LATS：同时探索多个候选并通过反馈选择

Language Agent Tree Search 把选择、扩展、环境反馈、估值、回传和反思组织为树搜索。节点可代表状态或部分轨迹；模型提出候选动作，环境返回观察，价值估计与已得到的结果共同影响下一次探索。它的前提是候选可生成、状态可表示，且评价信号能区分优劣；在不可回退的真实实验与写操作上不能直接照搬。本地论文

论文 HumanEval 编程实验中，GPT-4 的 LATS pass@1 为 92.7%，其表格列出的 GPT-4 Reflexion 为 91.0%。该 LATS 设置每次扩展采样 5 个候选、最多 8 次迭代，用 4 个生成测试及编译反馈选最终解，再在真实测试上评分。最终报告的“一个答案”背后包含多次候选和测试，因此不能与只采样一次的系统作不计成本比较。

对于结构分析，可以先在可复现的候选计算上使用受控搜索，例如对可行的残基映射提出少量候选，先用序列一致性、缺失片段和结构来源排除，再由独立验证器检验；不要让同一个模型给自己生成的科学主张打高分后直接通过。控制分支数、最大计算量、不可逆操作和人工复核点。

五、长期工作为什么需要分层记忆：MemGPT 到经验维护

上下文窗口再大也不等于研究记录、可信证据和可执行技能可以混成一份聊天摘要。

5.1 MemGPT：有限窗口之外还要能检索、写入和驱逐

MemGPT 借鉴虚拟内存：当前上下文包含系统指令、可编辑工作上下文和近期消息队列；外部有历史召回与归档存储。达到上下文压力阈值时系统发出提醒，较旧消息可被压缩并移出当前窗口，模型可以用函数检索、写入信息并链式调用。论文还用分页避免检索结果撑爆上下文。本地论文

其深层记忆检索实验在 Multi-Session Chat 构造的任务上，论文报告 GPT-4 + MemGPT 92.5% 与该设置的 GPT-4 摘要基线 32.1%。基线看到的是有损摘要，MemGPT 能分页检索完整历史，信息访问条件不同；这是对所设计比较的结果，不能解读成任何长期任务都会提升 60.4 个百分点。

另一条近期路线 MemRL（2026 年预印本）把记忆选择视为效用问题：先按语义相关性找到候选经验，再结合从执行反馈更新的效用估计选择经验；重点在于改变检索的偏好，而不依赖每次更新基础模型权重。对科研工作而言，“历史成功过”不一定适合新的结构家族或软件版本：应按适用条件分组估计效用，并记录更新前后的表现，防止一次偶然成功让错误经验广泛传播。可分别比较仅相关性检索、效用排序以及加入领域适用条件的排序。

5.2 如何映射到科研平台

  1. 事实与原始产物：原始结构、映射表、运行输入输出、版本和时间保存为不可由摘要覆盖的证据，记录内容哈希及访问权限。
  2. 当前工作状态：目标、选定结构版本、链/编号体系、作业状态、待确认问题放入结构化任务状态；通过 API 读取最新状态，而非依赖对话里的一次旧提及。
  3. 经验：检索特定适用条件的成功或失败案例；记录反例、过期条件及工具版本，让错误经验可以撤回和审计。
  4. 技能：经过测试的脚本或工作流与普通文字笔记分开；执行时重新绑定输入，并先检查软件版本与前提条件。
  5. 提示上下文：只装当前决策所需的摘要与证据指针；最终结论应引用可读取的原始产物，而不是只引用模型生成的摘要。

后续 ACE 研究通过生成、反思、整理等组件增量维护上下文，针对反复整体改写可能丢失细节的问题；这仍是上下文适应，不等同于模型权重更新。科研迁移时新增反证保留、来源追溯与旧版本回放，比较“无记忆、摘要、证据检索、带验证经验”在同任务与相同 token 预算下的效果。

六、为什么多 Agent 不是多写几个角色：AutoGen 与 MetaGPT

真正要设计的是各节点的职责、对象、交接条件和失败责任。

6.1 AutoGen：把会话也当作可编程控制流

AutoGen 论文 把一个 Agent 定义为可接收并回复消息的实体；它可以使用模型、工具、人工输入或程序逻辑。开发者配置角色能力，再控制谁发消息给谁、何时回复、何时结束或请求人类介入。论文用代码执行、问题求解等实例展示组合；该设计是对协作接口的抽象，并不证明角色数量越多越好。本地论文

6.2 MetaGPT：把标准工序变成可交接产物

MetaGPT 借鉴软件公司的 SOP：产品、架构、项目和工程等角色负责不同任务，通过结构化文档及发布—订阅机制传递信息；代码可经执行反馈迭代。重点不仅是角色名，而是每一步应产出怎样可被下游检查的对象。其论文 SoftwareDev 表中，MetaGPT 带反馈的 token 用量 31,255，高于 ChatDev 的 19,292；论文同表给出的执行性评分为 3.75 对 2.25。这说明实验里更高质量与更高 token 消耗并存，不能只报道收益。本地论文

对 NBDB 的具体设计：“分析规划”节点输出包含目标、假设、所需输入、计划和停止条件的任务契约；“结构与计算”节点输出只读产物地址、运行记录、工具版本与结果；“科学验证”节点从原始产物重新读取、给出每项通过/失败/无法判断；“报告”节点按证据生成并引用上述对象。验证器可由确定性代码、人和模型共同组成，其中模型审阅不能替代可计算的硬约束。

评估多 Agent 时至少比较：① 同模型、同工具的单 Agent；② 固定工作流；③ 多角色但不使用结构化交接；④ 多角色加类型化产物及独立验证。控制总 token、可运行次数和时间预算，记录交接遗漏、重复计算、冲突解决和科学准确性。这样才能知道收益来自并行、专业化、验证，还是仅来自更多计算。

七、从人工调提示到优化整个系统：DSPy、ADAS 与 AFlow

先确定被优化的对象，再设计训练、验证和未见测试；“自动优化”并不自动避免过拟合。

7.1 DSPy：把提示视作可优化程序的一部分

DSPy 论文 使用签名描述模块的输入和输出，用模块封装推理等调用，再用优化器（论文称 teleprompter）根据示例及任务指标构造和筛选演示、优化程序配置。一个多跳检索程序可由“生成查询—检索—根据证据生成下一次查询—回答”构成；优化对象通常是模块的提示、示例或适配参数，具体取决于使用的优化器，并非自动改正工具本身。本地论文

论文的 HotpotQA fullwiki 实验使用 Wikipedia 2017 摘要索引和 ColBERTv2，隐藏测试集不可用时从官方验证集中取 1,000 条用于测试；报告答案 exact match 与证据段检索准确率。不同论文的检索库、样本、模型或工具条件不同时，不应拿分数直接排名。若在 NBDB 上优化“把用户意图转成任务契约”，可用标注过的目标、实体、残基映射和缺失信息评分；开发数据只负责选择配置，最终测试要按蛋白家族与任务来源分组隔离。

7.2 ADAS / AFlow：进一步搜索流程结构

ADAS 的 Meta Agent Search 用模型提出新的 Agent 程序，执行候选并依据开发任务反馈维护已有候选，再继续提出变体。AFlow 则把工作流表示为由操作节点及连接组成的图，用蒙特卡洛树搜索，在候选工作流代码上进行修改，并以执行反馈评估候选。两者都把“Agent 如何组成”当作搜索对象，但候选空间、执行成本、反馈以及最终保留机制不同；实现细节要看论文和对应版本。ADAS 原文 · AFlow 原文

两篇如何做实验：ADAS 在 ARC 的一个简化子集里从最大尺寸不超过 5×5 的公开训练简单子集抽取 20 道题作为搜索验证、60 道作为测试，每个候选在验证及测试集合上各评估 5 次；该研究还报告了所有发现的候选在测试集上的表现，因此研究复现时应避免利用这些测试结果反复选模；它让 Agent 写出网格转换代码并在示例上执行。AFlow 每个搜索树节点代表一份完整工作流，先选择已有候选，令模型修改提示或节点连接，再在验证集执行 5 次并把性能和修改经验传回搜索树。AFlow 的一次搜索包含多个候选和多轮执行，部署最终工作流的成本与搜索阶段成本需要分别报告；多次查看验证集也会产生选择偏差，所以应保留最终未参与搜索和反复选模的独立测试。

科学迁移的边界：自动产生任意代码、命令或工作流会使成本与风险迅速扩大。建议搜索空间只开放已登记、经过契约检查的操作与有限连接；搜索算法只能在开发集运行，最终候选必须通过独立测试、工具环境检查、数据泄漏检查与权限约束。优化指标同时包含科学正确性、可复现性、计算开销及失败处理，不能单纯奖励“输出了一段结论”。

八、近期趋势：把工具使用带进训练，而不仅在推理时写规则

训练能改变调用策略，但需要真实环境、可追溯奖励和跨分布验证。

8.1 Search-R1：检索是训练回合的一部分

Search-R1 在多轮生成中允许模型发起搜索、接收文档、继续推理和输出答案；通过基于结果的强化学习更新模型行为。训练时检索返回的 token 是环境提供的观察而非模型动作，论文对这些 token 的损失进行遮罩，避免把它们当成需要模型学习生成的动作。文中 Qwen2.5-7B-Base 的特定 PPO 对照中，有遮罩与无损失遮罩的七项问答平均分别为 0.431、0.343；这是该表的任务和训练设置，不能推广成任意结构计算上的提升。本地论文

8.2 ReTool 与模型/工具编排

ReTool 将实时代码执行嵌入推理轨迹，并以多轮执行结果作为训练反馈，研究何时及如何使用代码解释器。ToolOrchestra 进一步研究较小编排模型如何选择其他模型及工具，以任务表现和效率为目标。二者提醒我们：要训练的可包括“选择工具、决定何时停止、决定是否使用更强模型”，而不只是输出格式。ReTool 原文 · ToolOrchestra 原文

对 NBDB 的训练顺序建议：先保留真实运行轨迹与专家修订，并冻结科学验证器；用轨迹检验一个不训练的基线；构建可回放的沙盒，记录动作、观察与可复现的最终结果；再试小规模监督学习或离线策略改进；有足够可信的反馈及预算后才考虑在线 RL。真正科研任务经常没有简单的单一真值，奖励必须区别“运行成功、结构一致、预测有参考价值、实验已证实”，防止模型为了分数滥用工具或选择容易评分的样本。

九、把历史变成能开发、能发表的研究设计

提出明确机制与可证伪假设；每个创新点都要有同预算基线和独立科学证据。

9.1 一条端到端候选架构

输入：任务目标 + 结构对象/序列 + 用户权限 + 预算
1. 任务契约：解析对象、链、编号、期望产物、缺失字段
2. 能力选择：检索登记工具，校验输入/输出类型及版本
3. 计划：确定可并行节点与依赖、每步验证器、停止条件
4. 执行：短任务工具调用；长任务提交→回执→轮询/恢复
5. 验证：检查文件、坐标/序列映射、方法适用前提与指标
6. 决策：验证失败时区分可重试、需重规划、需用户补充、不可判断
7. 产出：结果 + 不确定性 + 溯源清单 + 可复现运行配置

这条架构将 ReAct 的观察循环、LLMCompiler 的依赖调度、MemGPT 的分层状态、MetaGPT 的交接契约结合，但它是本报告的设计提案，尚未证明是某平台当前能力，也没有论文实验替它背书。

9.2 可检验的三个研究问题

RQ1：科学类型和前置条件能否减少“完成但科学上不可用”的结果？提出结构对象、链与残基编号、实验来源、置信度与工具适用条件构成的契约。对比只用自然语言描述工具、增加 schema、增加科学语义约束三个版本。主指标是独立审查的有效产物率；同时报告错误调用、漏拒绝和额外执行成本。

RQ2：基于验证的局部重规划能否比盲目重试更可靠？对模拟的缺链、编号偏移、不可用参考、工具超时、低质量结构设置已知故障；对比直接停止、固定次数重试、模型自由重试、类型化反馈加有限重规划。报告恢复成功率、错误恢复率、每成功任务资源成本以及误把不可判断说成成功的比例。不同故障的可恢复性应由领域专家预先标注。

RQ3：带来源和适用条件的经验是否可以跨结构家族迁移？比较无经验、普通摘要、带来源证据的经验库、加过期与适用性检查的经验库；按蛋白家族、实验方法、时间分割，避免高度相似结构同时进入训练和测试。测经验召回的正确性、科学成功率、检索噪声与失败分布，检验过时经验是否比无经验更差。

9.3 论文实验最少要报告什么

给出任务采集和专家标注流程、样本量与分层、排除规则；固定模型版本、工具版本、数据快照、权限与预算；用配对任务比较并给置信区间，报告失败和人工介入；把 prompt、协议、环境、轨迹、评测程序及可公开数据归档；对不可公开数据提供可复现的脱敏或替代案例。消融至少覆盖检索、契约、验证、重规划和经验组件，另比较单 Agent 与固定流程。报告支持结论的证据范围及失败案例；“接了很多软件”和“模型讲得像专家”本身不足以证明科学发现。

专题教程 / 深度解析

十、完整走一次：同一结构任务在不同架构下会怎样执行

以下是假设性示例，状态和数值用于解释设计，不是论文实验结果，也不是对任何具体蛋白的科学结论。

假设用户上传一条蛋白序列、两个候选结构，提出“分析序列第 42 位附近的环境并比较两个候选构象”。分析系统要在合适条件下完成结构映射、局部统计、比较和验证；如果输入不足，需要给出明确的缺失信息。先看过程，再理解为什么同一任务里不同论文的方法可以组合。

第 1 步：把自然语言变成可检查的任务契约

{
  "目标": "比较候选构象的第 42 位局部环境",
  "对象": {"序列": "sequence_asset", "结构": ["candidate_A", "candidate_B"]},
  "残基位置": {"用户编号": 42, "编号体系": "待核验"},
  "预期产物": ["两份映射表", "局部指标表", "计算与验证报告"],
  "预算": {"最长时间": "用户或平台设定", "最大工具次数": "运行前确定"},
  "停止条件": ["无法建立可靠映射", "必要输入缺失", "超预算"]
}

这里的对象名、字段与协议只是伪代码，具体接口由平台实现。无论后端用哪个 Agent 框架，先确定“用户第 42 位”指完整序列还是结构文件中的作者编号；PDB 文件中的链标记、插入码和缺失残基都可能使简单的整数对应失效。模型只负责提出候选解释，序列比对和映射程序提供具体映射，若仍有多种可行对应要标明不确定。

第 2 步：生成初始计划，但给未知留出口

可先并行读取两个结构的元数据、链序列和结构完整性，再对每个结构做序列—结构残基映射；映射有效后分别提取邻域、计算同一套指标，最后比较与验证。涉及结构来源与数据质量时应保留原始值、计算方法、参数和适用范围，供后续研究者重跑检查。假设两个只读结构检查可独立并行，体现了 LLMCompiler 的依赖图思路；假设计划以 evidence_1、evidence_2 指代未取得的数据，体现了 ReWOO 的计划—证据分离。实际执行者应等待输入完成并验证数据类型，不得把证据变量当作已知结果。

第 3 步：观察与异常分支

假设 A 映射成功，B 对应位置缺失。ReAct 式控制器读到 B 的真实状态后有几个选择：① 查询是否有另一条链或另一种构建体；② 用户确认允许分析其他结构；③ 输出“B 的对应残基不在可用坐标中”，停止对 B 的局部几何计算。哪条可用要由实际数据判断。对于可恢复的调用错误，可记录一次错误和限制重试次数；若是科学上缺少坐标，重复运行同一计算并不会产生该坐标。工具返回应包含 structured status、输出位置、错误类别和版本，不只是一段自由文本。

第 4 步：生成候选不等于判断有效

若存在两个序列相似但编号不同的映射候选，受控搜索可让系统提议两个分支；每个分支先检查序列比对、插入/缺失、链与构建体、位置上下文，并把支持证据与不一致之处列出来。能机械检查的约束由确定性验证器检查；剩下的歧义转给有上下文的人，而不是让另一个模型凭措辞为首个模型背书。LATS 式搜索最适合有明确、成本可控的评价及可回放状态的情况，否则多分支只是多次猜测。

第 5 步：交付可重复、可反驳的结果

结果至少包含：结构来源及版本、目标序列、链和残基映射、计算选择及参数、具体结果文件及其生成运行、质量限制和无法完成的计算。每条表述都应能对应输入、方法、结果或领域解释；如果没有实验效应数据，报告应说“该结构分析提出待检验的线索”，不应写成“突变改变活性已被证实”。对于某个计算不可执行，用户应能继续其他独立任务，并看到任务状态而不是一个看似完整的自然语言总结。

同一任务的四组对照

A 固定工作流：对已知正确的结构和映射固定执行计算，作为上限清晰的成本基线。B 单 Agent 闭环：模型在观察后选择下一步，检验动态决策价值。C 工作流 + 受控重规划：固定可确定节点，只在映射不确定、作业失败时开放有限选择。D 多角色 + 独立验证：与 C 使用同一工具和总预算，在规划、执行、验证间显式交接。比较任务契约正确率、科学有效率、适当拒绝率、时间、人工介入和算力，而不是比较生成报告的长度。

专题教程 / 深度解析

十一、怎样让工作成为一篇可信的论文

从机制、实验到结论逐层建立因果证据；避免把系统功能清单当作研究贡献。

11.1 先写清楚核心假设、适用范围和反例

以“科学契约减少错误结果”为例：假设是相同模型、工具和预算下，显式对象类型、前置条件及独立验证使结果有效率提高，尤其是在编号不一致、缺失坐标和工具适用范围错误的任务上；反例是检验器自身有错、任务超过它的规则覆盖、输入难度很低或增加延迟导致更少任务完成。提前列反例，是为了让消融能测试机制，而不是只寻找成功故事。

主要指标必须可操作：有效完成率 = 满足预先定义的科学与产物条件的可完成任务数 ÷ 全部标注为可完成的任务数。不能只在产生报告的任务中计算通过率；中止、超时和错误报告都在对应分母内。无解或信息不足任务的正确拒绝率单独计算，也可另外报告全体任务的正确处置率；可同时报告适当拒绝率、无根据断言率、产物覆盖率、独立专家一致率。模型自评分可作为辅助信号，但不应独自裁定科学有效性。

11.2 设置能定位原因的实验

在同一组任务上安排：基线 1 为固定流程；基线 2 为共享工具的单 Agent；基线 3 增加结构化输入输出；候选 4 再加前置条件；候选 5 再加独立验证与有限重规划。逐项开启可以识别收益来自哪一部分。重要混杂因素包括模型规模、采样次数、可用文档、工具数量、回合数、检索索引、单任务预算以及测试者对结果的可见性。预算可做两个视角：固定每次运行成本比较效果，以及固定有效率比较资源消耗。

研究数据需覆盖正常、缺失、矛盾、超出方法适用范围及资源失败情形；训练/调参与最终测试按任务和结构家族隔离，若有同源泄漏还需检查相似性。固定数据快照与索引，明确是否包含公开论文或目标答案。工具输出随机时记录种子和软件版本；闭源模型不可完全重现时记录调用日期、版本标识、提示与多次独立运行的波动，并说明重现限制。

11.3 统计与呈现

对相同任务的两套方法可用配对差值估计，并按任务或蛋白家族作适当聚类重采样求置信区间；若样本有限或失败稀少，应呈现原始数量与区间，而非只用百分比。对每项主要指标事先定义任务权重，避免某类简单问题主导平均数。复杂科研结果最好安排至少两名领域人员按预先定义的准则独立盲评样本，并报告评分一致性、分歧及裁决方式；计算可自动检验的部分仍需提供独立程序。

文章的结果部分除总体性能外，应展示成本—效果曲线、异常情形、工具和对象类型分层、失败案例及每个组件的消融。实验不支持假设时同样要如实报告。部署后再收集真实用户任务和反馈属于下一阶段，不应把实验中的代理指标直接解释为科研发现数量或实验成功率。

发展脉络：瓶颈如何推动方法变化

从真实反馈、计划、经验与分工，走到可优化系统、行为训练和持续运行。

以下按瓶颈组织，时期有重叠。规划、记忆、协作和训练通常组合使用，每条路线都要接受任务与成本检验。

2022—2023：把真实世界反馈接入模型

从“能解释”走到“能行动并观察”

当时的瓶颈：模型可以写出流畅推理，但缺外部信息、精确计算和环境状态。

方法怎样改变：CoT组织推理；ReAct让行动获得新证据；Toolformer探索把调用行为学进模型。

代价与局限：增加了API调用和错误面；语言中的计划与工具产生的事实必须分离。

留下的问题：工具一多、任务一长，串行循环开始暴露时延、依赖混乱和上下文增长。

何时采用：先用最小闭环验证任务是否能跑通；不能一开始就靠多Agent或训练掩盖工具问题。

CoT ↗ ReAct ↗ Toolformer ↗

NBDB 例子：自然语言请求→查实体与结构→真实工具返回→基于证据回答，是第一条可评价基线。

2023—2024：把行动变成可管理的计划

从逐步决策到依赖图、并行与受控搜索

当时的瓶颈：每一步都重新推理太慢；漏步骤和错误路径也会随任务长度放大。

方法怎样改变：Plan-and-Solve先分解；ReWOO用证据变量分离计划与执行；LLMCompiler按依赖并行；LATS对候选路径搜索。

代价与局限：预计划牺牲适应性，搜索消耗预算，并行需要资源与依赖正确；不存在单一最优。

留下的问题：规划不能包办所有不确定性；失败经验和成功技能需要跨任务保存。

何时采用：稳定步骤用DAG，不确定边界用反馈循环；只有能廉价验证的分支才搜索。

Plan and Solve ↗ ReWOO ↗ LLMCompiler ↗ LATS ↗

NBDB 例子：多结构质量检查可并行，电镜重构/精修等结果依赖强的环节应分阶段观察和重规划。

2023起，2025—2026继续深化：把经历转成可用能力

从反思文本、技能库到结构化记忆和经验效用

方法怎样改变：Reflexion记失败，Voyager记可执行技能，MemGPT管理上下文层次；A-Mem组织关联，ACE增量维护经验，Plan Caching复用计划，MemRL按反馈学习记忆效用。

留下的问题：记住并不等于记对；需要独立验证、来源、适用范围和失效规则。

何时采用：确有重复流程和可验证反馈时加记忆；先比较简单检索，不直接上复杂自演化网络。

Reflexion ↗ Generative Agents ↗ Voyager ↗ MemGPT ↗ A Mem ↗ ACE ↗ Plan Caching ↗ MemRL ↗

NBDB 例子：事实记录、流程经验、代码技能分别治理；成功轨迹可提炼为版本化分析模板，不能自动修改原始科学数据。

从自由对话到角色、产物和状态机

当时的瓶颈：不同专业、权限和上下文难都装在一个执行者里；简单串聊又会传播错误。

方法怎样改变：AutoGen提供可编程协作；MetaGPT用SOP和交接产物；MetaAgent自动构造FSM来控制多Agent动作和转移。

代价与局限：通信成本、共享错误、职责空白、上下文不一致和终止困难。

留下的问题：角色越多不必然越强；组织方式本身需要评价和优化。

何时采用：有独立可交付子任务、工具隔离或并行价值时使用；保留统一状态和仲裁/验证。

DSPy ↗ ADAS ↗ AFlow ↗

NBDB 例子：在固定回归任务上优化实体解析、工具候选、报告证据模块，不让生成器直接改写生产作业。

2025—2026：让模型学习何时检索、何时计算、怎样用工具

从静态示范到可执行数据与多步RL

留下的问题：训练与真实部署不一致，环境变化、费用和长程运行仍会导致失效。

Search R1 ↗ ReTool ↗ ToolRL ↗ GOAT ↗ CodeGym ↗

NBDB 例子：先用短、可回放的结构验证任务学习，再测新蛋白/新工具/新参数；不要用“程序退出0”当科学奖励。

留下的问题：当前开放问题是长期独立任务迁移、总开发成本、环境变化与演化后的回归。

ToolOrchestra ↗ Agent Lightning 1 ↗ OpenAgent ↗ AgentEvolver 2026 ↗
