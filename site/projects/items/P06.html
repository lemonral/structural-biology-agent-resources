P06 / ARCHITECTURE & IMPLEMENTATION REVIEW
应用与科学系统架构资料与源码入口核对

OpenHands

当前OpenHands/OpenHands仓库主要负责Agent Canvas工作台；执行服务、工具与会话运行在独立software-agent-sdk中。将多仓库边界弄清，才能准确学习其系统架构。

GitHub 仓库 ↗官方文档 ↗上手入口 ↗
1 架构与抽象2 一次任务怎样运行3 状态与部署4 源码阅读5 动手与选型
01 / COMPONENT VIEW

核心抽象：每层究竟负责什么

01

Canvas与交互状态

工作台呈现会话、文件及运行事件，保存客户端相关状态。客户端看到的进度不应被当成执行服务的全部事实。

02

Agent Server适配

API适配层连接执行服务并处理兼容、配置与事件。它是前后端契约的重要入口，可用于理解断线或版本不一致的行为。

03

SDK与自动化边界

Agent Server和运行语义归SDK，定时或事件调度又归自动化仓库。系统要分别回答何时执行、执行什么和怎样展示。

02 / RUNTIME VIEW

沿一次任务，从输入追到实际交付

  1. STEP 01

    用户在Canvas选择执行服务并提交任务。

  2. STEP 02

    客户端通过服务接口创建或继续会话。

  3. STEP 03

    执行服务运行Agent与工具，并返回事件和产物。

  4. STEP 04

    Canvas展示结果；后端真实性与领域检查独立完成。

03 / STATE & DEPLOYMENT

系统状态、执行环境和失败边界

数据、状态与恢复

客户端store、服务会话、工具事件和工作空间要区分。断开浏览器不等于取消任务，重连后应取得服务端真实状态。

部署形态与依赖

工作台、Agent Server和可选自动化服务可以分开部署。当前目录结构与旧单仓库教程不同，先确定每个组件版本和接口。

工程取舍

适合学习完整执行产品的服务边界与交互；照搬工作台并不能得到科学后端。跨仓库接口变化也带来集成与兼容测试成本。

04 / SOURCE READING

源码阅读：从具体入口进入实现

从agent-server-adapter与会话store进入，再按官方仓库边界阅读SDK；不要把前端仓库当作完整Agent运行实现。

已核对的源码入口函数或类型线索读代码时回答什么
src/api/agent-server-adapter.ts ↗DirectConversationInfo、resolveMaxIterations、RuntimeServicesInfo、parseRuntimeServicesInfo、fetchBackendServerInfoAgent如何装配模型、工具和上下文，下一步由谁决定？
src/stores/conversation-store.ts ↗ConversationTab、ConversationMode、CommitsPaneSection、MessageToSendTarget、IMessageToSend什么被保存、怎样更新，恢复时依据哪些状态？

入口文件已按目录核对并读取内容；函数/类型线索为静态提取，不代表已运行全部代码。 阅读链接固定到所记录提交。

  1. 先看最小示例的输入、工具和返回值，建立对象对应。
  2. 沿入口追一次真实调用，区分模型决策、程序执行与外部状态。
  3. 再读测试与错误路径，确认接口合同和版本限制。
05 / PRACTICE & DECISION

用小任务检验是否适合，而不只记住功能名

一个与课题相关的练习
本导读建议，非原项目实验

模拟一个长分析任务，在界面断线后重新连接，验证进度、产物和失败状态来自同一服务端任务，而非旧的前端缓存。

练习交付物要证明什么
任务合同输入、输出、对象、接受标准及必要依赖明确。
运行与产物记录真实操作、状态和文件来源可追溯，失败不会伪装成成功。
独立检查报告实现了什么、什么未通过，哪些结论仍受证据限制。
