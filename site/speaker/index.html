大家好，今天我介绍的是一个面向结构生物学计算的通用 Agent。实际研究中，一个问题往往需要经过结构文件检查、对象选择、工具调用、结果比较和科学解释。工具本身已经很丰富，但把这些步骤准确地接起来，仍然需要研究者处理大量细节。

我希望开发的系统，能够把自然语言问题整理成定义明确的计算任务，调用合适的专业工具，并交付可以核对输入、方法、数值和限制的结果。我们会先梳理已有方法与项目，再说明准备实现什么、怎样实现，以及如何用实验判断系统是否可靠。

这份材料既包含技术综述，也包含项目方案。目前已经完成的是固定流程的结构计算教学原型与策略逻辑测试，真实模型驱动的完整 Agent 及其性能仍需后续开发和评价。讲解中我会持续区分已有研究、本项目的实算结果和拟开展的工作。

原理、架构设计、实现与验证 第 001 / 168 页

结构生物学通用计算 Agent

课题目标是把自然语言研究问题转成受约束、可执行且可核查的结构分析。

可直接讲述

今天介绍的课题，面向结构生物学研究中一个很具体的困难：研究者提出的是科学问题，真正执行时却需要确定数据对象、选择方法、组织软件，再判断结果能支持什么结论。现有预测模型和专业工具已经提供了很多能力，我希望构建一个通用计算 Agent，把这些能力组织成研究者能够使用和复核的分析流程。

这里的通用，指在已验证的能力范围内处理不同对象，并组合已有工具解决新任务。系统应交付任务规格、实际计算产物和有证据支持的解释。接下来会介绍技术现状、课题定位、实现方案以及评价方法。目前已经完成的是固定流程的结构计算示例，真实模型驱动的完整 Agent 仍属于待开发、待验证的部分。

语言模型、工作流与 Agent

系统形式的关键区别，在于谁决定下一步以及结果是否来自真实执行。

可直接讲述

同一个结构问题，可以用三种方式处理。语言模型可以根据已有上下文给出文字回答，但这不一定包含坐标读取。固定工作流在输入和方法已经确定时，按照预设依赖执行真实计算。工具 Agent 则会读取新观察，例如发现链选择缺失，再决定先澄清还是进入计算。它们在控制路径和事实来源上有不同职责。

这三种形式能够组合。固定工作流的某个节点可以调用模型，Agent 也可以把一套已经验证的科学流程作为工具。对于稳定的叠合算法，不需要每一步都让模型重新决定。我们真正要找的是哪些地方必须根据当前对象和工具结果改变后续动作，再把动态决策放到这些位置，避免无必要地增加费用和不确定性。

状态、行动与观察怎样组成闭环

Agent 的基本循环是读取状态、提出动作、执行工具并用真实观察更新状态。

可直接讲述

这一页介绍通用 Agent 的基本机制，先建立后面讨论方法所需的语言。状态是一份程序记录，保存目标、已确认对象、已有产物和剩余预算。策略读取状态后提出动作，执行器检查并实际运行，工具返回的结果成为观察。系统把观察写回状态，再判断是继续、澄清还是结束。右边代码就是这个过程的概念表达。

放到结构比较中，先检查两份文件，得到真实的模型和链清单。发现多条链属于观察，选择作者编号中的 A 链属于后续决策，需要有用户要求或声明的选择规则。确定对象和映射后才能比较。请求执行、工具确实完成以及模型如何解释，要分别保存。本页控制轨迹用于教学，目前没有运行模型驱动的完整循环。

CoT：中间过程提示的收益与边界

CoT 通过中间步骤示例帮助任务分解，关键科学量仍需工具验证。

可直接讲述

CoT 关注一个基础问题：直接给答案时，模型可能漏掉推导关系。原论文在少样本提示中展示问题、中间计算和答案，让模型以类似方式处理新题。变化发生在提示和生成过程，模型权重没有更新。研究在算术、常识和符号任务中比较标准问答与 CoT，并检查模型规模和示例配置的影响。

对我们的启发是，可以把复杂需求明确分解，例如先检查对象，再分析整体和区域差异。但模型写出这些步骤，仍然没有证明它读取了坐标或算出了 RMSD。原论文的收益也依赖具体模型与提示，并非所有条件都稳定。因此在本课题中，过程描述可以帮助组织任务，数值和对象事实则要由真实工具产物支撑。

每个问题都需要先定义目标量，也就是最后究竟要估计什么。例如有效任务科学通过率的差值，可以作为主要效应；对象错误率、误拒和总成本则解释收益来自哪里、付出了什么代价。只展示一条成功修复轨迹，不能估计整体收益。

这些都是待验证的研究假设。主次指标、任务权重、比较方法与接受门槛应在看到冻结测试结果之前确定。最终结论也必须绑定被测任务分布和系统版本，不能由单例成功推广到所有结构生物学问题。

可直接讲述

07 实验设计与统计分析 第 110 / 168 页

07 实验设计与统计分析 第 111 / 168 页

工程故障实验与恢复判据

比较两个系统时保留相同任务与重复槽位的配对。相同 repeat 编号不保证模型产生相同随机输出，也不保证 API 完全确定。尽量记录版本、参数和时间块，并交错或随机安排系统顺序，降低服务漂移和负载的影响。

可直接讲述

公式按每题预分配的 n 次试验和其中 c 次成功计算，只有 k 不超过 n 才能估计，之后按题汇总。内部工具尝试不等于完整独立试验，不同任务难度和服务漂移也影响解释。主结果仍应先报告单次科学通过率和总代价。

很多科学错误发生在计算开始之前。例如使用晶体不对称单元还是生物学装配体，选择作者编号还是标准编号，怎样处理缺失坐标和替代构象，是否保留配体、水和离子，都会改变实际参与分析的对象。把这些步骤统称为清理，并不能让影响消失。

因此输入报告要保存原始文件摘要、选择表达式、选中数量、排除原因和预处理后产物摘要。缺失部分如果经过补全，就形成了新的计算模型，也要记录方法与版本。规则已经明确、处于授权范围内的默认值可以自动应用；对装配体或关键选区存在实质歧义时，再提出决定性澄清。这样研究者能够看清实际分析了什么，并追溯到原始输入。

10 运行部署与实施注意事项 第 160 / 168 页

失败处置：恢复运行，也保持问题的原意

故障处置要按错误类型推进，恢复不能通过偷偷改变研究问题来取得成功。

可直接讲述

错误类型决定下一步。空选择或映射歧义需要检查对象，必要时只询问关键缺参；瞬时网络和排队故障可以在总预算内有界重试；提交后没有响应要先查真实后端；数值无效或科学条件未满足，则要做领域诊断。越权动作应拒绝，只有独立且仍符合原任务的合法分支可以继续。

这里最需要守住的是问题原意。如果用户指定比较某个结构域，系统不能因为结果难处理就偷偷换成另一块区域；也不能降低阈值，反复计算到检查通过。科学对象或方法实质变化，需要明确记录并取得研究者认可，形成新的任务版本。状态名应与实际后端协议一致，未知、失败、拒绝和未定也要分别向用户说明。

通用Agent可以共享执行协议，每类科学任务仍需自己的前提、验收器和允许结论。

可复现交付：别人能重放，也能判断差异来自哪里

可复现交付保存输入、方法、执行和验证依据，并为随机过程声明可检验的等价标准。

可直接讲述

主报告最后落到交付。别人要核查结果，至少需要知道原始输入和选择是什么，方法与环境是什么，执行了哪些尝试，产物来自哪里，以及用哪个检查器接受了结论。四列信息把研究意图一直连接到最终报告，不能只交一个数值或一张图。

复现标准也要分情况。确定性数值内核可以按独立实现、不变量和预定容差核查；模型行为或随机搜索则需要记录版本、参数和种子策略，并通过多次运行报告分布。种子不能保证跨环境逐位一致。如果输入或版本变化，要先解释差异再验证。当前已完成的案例和夹具提供了可核对起点，后续要用同样的证据要求检验真实Agent与扩展任务。
