第001页　结构生物学通用计算 Agent
原理、实现、评估与安全
本页主旨：课题目标是把自然语言研究问题转成受约束、可执行且可核查的结构分析。

今天介绍的课题，面向结构生物学研究中一个很具体的困难：研究者提出的是科学问题，真正执行时却需要确定数据对象、选择方法、组织软件，再判断结果能支持什么结论。现有预测模型和专业工具已经提供了很多能力，我希望构建一个通用计算 Agent，把这些能力组织成研究者能够使用和复核的分析流程。

第004页　语言模型、工作流与 Agent
01 Agent 原理与方法演进
本页主旨：系统形式的关键区别，在于谁决定下一步以及结果是否来自真实执行。

同一个结构问题，可以用三种方式处理。语言模型可以根据已有上下文给出文字回答，但这不一定包含坐标读取。固定工作流在输入和方法已经确定时，按照预设依赖执行真实计算。工具 Agent 则会读取新观察，例如发现链选择缺失，再决定先澄清还是进入计算。它们在控制路径和事实来源上有不同职责。

这三种形式能够组合。固定工作流的某个节点可以调用模型，Agent 也可以把一套已经验证的科学流程作为工具。对于稳定的叠合算法，不需要每一步都让模型重新决定。我们真正要找的是哪些地方必须根据当前对象和工具结果改变后续动作，再把动态决策放到这些位置，避免无必要地增加费用和不确定性。

讲者提示：比较三行时强调“可组合”。这是控制结构的说明，页面中的对照尚未完成模型实验。

第005页　状态、行动与观察怎样组成闭环
01 Agent 原理与方法演进
本页主旨：Agent 的基本循环是读取状态、提出动作、执行工具并用真实观察更新状态。

这一页介绍通用 Agent 的基本机制，先建立后面讨论方法所需的语言。状态是一份程序记录，保存目标、已确认对象、已有产物和剩余预算。策略读取状态后提出动作，执行器检查并实际运行，工具返回的结果成为观察。系统把观察写回状态，再判断是继续、澄清还是结束。右边代码就是这个过程的概念表达。

放到结构比较中，先检查两份文件，得到真实的模型和链清单。发现多条链属于观察，选择作者编号中的 A 链属于后续决策，需要有用户要求或声明的选择规则。确定对象和映射后才能比较。请求执行、工具确实完成以及模型如何解释，要分别保存。本页控制轨迹用于教学，目前没有运行模型驱动的完整循环。

第006页　CoT：中间过程提示的收益与边界
01 Agent 原理与方法演进
本页主旨：CoT 通过中间步骤示例帮助任务分解，关键科学量仍需工具验证。

CoT 关注一个基础问题：直接给答案时，模型可能漏掉推导关系。原论文在少样本提示中展示问题、中间计算和答案，让模型以类似方式处理新题。变化发生在提示和生成过程，模型权重没有更新。研究在算术、常识和符号任务中比较标准问答与 CoT，并检查模型规模和示例配置的影响。

对我们的启发是，可以把复杂需求明确分解，例如先检查对象，再分析整体和区域差异。但模型写出这些步骤，仍然没有证明它读取了坐标或算出了 RMSD。原论文的收益也依赖具体模型与提示，并非所有条件都稳定。因此在本课题中，过程描述可以帮助组织任务，数值和对象事实则要由真实工具产物支撑。

翻页衔接：当问题需要外部事实时，下一步就是把行动和观察加入求解过程，这对应 ReAct。
讲者提示：把“中间过程提示”解释清楚，不要求展示模型隐藏推理。结构例子属于教学迁移。

第007页　ReAct：把外部观察接入下一步决策
01 Agent 原理与方法演进
本页主旨：ReAct 把外部工具的观察接入后续决策，但观察本身也可能出错。

ReAct 让模型在求解过程中选择外部动作，运行系统执行后，把真实返回提供给下一轮决策。例如，结构检查发现目标链未确定，系统应先处理这个问题；如果发现局部拟合不能回答区域相对位置，就应补充参考区对齐。这里最重要的变化，是后续动作能够受到新证据影响。

右侧是原论文同条件的结果。在所列设置下，ReAct 在 FEVER 的准确率高于 CoT，而 HotpotQA 的完全匹配分数略低，说明工具反馈的收益与任务有关。这些是原论文的模型、提示和工具结果，不能当作当前模型排名。结构轨迹则是教学示意；对象取错或检索不相关的信息，仍然可能沿着这个循环传播。

翻页衔接：既然模型要请求工具，接下来需要区分调用策略、调用格式和真正的执行。

第008页　Toolformer 与结构化工具调用
01 Agent 原理与方法演进
本页主旨：工具调用格式、工具使用策略的训练和实际执行，是三个不同的问题。

Toolformer 研究模型怎样学会使用工具。它先采样候选 API 调用，实际执行，再根据结果能否改善后续文本预测来筛选样本，随后用增强语料继续训练模型。因此，它涉及训练数据构建和模型参数变化。我们在应用开发中常说的结构化工具调用，则主要规定模型如何输出操作名称与参数，两者处在不同层次。

例如，请求中的 chain 字段是合法字符串，只说明格式可以解析，还要检查这个链是否存在于本次文件中，原子映射是否成立，以及方法和单位是否合适。程序完成这些检查后，才能执行并返回真实观察。本课题首期可以复用已有模型的调用能力，把研究重点放到领域检查和执行控制；是否训练策略，要等数据与评价条件成熟后再判断。

第009页　代码作为行动：组合能力与执行边界
01 Agent 原理与方法演进
本页主旨：代码行动增加组合灵活性，也要求明确执行环境、权限和产物验收。

当任务需要循环、多步数据处理或组合计算时，代码可以比逐个函数请求更紧凑。左侧伪代码展示了检查对象、建立映射、选择原子、拟合、评价和保存证据的过程。模型可以提出这样的计算片段，但真正运行代码的是执行环境。环境必须明确允许哪些依赖、能够访问哪些输入、运行多久，以及如何返回错误和输出。

我们还需要区分代码能运行与科学方法适用。一个片段即使正常退出，也可能选错原子或解释错参考系。持久解释器中的旧变量也可能影响下一次任务。因此本课题优先使用有明确输入输出的能力包，是否开放额外代码处理，要用参考任务评价灵活性收益，并保存实际片段、环境、退出状态和产物，供后续检查。

翻页衔接：无论采用函数还是代码，下一步都要把想做的事情表达成能够执行的计划。
讲者提示：代码按职责概括，不逐行念。当前为概念伪代码，不能据此宣称代码行动优于受控函数。
需要强调：代码行动、执行环境、科学验收

第010页　计划的三种形式：文本、证据变量与依赖图
01 Agent 原理与方法演进
本页主旨：计划需要逐步明确操作、结果引用和依赖，才能交给程序执行。

计划可以有不同精度。第一种是文本分解，例如下载、对齐、解释，它表达意图，但还不能直接运行。第二种加入证据变量，先声明检查两份输入，再把真实返回绑定到变量，供后续映射和汇总使用，ReWOO 代表这种规划与结果消费分离的思路。第三种进一步声明操作的输入输出类型和前置条件，形成可检查的依赖图。

在结构分析中，映射操作返回原子对应关系，拟合接收坐标与映射，再产生变换和指标。程序据此可以检查引用是否存在、依赖是否满足。如果实际输入发现歧义，原计划的分支也可能需要改变。因此一次性规划的效率与观察后的适应能力要兼顾，不能假设开放科研问题都能在读取数据前安排完整路径。

翻页衔接：依赖明确以后，可以让互不依赖的步骤并行执行，这就是下一页 LLMCompiler 的重点。
讲者提示：从左到右指出可执行信息逐步增加。ReWOO 仍会消费真实观察，不要说成完全不读工具结果。
需要强调：文本计划、证据变量、产物依赖

第011页　LLMCompiler：让就绪任务并行
01 Agent 原理与方法演进
本页主旨：LLMCompiler 利用依赖关系并行派发就绪操作，收益取决于任务结构。

有些工具调用能够同时运行，例如分别检查两份结构文件；另一些必须等待前序结果，例如建立映射要等两份对象清单都返回。LLMCompiler 用计划器描述操作和引用，由调度部分派发已经满足依赖的任务，再把执行结果回填。这样能够减少不必要的串行等待，也可能减少反复规划时重复发送的上下文。

表中保留原论文的具体条件。HotpotQA 的准确率接近，时延降低；电影推荐的所列设置同时改善准确率和时延。这里应该观察收益发生在哪类任务，而不能直接套用一个最大加速倍数。对结构计算而言，还要测量资源限制和排队时间，而且函数并行调度并不自动解决集群作业的提交确认丢失或恢复问题。

第012页　LATS：用搜索分配更多推断计算
01 Agent 原理与方法演进
本页主旨：LATS 通过搜索多条候选轨迹分配推断计算，必须计入全部内部尝试。

LATS 把部分状态和行动轨迹作为搜索树节点。模型扩展候选动作，选择规则在新分支探索与高分分支利用之间分配预算，环境反馈再更新候选价值。结构案例中，可以设想比较直接全链拟合与先核对科学选区的路径。但开放科研常常缺少即时正确答案，模型给出的价值判断只能作为启发，不能充当科学验收。

原论文的问答实验包含可返回正确性反馈的环境，编程搜索使用合成测试，最终再由真实测试验收。这些条件影响搜索的有效性。还要注意，搜索之后最终提交一个程序，内部可能已经尝试很多候选。评价时需要把全部尝试、工具费用和时间计入预算。昂贵计算或有副作用的操作，也不能像廉价问答分支一样随意回滚。

讲者提示：搜索图是结构任务示意。解释搜索后 pass@1 时，同时指出内部候选消耗。

第013页　RAG、上下文与记忆的不同职责
01 Agent 原理与方法演进
本页主旨：资料检索、当前任务状态和历史经验分别提供不同的信息，不能相互替代。

这页区分三种经常混在一起的信息。资料回答方法依据，例如怎样定义拟合区和评价区，可以检索论文或手册。当前状态回答这次到底用了什么对象、映射和文件，需要解析输入或查询运行记录。历史经验回答过去遇到过什么问题，可以提醒检查编号体系，但仍要核实是否适用于当前任务。它们都可以进入模型上下文。

一个合理组合是：从资料得到方法定义，从文件获得本次真实链和坐标，从经验里发现需要检查作者编号与标准编号的差异，最后由工具计算数值。检索相似度高，不代表方法必然适用；摘要和旧结果也可能丢失输入版本与条件。因此系统应分别保存来源、状态和原始产物，只给当前决策提供必要且可追溯的信息。

第014页　Reflexion：反馈怎样变成跨尝试经验

第032页　置信度、质量与生物学证据

第066页　第二类实际操作：蛋白与配体几何接触

第070页　未知提交与取消：明确模拟的状态试验

第077页　评测轨道与可接受响应

这张表把任务类别落实成产物。输入核对需要对象清单、来源摘要和明确选择；结构比较需要匹配表、选区、变换、指标和单位；参考区对齐需要说明哪个区域决定变换，再在同一变换下评价其他区域。

接触任务则要固定链与配体实例、重原子和距离阈值，并交付规范化的接触表。组合任务把这些操作按依赖连接起来，最后根据科学对象、产物与证据验收，而不是强迫模型逐字复现某条参考调用序列。不同合理工具和计划可以产生等价交付。

当前 AdK 包直接计算了给定映射的比较与配体邻近几何，还没有多对象自然语言任务集。正式任务池需要增加蛋白对象组、输入质量和科学条件的覆盖，并为每类任务准备独立评分。工具数量增加本身不能替代跨对象实测。

翻页衔接：这些任务的公开输入和研究者评分信息，接下来需要分别放进版本化清单。
讲者提示：重点解释必须交付列。不要把待新增结构实例说成已计算，也不预填界面接触数量。

第079页　任务文件：输入、轨道与评分键
06 实验设计与统计分析
本页主旨：公开任务与隐藏评分键分开管理，保证Agent依据题目而非答案完成任务。

左侧是教学任务文件的结构：有案例编号、自然语言问题和任务字段，明确输入、模式、链、单位与映射。正式评测还要增加任务族、对象组、模板、组合、数据划分和版本信息，用于检查重复、组织配对和分层统计。

第080页　任务池构建与标注流水线
06 实验设计与统计分析
本页主旨：任务数量应伴随对象与科学条件覆盖增长，并通过参考计算和复核冻结。

任务池建设从可复现的数据检索开始，保存来源、版本和筛选条件。接着审查科学对象，确认模型、链、组装、缺失情况与可比范围。然后用参考方法或人工核对建立产物，写明哪些结果必须一致、哪些策略可以等价。

第081页　数据划分与泄漏审查
06 实验设计与统计分析
本页主旨：数据划分先识别对象、模板和组合的关联，再按研究目标建立留出测试。

数据泄漏有不同层次。文件和对象层可能重复使用同一结构版本、同一序列或同源蛋白；问题层可能只是改写同一道题；组合层则可能让完整依赖模板在开发时已经出现。不同留出条件回答不同的泛化问题，需要分别登记。

划分前先建立关联组。如果一道题使用两个结构，只要共享任一对象或相关家族，就要考虑把它们连到同一组，再按组划分。序列聚类和分组交叉验证可以帮助执行规则，但它们不会替研究者自动发现所有同源关系、输入共享或模板重复。

开发集用于改提示与工具，验证集用于选择配置和预算，冻结测试在配置确定后评价。对象留出与组合留出可以分轨，也可以建立双重留出，但需要解释难度和覆盖差异。公开结构还可能出现在预训练中，因此新坐标操作能力也要有专门检查。

翻页衔接：即使划分正确，还要提前写清评分规则，保证不同人员和不同实现判断的是同一件事。
讲者提示：顺着对象、问题、组合三层讲。分组不交叉不等于已经证明无同源泄漏。

第082页　标注手册与科学接受规则
06 实验设计与统计分析
本页主旨：科学评分依据对象、数值和证据等价条件，不要求唯一文字或唯一工具路径。

标注手册要把接受条件提前写清。对象层声明模型、命名空间、链、残基和原子，保存显式映射；数值层按具体输出设置容差，先确认对象和单位，再比较数值。非有限值、覆盖不足等情况也需要明确处理，不能因为格式能解析就通过。

集合和文件还有规范化问题。例如接触残基可以按规范身份去重，不因行序不同判错；但距离是否包含四埃边界、使用哪个配体实例和替代构象，都会改变科学含义。RMSD 题也不能简单奖励更小数值，因为拟合范围决定它回答的问题。

合理的澄清、工具和计划可以有多种，评分应接受满足科学条件的等价产物。解释层则要求每条主张能定位到证据，并保留限制。需要专家判断的部分，通过复核和分歧裁决处理，不能用文字流畅或语气自信代替正确性。

翻页衔接：接下来把运行中帮助Agent纠错的检查，与实验结束后判断研究结果的评分明确分开。
讲者提示：选对象、数值、等价策略各举一例。容差必须预先确定，不能测试后为某组放宽。

第083页　运行检查器与外部评分器的独立性
06 实验设计与统计分析
本页主旨：运行诊断用于帮助执行，外部评分用于判断实验结局，两者需要独立性审查。

运行内检查器与外部评分器承担不同职责。前者读取当前任务和产物，快速返回可见诊断，帮助 Agent 判断是否需要修订；后者在系统执行结束后，根据原始任务、隐藏参考、真实文件和完整轨迹作出实验判定，不向被测系统泄露答案。

独立性需要逐项审查。两个程序即使目录不同，也可能共用错误映射；两种数值算法也可能共同选错对象。除了代码，还要核对输入来源、解析器、阈值和人工标注是否共享，再用预构造错误产物测试可能共同漏掉的问题。

当前教学包的运行检查与评分都调用 reference.validate，因此可以演示产物重读和分层评分，不能证明独立科学真值已经建立。正式研究先测检查器的漏检与误拒，再评价反馈修订收益，同时披露仍然存在的共享依赖。

翻页衔接：区分好两类检查以后，下一页把不同机制组合成能够公平比较的基线系统。
讲者提示：以谁能看到诊断、谁能看到隐藏参考作对比。不同API或不同模型都不自动等于独立。
需要强调：运行诊断、外部评分、共享错误、独立性审计

第084页　B0–B5 的受控比较
06 实验设计与统计分析
本页主旨：基线通过逐项开关机制识别增量，并以同信息和同预算排除不公平优势。

这张表建议按机制逐步增加能力。B1 是基础 Agent，保留字段格式检查；B2 加入对象与方法语义约束；B3 进一步做科学检查，但检查后不根据诊断修复；B4 接收科学诊断进行有限修订。B5 使用普通观察和通用自修复，用来控制多尝试本身的收益。

B1 到 B5 使用相同模型、原始输入、领域资料、工具与预算口径。增强组可以更严格执行规则，却不能额外获得人工整理的正确映射或答案。B4 和 B5 尤其需要对齐最大尝试、模型用量、工具调用、计算和时间上限。

翻页衔接：先看最基础的比较，明确语义约束具体阻断哪类字段合法却科学错误的请求。
讲者提示：先讲B1到B4逐步增加，再解释B5和B0的特殊角色。强调当前是实验方案。

第085页　实验 H1：语义约束到底减少什么错误
06 实验设计与统计分析
本页主旨：H1检验可执行语义约束的收益，同时记录它造成的误拒和成本。

H1 关心的是字段合法以后还会漏掉什么。例子一，任务要求作者 A 链，调用却指向 B 链；例子二，任务要求 CORE 参考对齐，模型却调用各区域独立拟合。两种请求都可能通过类型检查，也可能产生看起来合理的数值，但没有完成原问题。

实验让 B1 和 B2 读取相同问题、结构清单与工具说明，只改变领域约束是否由程序强制执行。比较执行前阻断、最终对象与方法错误，以及有效科学交付。结构清单由同一个工具提供，不能只对 B2 增加人工映射或额外知识。

翻页衔接：语义约束之后，下一项实验区分科学检查、诊断修复和普通多次尝试各自带来的作用。

第086页　实验 H2：检查、修复与额外搜索分开
06 实验设计与统计分析
本页主旨：H2先验证检查器，再检验诊断修订相对于只检查和通用重试的净收益。

H2 分两阶段。先把人工核实的有效和错误产物交给冻结检查器，测量错误漏检和有效产物误拒。这个阶段不让模型行为变化干扰检查器质量。然后再做完整 Agent 闭环，比较检查后停止的 B3、按科学诊断修订的 B4，以及通用修订的 B5。

第087页　实验 H3：对象迁移与组合泛化

第088页　负例注入与几何不变性检查
06 实验设计与统计分析
本页主旨：受控负例与几何不变性检查，从已知应变和不应变的关系定位实现问题。

负例注入一次只改变一个可定位因素。例如改链标识、换拟合模式、损坏数值或单位，再检查系统是否按预期阻断。每次保存注入位置、前后摘要和真值标签，才能把观察到的失败归因到这项改变。

另一类是几何不变性检查。给相关坐标施加共同刚体变换后，内部距离和相应的最佳叠合 RMSD 应保持在容差内；保持显式映射的记录重排，也不应改变科学结果。但旋转和平移参数本身可能变化，不能要求所有输出字节完全相同。

这些检查能发现坐标处理、顺序依赖和数值实现错误，还需要避免只构造与验证器规则一模一样的简单负例。距离边界单独测试，容差提前确定。即使不变性全部通过，也仍需审查对象选择与解释是否符合实际科学问题。

翻页衔接：科学负例之外，下一页把超时、失联、重复和取消作为单独的工程恢复实验。
讲者提示：讲一个错链负例与一个共同刚体变换即可。明确科学量不变不等于变换参数不变。
需要强调：受控扰动、几何不变性、保持映射的重排、边界测试

第089页　工程故障实验与恢复判据
06 实验设计与统计分析
本页主旨：真实恢复实验需要核对外部作业与资源事实，模拟状态测试只能验证局部分支。

工程实验可以固定科学输入，单独改变故障条件。例如提交意图已经保存，但外部响应丢失；结果重复到达；取消确认丢失；或者服务进程中断。首先规定每种情况能够获得什么外部事实，再定义何种状态和行为才算通过。

教学包里这些外部情形是模拟，没有实际向集群提交。生产适配器还要在真实后端演练断连、重启、查询和取消，保存外部日志与 JobID。检查点和幂等键提供机制基础，外部系统是否只执行一次仍需事实核对。

翻页衔接：这些实验会产生多层记录，因此接下来先明确一次独立运行和内部尝试各是什么。
讲者提示：严格区分本地fixture与未来真实后端演练。讲通过判据时包含实际作业，不只内部状态。

第090页　运行单位、内部尝试与配对关系
06 实验设计与统计分析
本页主旨：独立启动的运行可能共享科学对象，统计时要保留对象层相关性与系统配对。

这里把统计单位分开。对象组连接共享蛋白家族或输入的任务；基础任务和问句改写表达同一问题的不同变体；每个任务、系统和重复槽位组成预先分配的端到端运行；运行内部的步骤和重试则是 Attempt。

三次工具尝试不是三个独立样本，同一 AdK 上的多个模式和问句也不是多个独立蛋白。重复启动可以估计随机执行的不稳定性，但跨对象推断需要足够的独立对象组。汇总时先聚合基础任务内的重复，再按预定权重计算总体结果。

比较两个系统时保留相同任务与重复槽位的配对。相同 repeat 编号不保证模型产生相同随机输出，也不保证 API 完全确定。尽量记录版本、参数和时间块，并交错或随机安排系统顺序，降低服务漂移和负载的影响。

翻页衔接：明确运行单位后，才能解释多次试验里至少成功一次和每次都成功为什么是不同目标。
讲者提示：用一个任务多次Attempt与多个repeat对比。不要将API seed讲成确定性保证。
需要强调：对象组、预分配Run、内部Attempt、配对比较

第091页　单次正确、候选覆盖与重复可靠性
06 实验设计与统计分析
本页主旨：至少一次成功与每次都成功描述不同可靠性目标，并都需要计入重复成本。

这一页区分两个容易混淆的指标。pass at k 问的是，给同一道题 k 次完整尝试，是否至少有一次成功；记作 pass 上标 k 的指标问的是，这 k 次是否每次都成功。前者描述候选覆盖，后者更接近重复执行的一致性。

如果系统生成多个结果，却没有可靠办法识别哪个正确，至少存在一次成功还不等于实际交付成功。因此使用检查器选结果时，要把选择后的端到端通过率和全部候选成本一起报告。也不能在实验结束后免费挑选最好的一次轨迹作为系统成绩。

公式按每题预分配的 n 次试验和其中 c 次成功计算，只有 k 不超过 n 才能估计，之后按题汇总。内部工具尝试不等于完整独立试验，不同任务难度和服务漂移也影响解释。主结果仍应先报告单次科学通过率和总代价。

翻页衔接：这些指标都依赖清楚的运行配置，下一页把模型、预算和缓存规则固定成机器可读记录。
讲者提示：公式可只解释n、c、k及两个事件，不必逐项推导。不得从平均p直接机械计算各题可靠性。
需要强调：pass@k、pass^k、结果选择器、全部候选成本

第130页　任务、尝试与证据的身份关系
09 运行部署与实施注意事项
本页主旨：Task、Run、Attempt和Artifact表达不同身份，结果必须关联产生它的实际尝试。

这张表解决的是追踪问题。Task及其版本记录研究请求和对象约束；Run表示预分配的一次系统运行，承载配置与总预算；Step是逻辑步骤，Attempt是这一步实际执行的一次尝试。一次Run内的重试会增加Attempt，不会变成新的研究样本，也不会重新获得总预算。

只有调用外部后端时才需要Job，本地同步计算可以直接产生Artifact，也就是实际产物。每个产物要关联产生它的Attempt、方法和环境，验证结果则追加保存。开发实现中，从解析、澄清到规划都归入同一次运行；科学执行前固定任务规格。若后来实质改变研究对象或方法，应建立新的任务版本和关联运行，保留原始请求与已有证据。

第131页　提交确认丢失与 UNKNOWN 状态
09 运行部署与实施注意事项
本页主旨：响应丢失时先核查外部事实，UNKNOWN保留真实不确定性并阻止危险重复提交。

第137页　输入预处理会改变研究对象

第142页　核心术语：实验与统计
附录 B
本页主旨：统计结论取决于目标量、实验单位和分母，重复尝试不能伪装成独立证据。

实验里首先要说明希望测量什么，这就是目标量。例如在固定预算下，两种系统的科学有效交付率相差多少。接着说明什么是一次运行，哪些任务属于同一对象簇。对同一个问题重复尝试，或把一句话改写多遍，不能因此获得同等数量的独立科学对象。

另一个容易混淆的是运行检查器与外部参考。两者若共用实现，可能继承同一种错误；数据划分也要检查同源结构、模板和答案信息是否跨集合传播。置信区间建立在明确的目标总体和抽样机制上，不能把单一AdK簇的重复运行外推到整个领域。最后，有效任务失败与无效请求正确拒绝属于不同结局，要分别定义分母。

【2026-11-09 架构与框架设计补充讲稿】

结构生物学Agent · 架构与框架设计配套讲稿

2026-11-09；设计说明，对照PRD0.2。

本稿用于补充已有PPT相关页，章节编号不是新增幻灯片页码。



01　架构、框架、模型与科学工具的分工

对应原PPT：4、5、29、45、50、74、129页



这里先区分几个容易混在一起的词。架构规定各部分如何协作、事实放在哪里以及失败由谁处理。框架帮助组织控制流程，模型提出理解和候选动作，科学工具才读取实际坐标并计算。这样划分以后，我们才能知道问题来自理解、执行还是结果解释，也能在以后更换框架时保留科学合同。

沿着流程看，一开始就创建分析 Run 并建立总预算，随后在同一个 Run 中预检、澄清、冻结规格，再规划、执行和验证。固定步骤由代码负责，需要新观察时才让模型决策。这一章是对已有 PPT 的补充设计，描述下一步要实现的服务；目前资料站和固定流程示例并不等于完整 Agent 已经部署。



02　首版技术选择与框架取舍

对应原PPT：22、24、25、26、29、54、129页



首版选型的出发点，是让任务能够澄清、挂起、恢复，而且不会丢掉对象和预算。因此主控候选沿用 LangGraph，必要时使用 LangChain 的模型和工具组件。其他框架也有重叠能力，表格说明它们在我们项目中的角色，不是在给产品排高低。科学工具和任务合同需要保持可替换。

配套技术也先保持紧凑：一个 PostgreSQL 保存业务事实和领取队列，受限 Worker 执行固定科学操作，产物写入项目隔离存储。Pydantic 负责格式，领域规则负责真实对象，授权组件负责权限。版本能否一起工作仍需兼容试跑；这里记录设计选择，没有启动新模型服务，也没有完成生产能力验证。



03　九个模块的输入、输出与责任边界

对应原PPT：50、54、55、61、74、129、130页



这九个模块是职责划分，不要求先部署九个独立服务。最重要的边界是，模型提出什么、程序实际做了什么、科学上能否接受，分别由谁负责。输入检查提供真实对象，规格构建明确问题，规划提出候选，编译和授权决定能否执行，Worker 才产生真正的计算记录。

产物与验证保留不可变历史，报告引用这些事实，用户反馈再进入复现和审查。这样一个错误就能追到责任位置：错链查对象与合同，没生成文件查执行，夸大结论查报告。模块之间使用有版本的工件引用和业务记录，不靠几个角色互相说已完成。这是补充架构设计，仍需后续实现和验收。



04　State、业务账本与 checkpoint 各存什么

对应原PPT：5、13、23、24、68、70、90、130、131、133页



这里的 State 可以理解成系统为了决定下一步而准备的工作视图。它保存任务引用、阶段、观察和待补问题。业务账本则保存真实的 Run、Attempt、产物、权限和预算，checkpoint 保存图走到了哪里。它们可以共用数据库，但不能相互覆盖职责，尤其不能让旧的图状态恢复出已经撤销的权限或重置成本。

恢复时先读账本，再核对实际执行和产物，最后恢复图的决策。程序可能已经运行而响应丢失，不能看到旧节点就直接再做一次。页面也要分开展示执行阶段、流程状态和科学接受：计算流程结束，并不自动说明结果科学上有效。这些恢复边界是本项目需要实现和测试的设计，框架持久化只提供其中一部分能力。



05　类型化任务、冻结合同与版本化计划

对应原PPT：33、52、53、56、62、63、74、79、90、92、130页



类型化任务的作用，是让用户的问题能够由程序明确检查。原始请求保持不变，系统在同一个 Run 内预检和澄清，然后在首个科学执行前冻结合同。冻结的是对象、方法意图和接受政策，实际映射或索引可以随后由受控计划产生；不能为了拿到这些产物而在冻结前偷偷启动科学步骤。

计划失败后，如果科学合同不变，就追加新的计划版本，绑定实际尝试并继续使用剩余预算。如果换链、换拟合方法或改变目标，就形成关联的新修订和新 Run，保留原来的记录。格式、科学语义和权限也要分别检查。这里的示例用于阅读现有合同，引用都是占位身份，还不是可提交的运行请求。



06　四个 P0 科学能力包与扩展准入

对应原PPT：47、54、58、60、64、65、66、67、75、139、144页



首版科学内核收敛为四个能力包：检查结构、建立对应、计算 RMSD 和蛋白配体几何接触。每个包都要说明输入、方法、支持范围和接受条件。例如接触需要明确配体实例和阈值，结构比较则要分开拟合区与评价区。把调用接通，只完成了其中一部分，还要核对真实产物与科学前提。

新任务也按同样流程接入：先写科学合同，再固定适配器，建立参考和负例，测试权限资源，最后登记并发布版本。报告生成是交付辅助步骤，不增加新的科学真值。已有 AdK 教学包可以帮助复算和迁移，但本章没有安装这些生产模块，也没有运行真实模型；通用范围要由新增对象和组合测试逐项建立。



07　一次研究问题怎样成为可执行分析

对应原PPT：5、50、52、53、56、63、74、130页



一次分析从用户问题开始，但服务端要先建立Run并固定预算，再调用模型。系统先读取真实结构清单，确认有哪些模型和链。缺少决定性信息时，只补必要澄清，费用和等待状态仍归同一次运行。条件充分后冻结科学规格，明确对象、方法、拟合与评价意图，再让模型提出计划。

计划还要经过程序编译、权限和预算检查，才能进入Worker。实际映射与索引可以在冻结后按既定意图产生，但派发时必须是真实工件引用。计算结束再做科学验证和报告审核。同合同失败可以有限修订，若改变研究问题，就建立关联的新版本。当前页面说明拟建流程，已有AdK数值来自此前固定计划。



08　异步、租约与恢复：账本保存事实

对应原PPT：23、68、69、70、89、130、131、132页



异步的关键是把已经发生的事实留在账本里。API收到请求后先持久化，Controller和Worker即使重启，也能按同一个Run查到操作。用户重复点击用幂等键识别，某次真实尝试用operation_id识别，二者解决的重复不同。租约带递增epoch，避免迟到Worker覆盖新状态。

检查点只说明图从哪里恢复，不证明工具是否已经运行。恢复前还要查数据库、真实进程和产物。文件与数据库也没有共同事务，可能出现文件已写但尚未登记的窗口，因此必须有临时槽、完成回执和协调流程。无法确定执行或计费时保留未知，既不盲目重提，也不把预算重新归零。



09　执行、科学验收、报告审核与实验评分

对应原PPT：55、57、65、66、67、71、82、83、86、94、99、102、124页



一次任务有几种不同的通过。Worker正常结束，只能说明程序执行和产物采集完成。科学检查还要确认对象、映射、拟合与评价范围、单位和实际数值；报告审核再判断解释有没有准确引用这些证据。接触结果可以说明几何邻近，不能自动写成亲和力。授权则独立决定当前动作能不能做。

正式研究还需要外部评分器，根据原始任务和隐藏参考检查最终交付，答案不返回模型。检查器本身先测漏检和误拒，再测反馈修订是否有效。现有AdK包的检查与评分有共用实现，因此只能作为参考起点。新版本的验证结论追加保存，COMPLETED始终不等于科学通过。



10　RAG、运行状态与历史经验怎样进入模型

对应原PPT：13、14、15、23、79、81、101、105、112、118、119、141页



模型每次能看到的信息有限，所以要把几类内容分开。RAG负责找方法依据，工作状态说明这次任务实际进展，工件保存可复算证据，历史经验提醒过去遇到的问题。它们都可以帮助决策，但权威来源不同。论文写着怎样处理结构，不能代替读取这一次文件，更不能扩大执行权限。

Controller每次只提供必要的对象清单、规格引用、工具和最新诊断，同时记录版本。需要压缩时，链、映射、拟合与评价范围、单位和未完成项必须保留，原始数值仍回到工件读取。私有结构和摘要按数据政策处理，凭证留在连接器。记忆与缓存复用也重新检查当前权限，旧经验不能直接变成本次事实。



11　首版部署：模块清楚，基础设施保持最小

对应原PPT：24、29、50、54、74、114、115、116、118、125、129、134、135页



第一版可以从很小的部署开始。API处理用户与权限，Controller组织一个受控状态图，CPU Worker执行固定科学入口，PostgreSQL保存事实和队列，文件存储保存不可变产物。代码可以在同一仓库里，控制和计算进程保持清楚边界，便于独立重启与排查。

计算子进程没有模型密钥和数据库凭证，输入只读，输出专用，并实测网络、内存、进程、磁盘和时间限制。先验证参考计算，再接真实模型与恢复；团队开放前还要验证项目隔离。首版不需要额外队列平台或集群编排；是否扩容由任务和负载测量决定。目前3188提供资料，上述服务还要在确认部署环境后实现。



12　从可追踪到可验收：事件、用量与恢复演练

对应原PPT：68、70、89、90、92、94、97、99、103、108、109、110、121、123、130、131、133、134、140页



观测首先要能够追踪。用户看到的一个数值，应能连到Run、规格、计划、真实尝试和产物，再看到采用哪版检查器验收。界面通过持久事件更新，断线以后取快照并补事件；Trace可以采样，业务事实不能因为采样消失。执行、科学和交付状态也分别展示。

验收要真正打断进程，测试重发、租约过期、文件发布窗口和取消。未确认停止就保留待确认或未知，不直接显示已取消。所有模型和工具费用从原Run创建起累计，失败、澄清和修订也计入。费用未知保持预留，迟到账单追加核对。最后按代表任务测质量、资源和时延，才决定是否开放试点。



13　代码如何组织，状态图如何装配

对应原PPT：50、60、61、63、68、69、74、129、130、131页



这里把抽象架构落到代码组织。API收到请求后，先做身份和项目检查，再把任务写入数据库；它不长期占着请求执行科学计算。控制器推进状态图，模型只在需要理解或规划的节点提出候选，确定的科学操作由Worker运行。这样API重启或用户关闭页面，都不会让执行事实消失。

看这段构图，节点实现由外部注入，所以我们能先用固定策略测接口，再接模型。遇到缺参数或工具未完成，图提交等待事实后立即返回。持久事件再次唤醒同一Run，先读取账本，再决定下一步。首个科学计算之前必须冻结规格，所有解析、修订和报告都使用同一Run剩余预算。这是一份设计示例，还需要实现节点、验证依赖与故障行为。



14　前后端接口与事件时序

对应原PPT：50、68、69、70、129、130、131、133页



前端与后端的关系要尽量简单。前端发出创建、澄清、恢复或取消请求，后端先做身份与项目检查，再持久保存。比如创建Run返回202，只说明系统已经接收并预留资源，不表示计算完成。之后页面分别显示执行状态、科学判断和费用，报告中的每个数值还要能追到实际工件。

实时进度可以用SSE，但页面断线不能中断任务。重新进入时先取Run快照，再从它的事件序号之后补发，重复通知由客户端去重。用户回答澄清和恢复也要带状态版本，避免旧页面覆盖新事实。接口编号沿用PRD，具体字段以canonical OpenAPI为准；这份讲解不会把资料站变成已经上线的执行API。



15　按 M0–M5 分步实现与第一轮开发任务

对应原PPT：60、72、74、75、98、125、129、135、136页



实现顺序按PRD的M0到M5推进。第一轮先把合同、身份和账本固定，再做无模型的科学垂直切片：一份真实输入能产生可复算的结果，错误对象和单位会被阻断，报告可以追到具体产物。这个阶段的价值是先证明执行底座可靠，便于以后判断模型究竟在哪个决策上出错。

接着M2才接真实模型，并把解析、澄清、规划、修订和报告都计入同一Run。M3完成真实身份、页面查询、CPU停止恢复与隔离，M4用冻结任务和独立评分决定试点。SASA等新能力放在M5，不拖延首版。每阶段按退出证据验收，工期和性能指标应根据团队资源与先导结果确定。



16　常见架构错误、扩展时机与新增能力清单

对应原PPT：21、26、29、47、54、58、107、114、124、129、131、132、135、137、138、139、144页



架构最常见的问题，是先增加很多组件，却没有确定谁保存事实、谁有权执行、结果怎样验收。首版用一个主控和清楚的模块边界已经可以验证关键机制。出现独立专业子任务时再研究多Agent，并通过消融检查是否值得额外成本；排队和资源确有实测瓶颈时再升级调度。

新增能力也要按完整链路做。比如接入SASA，除了调用程序，还要规定输入对象、单位和解释范围，生成可追溯产物，补独立检查与权限、停止和回归测试，再向规划器标为可用。HPC和三维视图同样由需求触发，不能替代账本、科学验收和预算。这些退出条件让通用能力逐项增加，也让支持范围始终可以核对。
