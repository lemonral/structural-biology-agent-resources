01 / WHERE TO START

按已有基础，找到你的起点

你现在的情况先学什么做到什么再继续
刚接触 AgentHello-Agents（Datawhale） · AI Agents for Beginners（Microsoft） · Hugging Face Agents Course任选一门；能画出“目标 → 工具调用 → 观察 → 下一步”的循环。
会 Python，准备开始写代码OpenAI Agents SDK · Python · Pydantic · 输入输出约束能把一个本地函数暴露为工具，并用 schema 检查输入输出。
已有工具，开始遇到多步和长作业LangGraph：显式状态与执行分支 · Langfuse Examples：追踪与评价入口 · Temporal Python Samples：持久工作流能保存状态、定位失败、追踪产物，并说明什么情况下可以重试。
贯穿项目：结构检查小助手

第一版只回答一个可验收问题：“这个结构文件有哪些模型和链，解析时发现了哪些异常？”之后再增加明确的结构比较任务。

先用离线练习看清工具与验收边界

纯Python · 无模型服务 · 合成坐标

工具合同 → 真实执行 → 独立检查

下载包用明确执行计划调用距离和几何中心工具，记录输入摘要、选择、单位和产物。它是接入Agent前的确定性基线，便于理解模型应该负责哪一部分。

下载离线工程练习包

不是PDB/mmCIF解析器，也没有假装完成自然语言推理。真实结构输入要由合适的解析与领域检查接入。

自己运行与核验

python3 runner.py example.json output
python3 -m unittest -v

包内6项检查已运行：参考三角形、刚体变换不变性、选择顺序、无效选择、单位/非有限值，以及执行完成与科学验收的区分。

读完后将一个已验证函数接到所选框架，再比较直接函数、MCP与Agent工具调用是否保持同一合同和错误语义。

02 / SIX STEPS

沿同一个小项目，逐步补齐能力

01
STEP 1 / LEARN → BUILD → CHECK

认识 Agent 的最小循环

区分模型回答、工具执行和外部观察；先掌握单 Agent 与固定工作流。

目标→动作→观察与停止

建立概念边界

模型提出动作，执行器产生真实观察，环境保存外部状态。先用一个固定流程作为基线，再指出哪些节点确实需要读观察后决策。

常见错误：能够解释没有模型的确定性练习包为什么仍有价值；不能把预写路由误认为自然语言Agent。

交付一个产物

一张能标出模型、工具和环境边界的流程图。

这样检查是否学会

能解释工具为什么要返回真实结果，以及模型何时继续、何时停止。

学习入口：Hello-Agents（Datawhale） · AI Agents for Beginners（Microsoft） · Hugging Face Agents Course

02
STEP 2 / LEARN → BUILD → CHECK

写出第一个工具型 Agent

先写可单独调用的结构检查函数，再让 Agent 通过函数工具调用它。

自然语言请求→结构检查函数→结构化结果

追踪一次真实调用

在SDK中找到工具注册、参数解析、实际函数执行与返回模型的路径。不要只打印最终回答；保留调用参数、原始返回和退出状态。

常见错误：分别诱发参数错误和工具失败，检查Agent是否承认失败，是否只在允许范围内修正。

交付一个产物

一个仅包含一个工具的最小示例；先选LangChain或轻量SDK，需要显式状态时再深入LangGraph。

这样检查是否学会

一次正常请求能返回链列表；一次解析失败能返回明确错误；可查看真实调用参数。

学习入口：LangChain 开发专题 · OpenAI Agents SDK · Python · LangGraph：显式状态与执行分支

03
STEP 3 / LEARN → BUILD → CHECK

给工具加输入输出契约

把文件、模型和链选择写成字段；区分数据格式合法和科学对象选择正确。

输入 schema→前置条件检查→输出 schema

类型与科学语义分层

JSON/schema回答数据形状是否符合合同；文件、模型、链或原子选择需要检查真实对象；物理单位和接受标准需要独立定义。

常见错误：不要通过默认链或默认单位悄悄填平缺失输入。错误必须可定位到合同层或领域检查层。

交付一个产物

任务输入、工具输出和错误结果三类 schema。MCP 在需要共享工具时再加。

这样检查是否学会

非法字段能被发现；不存在的链不会被悄悄替换；产物记录保留对象与选择信息。

学习入口：Pydantic · 输入输出约束 · MCP Python SDK：统一工具接口

04
STEP 4 / LEARN → BUILD → CHECK

让多步任务可追踪、可恢复

先保存运行状态与产物；需要长作业时再学习工作流、worker 和恢复模式。

任务与步骤状态→执行及日志→恢复与产物登记

把状态机和对话分开

至少关联Task、Step、Attempt、外部Job与Artifact。提交后失联时先查实际作业；重试参数错误、恢复环境与科学修正是不同动作。

常见错误：暂停界面或断开浏览器不能被当作计算取消；恢复成功需要核对真实外部状态与已有产物。

交付一个产物

一次运行的步骤记录、日志、错误分类和产物清单。

这样检查是否学会

中途失败后能定位具体步骤；再次执行前先核对已有结果，避免无依据地重复提交。

学习入口：LangGraph：显式状态与执行分支 · Langfuse Examples：追踪与评价入口 · Temporal Python Samples：持久工作流

05
STEP 5 / LEARN → BUILD → CHECK

建立独立科学验收

先新增一个成对距离计算工具，再准备参考结果与失败输入；分别判断执行、产物和科学检查。

独立参考→实际计算产物→分层验收报告

先固定判据，再评价Agent

用独立参考值和不变性质检查数值，记录选择、单位与容差。评价需要同时覆盖可行输入、无效输入和看似成功却科学不成立的结果。

常见错误：执行率、产物有效率、科学通过率和成本分别报告，模型评审与数值真值分别记录。

交付一个产物

一个小型测试集，覆盖正常输入、无效文件、错误对象选择和距离计算。

这样检查是否学会

整体刚体变换前后，内部距离应保持不变；记录原子选择、单位和数值容差，再扩展结构比较。

学习入口：Pydantic · 输入输出约束 · Langfuse Examples：追踪与评价入口

06
STEP 6 / LEARN → BUILD → CHECK

带着组件问题读科研代码

对照自己的工具注册、执行环境和验证需求阅读领域系统，选择可复用的一小部分。

工具接口→执行环境→方法接入与复现

从论文方法到可维护工具

方法接入要锁定源材料、运行环境、教程与新输入测试；框架教程复跑、作者案例复现与开放科研泛化是不同阶段。

常见错误：冻结工具版本后再测新对象与新组合；记录不支持的输入和失败，避免把一次演示写成通用能力。

交付一个产物

一份方法接入说明：依赖、输入输出、示例、验证、版本和来源。

这样检查是否学会

换一份独立输入再验证；能说明教程复跑成功与新科研任务成立之间的差距。

学习入口：ToolUniverse · Biomni · Paper2Agent
